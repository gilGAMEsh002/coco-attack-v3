## 1. 目标与范围

建立可独立安装和调用的 `coco_attack` 应用包，并回答四个问题：本期使用哪些资产、资产分别属于哪个组合、文件和记录是否齐全、哪些差异需要用户裁定。

本任务交付工程入口与核查报告，不执行生成代码、不调用模型、不读取 API 密钥、不建设 Docker 或评估缓存。静态 oracle 保持原文件不变，本任务只登记源码位置和指纹；接入与判定校准由后续任务完成。

核查负责发现并完整报告问题；正式数据加载器的强校验由任务 02 实现。不能在核查过程中自动修复原始数据、补猜测试字段或重新选择示例。

## 3. 工程组织与责任边界

所有实现新增在仓库内独立子项目 `coco_attack/`，不改 DSPy 根包名、根包发现规则或优化器依赖。

```text
coco_attack/
├── pyproject.toml
├── requirements.lock
├── README.md
├── .gitignore
├── configs/
│   └── combinations.json
└── src/coco_attack/
    ├── __init__.py
    ├── __main__.py
    ├── cli.py
    └── assets/
        ├── paths.py
        ├── audit.py
        └── artifacts.py
```

- 使用 setuptools 构建，独立 `src` 布局，Python 限定 3.14 系列。运行依赖声明 DSPy；本任务代码使用标准库，CLI 不在导入时初始化 DSPy、缓存或密钥。
- 使用子项目独立 `.venv`，通过 editable 安装本地 DSPy 根目录和本应用包；不改现有根环境及根 `uv.lock`。第三方依赖确定后记录精确版本到 `requirements.lock`，editable 两个源码包的版本/路径另由环境报告追踪，不能用远程同名 DSPy 代替本地源码。
- README 固定环境重建顺序：创建 Python 3.14 环境、安装锁定依赖、editable 安装两个本地包、运行 CLI。无法完成依赖解析或安装时如实记录，不生成伪造锁文件。
- `.gitignore` 仅处理子项目环境、构建、缓存与运行产物；文档、配置和源码可纳入版本管理。真实资产和凭证不复制进包。
- `combinations.json` 是本期组合到文件、示例来源和 oracle 身份的唯一应用路由表。记录原注册表统计 ID、规范组合 ID、旧别名、任务相对路径、oracle ID/源码路径、示例来源、可用 clean 素材及层覆盖；clean/target 定义从原注册表读取，不再手抄一套规则。
- 本任务负责 CLI 总入口、路径与通用产物写入；任务 02 在其上增加数据子命令和强校验，不另建配置或扫描器。

## 4. CLI 与报告契约

拟定命令：

```text
coco-attack audit-assets --repo-dir <仓库> --assets-dir <资产根目录> --output-dir <本次核查输出目录>
```

三个目录参数均必填。输入目录必须存在，输出目录可以是显式指定的新目录；拒绝把输出放进只读资产树。无参数时显示用法并非零退出；`--help` 不扫描资产、不加载 DSPy。

组合路由表随包提供默认的 9 组合清单，不内置用户主目录或历史绝对路径。路径解析集中在 `paths.py`；相对资产路径必须解析到指定资产根目录内，不静默追踪到其他资产来源。

核查产物：

| 文件 | 最小内容与用途 |
|---|---|
| `asset_manifest.json` | 核查 schema 版本、路由配置 hash；每个资产的相对路径、类别、组合、字节 SHA-256；数据数量/schema/ID 集合摘要、提示集合与历史字段可用性 |
| `environment.json` | Python、平台、实际解释器、DSPy 提交和已安装分发版本、锁文件 hash、相关源码修改指纹；后续工具的可用性与依赖需求 |
| `issues.json` | 问题类别、影响范围、相关资产与行号/ID、证据、是否需要用户裁定；不自动写入裁定结论 |
| `REPORT.md` | 人工可读总览：可用资产、缺失项、schema 与计数差异、后续受影响工作、待裁定问题 |

以同一组核查事实生成机器记录与 Markdown，不维护两个会分叉的计算实现。JSON 的稳定部分采用 UTF-8、固定键排序和 LF；时间、耗时、绝对运行目录等观测信息不进入语义指纹。文件 hash 对原始字节计算，不能先改换行或清洗再称原文件 hash。

只扫描明确列出的资产类别。历史 run 可先建文件存在性与字段能力目录，真正参与后续对拍的原始生成/评估文件再固定完整 hash；不递归读取第三方二进制、全部模型输出或 `.env`。环境核查只收集允许的版本信息，不导出全部环境变量、配置或 Git diff 原文。

输入问题尽可能汇总后一次报告。用法/目录参数错误退出 2；完成核查但有必需资产错误或待裁定差异退出 1；无此类问题退出 0。软依赖缺失标为后续阶段限制，不单独使本任务失败。核查完成不等于语义校准通过。

## 5. 实施步骤

1. 建立独立包、环境与 CLI，保证仅运行帮助命令不会初始化模型服务。
2. 填写 9 组合路由配置，以原注册表核对规范 ID 与定义唯一性；登记旧别名，但不按 CWE 名称猜测编号。
3. 实现原始 JSON/JSONL 核查：字段集合、类型概况、非空 test、组合内重复 ID、选择记录与提示集合一致性。保留跨组合共享任务，不全局去重。
4. 登记 oracle、参考报告、clean 素材与历史 run 的存在性、版本和可比较能力；不调用判定器、不运行功能测试。
5. 收集环境与依赖信息。Python/系统库需求通过数据元信息与静态检查整理，准备给 Docker 阶段；不执行资产中的 import 或安装全部第三方工具。
6. 原子写出核查产物并形成差异总览。任何修正数据、路径归属、判定或对拍口径的方案先汇报，由用户决定；不受影响的工程工作可继续。

## 6. 汇入阶段统一验收的检查点

不为本任务单独建设测试套件。阶段验收时复用核查命令与最少的参数化负例：

| 检查点 | 通过条件 |
|---|---|
| 工程与显式路径 | CLI 可独立调用；缺参明确报错；输入资产未变；未读取密钥或运行代码 |
| 资产覆盖 | 9 组合、两份选择记录、旧 4 组合 clean 素材和参考文件均有来源记录；多项输入错误能汇总 |
| 诚实报告与稳定性 | 不自动删题或填默认归属；稳定资产在重复核查中指纹一致；已知差异列出证据并标未裁定 |

这些检查点进入阶段概述所定义的集中验收部分，执行结果进入阶段的统一验收文档，不另设本任务验收记录。本 plan 只规定检查点，历史实际执行见证据索引；后续仅在变更影响时补充或重跑对应检查。

## 7. 完成条件与交接

代码、配置和核查报告可复现，问题列表完整，才可标为实现完成；有待裁定差异时不得标为阶段验收通过。

向任务 02 交付唯一路由表、路径/产物 helpers、CLI 扩展入口、资产原始指纹与字段概况、示例/任务 ID 集合以及差异清单。对“事实采集”和“正式契约校验”共用基础读取逻辑，不复制两套数据规则。
