## 1. 目标与边界

将已核查资产转换为可供提示、评估和实验协议共享的数据接口，固化任务身份、来源、示例排除与组合级划分，产出可复现的任务快照和划分清单。

本任务加载全部 9 个组合；旧 4 组合为后续 clean 实验准备数据，新 5 组合仅提供数据和静态校准/评测集合，不创建其 clean 模板或新增动态/真实性覆盖。不清洗模型输出、不接入 oracle 执行、不调用模型、不运行任务测试。

测试用例只作为数据完整加载和保存；参考解只保留代码前缀与函数体，重组、判定和执行由后续任务负责。

## 2. 输入与前置条件

- 使用任务 01 的唯一 `combinations.json`、路径解析、原始读取和稳定 JSON 写入能力；不新增第二份组合路由表。
- 标准任务从 `data/BigCodeBench/CWE-*.jsonl` 加载。旧任务文件只能通过显式的历史读取入口使用，不能自动成为正式数据的兜底来源。
- 旧 4 组合：读取已物化 clean 素材的 fewshot/meta/test_prompts，并用 `data/bigcodebench_old/tasks/fewshot_selection_seed42.json` 核对种子和示例顺序。
- 新 5 组合：读取 `data/BigCodeBench/fewshot_selection_seed42.json` 中已有选择，不重新运行随机抽样。
- 影响当前输入身份、示例集合或数据来源的差异须先由用户裁定；历史功能参考计数等独立差异可保留待决，不据此修改标准数据或阻断无关的数据接口开发。

## 3. 模块与公共接口

在任务 01 工程基础上新增 `src/coco_attack/data/` 和 `src/coco_attack/protocol/`，扩展原 CLI。领域模块只依赖标准库，以 dataclass、Enum 和普通函数表达契约，不导入 DSPy。

| 接口/记录 | 本任务负责的最小能力 |
|---|---|
| `CombinationSpec` | 规范组合 ID、显式 oracle ID、原注册表定义引用、数据/示例来源和覆盖声明；来自唯一应用路由表 |
| `TaskRecord` | 任务身份、完整原始 17 字段、代码前缀/入口/测试等命名访问、来源路径/行号/schema/内容 hash |
| `DatasetSelection` | 某组合的有序示例 ID、固定评测 ID、选择来源/seed、对应任务快照 hash |
| `SplitManifest` | 划分版本、组合、集合口径、seed、规则 hash、输入集合 hash，以及明确配置的 search/holdout 列表 |
| `load_tasks(spec, assets_root)` | 严格加载单组合任务，保留原始顺序与来源，不静默覆盖重复 ID |
| `prepare_selection(spec, tasks, assets_root)` | 校验已有示例与评测集合，返回统一选择记录 |
| `build_split(selection, split_config)` | 纯函数生成配置划分或 whole-set 集合清单，不访问模型或文件系统 |

本任务只建立下游 `ExperimentSpec` 必需的数据与归属输入，不提前设计完整生成、评估或方法状态 schema。任务 03 将任务与提示素材组合成实验三件套；任务 04 使用同一 CombinationSpec 执行严格 oracle 路由。

## 4. 数据契约与校验规则

### 4.1 标准 schema

标准 schema 版本命名为 `bigcodebench-screened-v1`，要求当前 17 个字段：

```text
task_id, complete_prompt, instruct_prompt, canonical_solution, code_prompt,
test, entry_point, doc_struct, libs, source_id, source_cwe_id,
statistical_cwe_id, decision, experiment_type, reference_side,
has_clean_pattern, has_target_pattern
```

- 必需字段集合与声明 schema 匹配；缺失或新增未声明字段不能静默接受，须更新 schema 或报告问题。不能只检查字段总数。
- `has_clean_pattern`、`has_target_pattern` 必须为布尔值；`source_cwe_id` 允许字符串或 null；其余当前字段按字符串保存。`task_id`、提示/代码前缀、入口及功能测试必须非空；不对所有来源元信息一律要求非空。
- `libs`、`doc_struct` 保留源字符串，不误当列表或对象，不用 `eval` 解析。保留代码、测试和提示的原始文本，不在加载时 strip、重缩进或改换行。
- `statistical_cwe_id` 必须与显式组合定义一致；`reference_side` 必须为 clean 或 target。experiment_type 取值按注册表类型体系校验，不能凭名称重分类；decision 原值保留，不能因 qualified 后缀不同就改写标签。
- 用于 pass@k、动态和真实性执行的任务须有非空 test 来源；当前正式数据统一走含 test 的标准文件，因此加载后执行前仍须保留自检。
- JSONL 每个非空物理行只含一个 JSON 对象，语法或字段错误报告文件、物理行号、任务 ID（若可读）、字段和原因；不跳过坏行。全文件汇总可识别错误，存在错误时不返回有效 TaskRecord 集合。

### 4.2 身份与来源

- 任务身份使用 `(combination_id, task_id)`；同一 task_id 出现在不同组合是合法成员关系，组合内重复 ID 即报错，不按 dict 覆盖或去重。
- 规范组合 ID 使用 `cwe078-0` 等 9 个完整 ID。旧别名只在显式导入映射中使用：cwe078→cwe078-0、cwe094→cwe094-0、cwe295→cwe295-0、cwe502→cwe502-0；不得普遍为缺后缀名称自动补 `-0`。
- 数据准备配置必须显式携带组合和 oracle ID，并与应用路由表核对；后续实验仍须再次显式声明，不能以本任务有映射为由允许运行期缺归属。
- Source provenance 保存资产相对路径、原始字节 hash、行号和 schema；源文件整体 hash 与单条记录稳定 hash 分开保存。
- 旧 6–7 字段 schema 的读取结果标为历史记录，保留实际缺失字段。若后续对拍需要标准 test，只能按已声明组合和准确 task_id 关联标准记录并记录来源；不凭函数名、近似文本或路径猜测。

## 5. 示例与评测集合

### 旧 4 个组合

1. 按 `fewshot.json` 的原顺序读取四个不同示例 ID，核对 meta 与旧 seed=42 记录的 ID 和顺序；差异报错，不自动选其中一份为准。
2. 从 `_clean_0shot/test_prompts/` 与 `_clean_fewshot/test_prompts/` 读取题目 ID，要求集合一致，且所有 ID 存在于标准数据。
3. 文件名使用现有 `BigCodeBench_SL_<编号>.md` 与 `BigCodeBench/<编号>` 的明确编码对应；校验可逆及无重复映射，不进行任意 `_SL_` 全局替换猜测其他数据源。
4. 评测集合必须与示例集合互斥，并与标准任务全集排除四个示例后的集合核对。差异报告缺失/额外 ID，不静默取交集。
5. 0-shot 不实际使用示例，但继承共同的四题排除集合。尤其 cwe078 的 0-shot meta 当前 `fewshot_ids=[]`，不能因此把全部 31 题用于 0-shot。

### 新 5 个组合

按新 seed=42 记录中的有序 task_ids 选择四个示例，验证它们存在且不重复；其余任务构成评测集合。selection 中的样本副本仅作来源核对，标准任务字段仍以路由到的任务文件为准。

这些示例 ID 不代表示例内容已经是 clean，也不代表存在可运行的 clean 模板；本任务只交付数据选择记录。参考解校准使用完整原始任务集合，包括示例题，不以排除示例后的评测集合代替参考校准集。

## 6. 确定性划分与 whole-set

新增 `configs/splits.json`，这是划分配置，不重复组合到数据的路由。首版只配置 cwe078-0：seed=42、search_count=18、holdout_count=9；其他组合显式声明 whole-set。

cwe078 算法固定为：

```text
输入 = 已核对的 27 个评测 task_id（不含四个示例）
排序键 = (sha256(UTF-8("42:" + task_id)).hexdigest(), task_id)
search = 排序后的前 18 个 ID
holdout = 后 9 个 ID
```

- 输入必须唯一且数量等于配置之和；任一分区为空、重叠、覆盖不完整或规则缺失时报错，不自动舍入、调整比例或补题。
- 保留摘要排序后的分区顺序，不能输出前再重新按 ID 排序。未来组合可显式配置整数题数，实施者不得自行给小组合制定划分。
- 执行阶段枚举严格为 `search`、`holdout`；whole-set 只是集合模式。未划分组合的 manifest 保存全体评测 ID 与 `mode="whole-set"`，不伪造 holdout 列表、锁定成功或 holdout 验证结果。
- 数据准备阶段可以由可信准备工具产生划分清单，不运行 holdout 评估。清单产生不代表方法可访问 holdout；物理访问隔离在阶段 02 实现。
- `SplitManifest` 保存配置文件原始字节 hash、划分算法版本、组合与有序输入 ID 的稳定 hash、任务快照 hash。稳定 manifest 不放生成时间和机器绝对路径；相同输入重复准备必须字节一致。

## 7. CLI、产物与实施顺序

在任务 01 的 CLI 增加：

```text
coco-attack prepare-data --repo-dir <仓库> --assets-dir <资产根目录> --output-dir <新输出目录> --split-config <划分配置> --combination <完整组合ID>
```

`--combination` 可重复或取显式 `all`；不根据当前目录猜测默认组合。输入/输出目录沿用任务 01 规则，生产数据准备不默认调用真实服务或创建 DSPy 缓存。

| 产物 | 内容 |
|---|---|
| `<组合>/tasks.jsonl` | 完整标准任务快照与 provenance，用于参考校准和下游任务查找 |
| `<组合>/selection.json` | 有序示例 ID、固定评测 ID、seed 与来源指纹 |
| `<组合>/split.json` | 显式分区或 whole-set 清单、算法/配置/输入指纹 |
| `manifest.json` | 数据契约版本、组合与 oracle 映射、所有输出文件 hash 和本次准备完成状态 |
| `REPORT.md` | 数量核对、示例/集合/划分摘要、错误与待裁定事项 |

报告的时间等观测信息不纳入稳定快照。写文件复用任务 01 原子写入方法，完整校验成功后才发布完成 manifest；失败保留诊断但不留下可被误认为成功的数据集。输出目录非空时拒绝覆盖，使用新的显式目录。

实施顺序：先补 CombinationSpec 与标准加载器，再实现历史只读适配与来源校验，接着验证示例/评测集合，最后实现纯划分函数、快照写入和 CLI 接线。遇到错误使用同一问题记录格式，不能模块各自吞错或补默认值。

## 8. 汇入阶段统一验收的检查点

不建立本子任务的独立测试套件或验收记录。以下检查与任务 01、后续提示/判定检查在阶段验收时合并执行。

| 集中检查 | 通过条件 |
|---|---|
| 一次全组合准备 | 9 组合可加载；旧 4 组合评测题数为 27/4/33/45；新组合正确排除已有示例；原资产不变 |
| 少量数据负例 | 参数化覆盖缺 test、重复 ID、错组合/oracle、未知 schema 和示例交集；无静默过滤或补默认值 |
| 集合与划分重放 | 相同输入生成的快照、selection、split 字节一致；cwe078 分区为 18/9 且无交集；其他组合无虚构 holdout |

执行者将命令和输出链接汇入阶段验收文档；对历史记录的实际 verdict 对拍由任务 05 统一完成，本任务不重复建设对拍检查。

## 9. 完成条件与交接

标准数据、示例排除与划分可通过统一接口获得，输出来源/版本可追溯，未决问题明确列出且未被程序自动修正，才可标为本任务实现完成。阶段是否验收通过由集中检查及人工审查确定。

向任务 03 交付 TaskRecord、DatasetSelection、SplitManifest 和素材来源；向任务 04 交付显式组合/oracle 身份及标准测试字段；向任务 05 交付完整参考任务集、来源快照与尚未裁定的历史差异。后续实现必须复用这些契约，不再次自行划分或抽示例。
