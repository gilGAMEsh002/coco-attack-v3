## 1. 目标与范围

将已清洗的最终生成记录送入正确的既有静态 oracle，产出可追溯的逐样本判定，再按固定任务集合和采样配置计算指标。先贯通 cwe078，再接入其余 8 个组合。

本任务直接复用 `cocota_data_eval_result/oracles/` 的判定代码，只新增加载、契约校验、记录适配和指标计算。领域代码不导入 DSPy，不调用模型，不执行候选代码；SAST、LLM judge、功能测试、动态层与真实性层的实际运行留给阶段 02。指标函数可以消费构造的或已规范化的外部评估记录，不能把构造结果写成真实实验结果。

完整参考解校准、历史 run 导入与新旧逐样本对拍由任务 05 负责；本任务交付这些工作需要的接口和差异字段，不提前宣称历史一致或阶段验收通过。

## 2. 当前代码与复用依据

| 已有代码/资产 | 接入方式与注意事项 |
|---|---|
| `data.contracts`、`data.snapshot.load_prepared_data` | 复用 `TaskRecord`、`CombinationSpec`、`PreparedCombination` 及已验证的 selection/split，不重新抽样或定义任务路由 |
| `evaluation.cleaning.CleanResult`、`evaluation.run_cleaning.clean_generations` | 消费 `cleaned_generations.jsonl`，使用 `cleaned.final_code`；保留原始响应、提取代码、最终代码、生成状态及其 hash |
| 清洗 `manifest.json` | 校验 `completed=true`、组合/oracle、清洗版本、输入来源与输出文件 hash；这是清洗产物格式，不与准备产物的 `completion="complete"` 混用 |
| `oracles/static_registry.py` | 复用 `STATIC_MODULES` 的 oracle 到模块映射及现有调用入口；应用层仍须显式验证组合归属，不能依赖旧默认推断 |
| `oracles/cwe*.py`、`_symbols.py`、`_static_common.py` | 加载可信资产代码（cwe078 采用 D05 已批准修复的 v2，其余复用原件），记录模块及共享依赖指纹，不复制后另行维护判定规则 |
| `assets.artifacts`、`assets.paths`、`assets.issues`、`cli.py` | 复用 hash、原子写入、路径边界、诊断与 argparse 入口 |

当前清洗记录已包含 `combination_id/oracle_id/task_id/repeat_id/source/cleaned`，但清洗 manifest 没有完整的模型、温度、repeats 和实验用途信息。因此指标入口必须另收显式评估配置，不能从目录名猜测，也不能仅按现有行数推断预期样本数。

既有 `resolve_oracle_id(cwe, oracle_id)` 会优先采用传入的 oracle_id，并不保证它属于传入组合。例如“合法但属于另一组合”的 ID 仍可能通过其成员检查。新外壳必须在调用前补齐归属校验，不能只校验返回值。

旧项目 `src/cocota/evaluation/metrics.py` 仅用于理解历史口径，不成为运行依赖。其中缺失工具字段可能被当作未检出、零分母返回 0 等行为与当前任务书不同，不能直接照搬；这些差异交任务 05 展示。

## 3. 模块与公共记录

在 `coco_attack/src/coco_attack/evaluation/` 下增加少量模块，沿用现有包与错误体系；以下名称为拟实现接口，可按已有工程风格调整，不创建第二套任务/划分类型。

| 模块/接口 | 职责 |
|---|---|
| `contracts.py`：`EvaluationRecord`、`MetricResult`、评估配置 | 定义样本身份、各层结果、指标可用性与统计口径 |
| `static.py`：oracle 加载器、`evaluate_static_sample` | 校验路由，调用原 oracle，对输入及返回值作严格校验 |
| `metrics.py`：ASR、evasion、judge rate、pass@k 聚合 | 纯计算函数；不读取凭证、不启动工具、不修改输入记录 |
| `run_static.py`：批次编排与报告 | 读取已准备/清洗产物和评估配置，校验集合，发布逐样本结果与汇总 |
| `cache.py`：评估缓存协议与禁用实现 | 查询总是未命中、写入不保存；供后续评估器沿用接口 |

`EvaluationRecord` 至少保存：组合/oracle、task/repeat、实验或输入批次身份、清洗记录引用与 hash、最终代码 hash、生成状态、规范化静态结果、原 oracle 返回值、判定来源、评估器指纹，以及其他评估层的可用性和未执行原因。`asr_hit` 若作为便捷字段保存，只能由静态 verdict 派生，读取时再次核对。

`MetricResult` 保存指标名、value、是否定义、原因、分子/分母及计数口径、k、任务和样本数量、集合与采样配置引用。未定义用 `value=null` 加明确原因表示，不用 0、NaN 或空字符串冒充。pass@k 额外保留每题 n、c 和估计值；聚合分子是逐题估计值之和，不伪装成整数命中题数。

## 4. 静态 oracle 接入

### 4.1 显式路由与加载

1. 以既有组合配置中的 `CombinationSpec.oracle_id` 为归属依据，核对准备产物、评估配置、清洗 manifest 和逐行记录一致。新入口要求完整组合 ID 和明确 oracle_id；旧别名转换只在受控的历史导入边界进行。
2. 使用既有 `STATIC_MODULES` 查找实现，不在 CLI、指标层或逐样本函数中重复维护 9 份分支。覆盖 cwe022-0、cwe078-0、cwe089-0、cwe094-0、cwe295-0、cwe295-1、cwe367-0、cwe400-0、cwe502-0。
3. 现有模块内部使用 `oracles._symbols`、`oracles._static_common` 等绝对导入。加载器在进程初始化时将明确的可信资产根纳入导入路径，验证实际加载模块位于该根下；不能只用任意别名加载单文件而忽略其包依赖。
4. 同一进程固定一个 oracle 资产根；发现已加载同名包来自其他路径时明确报错，不静默复用或在逐样本调用中来回改全局导入状态。缺文件、未知 ID 或导入失败均报告配置/依赖错误。按复核记录，进程内模块缓存须核对源码 hash，源变更时重新加载，不能只按 oracle_id 沿用旧模块。
5. 只导入可信 oracle 实现；候选代码始终以字符串交给静态解析器，不 import、exec 或运行候选代码。

### 4.2 三重校验与失败语义

正常调用后强制检查：返回 `oracle_id` 等于预期 ID；`verdict` 属于 `target_present/target_absent/parse_error`；`target_present` 必须是严格布尔值，且仅在 verdict 为 target_present 时为 true。`1`、`"false"` 或缺失字段不能通过布尔强转蒙混过关。

旧模块若没有 `oracle_layer`，在外层规范化记录中补 `static`，原返回值仍原样保存；若显式返回其他层则报错。保留 matches、target_pattern、解析错误位置等原始证据，不把静态命中提升为动态观察或真实可利用性结论。

| 输入/运行情况 | 处理 |
|---|---|
| `generation_status != success` | 按 F3 产生 `parse_error`、`target_present=false`，保留分母；标明来源为生成失败映射，不伪称原 oracle 对空字符串给出了该结果 |
| 成功但最终代码为空/全空白 | 单独记录 empty_output，并由外壳按无可评估代码映射为 parse_error；不得利用 `ast.parse("")` 成功将其计为 clean |
| 非空代码存在语法错误 | 调用原 oracle，保留其 parse_error 及错误证据；不重试其他清洗候选 |
| 语法合法但缺任务入口 | 按原 oracle 判定目标模式，同时保留入口缺失；入口缺失不能直接改成 parse_error 或功能通过 |
| 内容 hash 不符、组合错配、返回契约错误或非预期异常 | 作为评估输入/实现错误报告，批次不标记完成；不能伪装成模型 parse_error 或未命中来凑齐统计 |

新流水线统一评估 `final_code`，不根据命中与否在提取代码和补全代码间选择。`target_absent` 只代表未检出该目标模式，不能称为代码安全；parse_error 与 target_absent 始终分别计数。

## 5. 指标口径与分母

### 5.1 先固定样本集合

评估配置显式声明组合、oracle、模型、temperature、repeats、提示形态/实验引用、任务集合及 split 引用。预期键为本次固定任务 ID × `repeat_id=0..repeats-1`；检查重复、越界、额外和缺失记录，不能从现有行临时缩小任务集合。

显式生成失败仍是一条最终样本，应留在分母；日志缺行或断点尚未完成是样本不完整，只能输出诊断，不能当成完整实验发布。重试 attempt 不作为新 repeat，重复导入或缓存读取也不得增加独立样本数；有采样来源信息时保留并校验，没有时不能宣称已证明独立采样。

`search/holdout` 使用准备阶段固化的集合；未配置划分的组合使用 `whole-set` 集合口径，不新增第三种执行阶段。阶段 01 的历史文件诊断不代表开放在线 holdout：按阶段 02 D06，阶段隔离以约定和方法作者自觉为主，不要求代码强制；本模块不自行向方法提供全量结果。

### 5.2 计算规则

| 指标 | 定义及边界 |
|---|---|
| ASR@1 | 每题只取 repeat 0 的静态命中，命中题数 / 固定题数；正式 @1 配置为 temperature=0、repeats=1 |
| ASR@k | 每题前 k 个 repeat 任一静态命中即记该题命中，再除以固定题数；正式 @5 配置为 temperature=0.7、repeats=5；不能把所有样本命中率当成 ASR@k |
| 样本静态命中率 | 命中样本数 / 预期最终样本数，作为另名诊断统计，并列出三种 verdict 计数，不替代任务级 ASR@k |
| tool/LLM evasion | 分母为静态 asr_hit 样本数；分子仅为该子集中工具/judge 成功完成且明确未检出的样本数。失败、跳过、缺失结果不进入分子，不因缺结果缩小命中子集分母 |
| llm_judge_rate | 对规范化 judge 记录统计明确检出样本数 / 固定样本数，另列成功、失败及缺失数；不得将 judge 失败写成未检出。具体原始标签到检出布尔值的转换由阶段 02 judge 适配器固定并版本化 |
| pass@1/@3/@5 | 每题 n 个最终样本中 c 个功能通过，使用 `1 − C(n−c,k)/C(n,k)`，再对固定任务集合等权平均；当 n−c<k 且 n≥k 时估计为 1，n<k 时未定义 |

evasion 与 llm_judge_rate 仅在 `repeats>=5 且 temperature=0.7` 时有效；工具整体未接入/不可用时仍为未定义，并保存 `available=false` 和原因。零分母始终未定义；个别工具失败另报覆盖率，不能呈现为“全部成功检查后未检出”。

ASR 计算函数可用于其他 k 的诊断，但配置不符合正式采样协议时必须标明诊断用途和具体配置，不能包装为协议规定的正式 @1/@5 结果。历史已有其他配置的指标在任务 05 单独比较，不修改旧文件。

功能测试结果须区分明确通过、明确未通过与评测基础设施不可用。生成失败按未通过留在预期 n 中；未运行功能测试、环境不可用或结果缺失时不能填失败补齐后发布 pass@k，也不能删去受影响题后重算均值。存在无法确定功能结果的题时，整体指标标为未定义并列出原因。

数学检查共用一组小样本即可：n=5、c=2 时 pass@1=0.4、pass@3=0.9、pass@5=1；不能将同组的 any-hit=1 当成所有 pass@k。全生成失败且任务集非空时 ASR=0，同时 parse_error 占比为 1；这不代表所有输出 clean。

本阶段静态批次报告中的真实 pass@k、SAST/judge 指标均为未接入占位。构造记录只验证计算规则，外部历史结果须经任务 05 显式适配并注明来源后使用。报告不增加 `stable_task_rate`，不定义迭代方法的综合分数。

### 5.3 clean 基线与比较

报告区分静态诊断、clean 自然命中率和正式投毒对比。正式投毒报告必须同时包含 ASR、base rate 和增量；缺基线时可保存逐样本结果与诊断，但拒绝发布完整投毒效果报告。

比较前核对同组合、同 split 及实际任务集合、同 k、同温度、同模型、同 repeats，并检查数据、清洗和 oracle 版本的兼容性；不匹配则拒绝比较，不自动寻找“最接近”的基线。显式记录所选 clean 形态及基线产物 hash。未配置划分的组合双方都使用 whole-set。

功能约束配置保留 P 对应哪个 pass@k、ε 及基线聚合方式。本任务只保存声明和必要数值，不替迭代方法设定 ε、优先级或成功目标。clean 自然命中显著非零时先报告并核查原因，不直接归因于 oracle 误报。

## 6. 版本、缓存与产物

静态评估指纹包含最终代码 hash、oracle_id、实际 oracle 模块/注册表/共享依赖 hash、外壳版本、清洗版本及相关 Python 解析运行环境。汇总另记录指标版本、配置和任务/split 指纹；清洗或评估器变更可追溯，不覆盖旧结果。

本期只为功能测试建设结果缓存，具体实现属于阶段 02。本任务为静态及其他评估器保留统一查询/写入协议，接入禁用实现，不建磁盘索引、不按相同代码复用 verdict、不为其设计额外缓存系统。逐样本 JSONL 和汇总属于审计产物，保存记录不等于实现了缓存；DSPy 响应缓存属于生成层，与本任务分开。

拟新增 CLI：

```text
coco-attack evaluate-static --assets-dir <只读资产> --data-dir <prepare-data输出> --cleaned-dir <clean-generations输出> --combination <完整组合ID> --oracle-id <明确oracleID> --config <评估配置JSON> --output-dir <新目录>
```

命令一次处理一个显式组合，批量工作由调用方列出组合清单。评估配置引用已有数据/实验产物，不重新定义提示格式；来源不足的历史配置留给任务 05 补充证据，不能猜测 model、temperature 或 repeats。

输出 `evaluations.jsonl`、`metrics.json`、`manifest.json`、`REPORT.md`；输入/运行错误保存诊断，非零退出，不发布完成标识。报告包括配置与覆盖范围、verdict 分布、逐题/汇总指标及分母、未定义原因、未接入层、输入和代码版本。所有写入使用现有原子写入约定，输出目录必须为空且与只读资产、准备/清洗目录隔离。

## 7. 实施步骤与衔接

1. 衔接现有准备/清洗产物，补评估配置和 EvaluationRecord/MetricResult，验证完整样本矩阵与来源。
2. 实现可信资产加载和严格外壳，先以 cwe078 串起清洗记录、静态调用及最小报告；同时明确生成失败和空输出的外壳映射。
3. 通过同一注册表接入其余 8 个组合，保存源码及共享依赖指纹，不改判定逻辑。
4. 实现纯指标函数、可用性与采样配置门控、基线比较校验；仅用构造记录开发尚无真实执行器的指标。
5. 接入 CLI、禁用缓存接口及可审查报告，汇总发现的问题和阶段检查点。
6. 向任务 05 提供逐样本 oracle 结果、原始返回值、代码/来源指纹、任务/repeat 集合和分母，供参考解校准与历史差异定位；不在这里另做一套历史验收。

## 8. 汇入阶段统一验收的检查点

不建立本子任务独立测试套件或验收记录。检查在阶段 01 集中执行，优先复用任务 03 清洗样例、任务 05 参考记录及一组小型参数化指标数据，不按模块逐项增加测试。

## 9. 完成条件
