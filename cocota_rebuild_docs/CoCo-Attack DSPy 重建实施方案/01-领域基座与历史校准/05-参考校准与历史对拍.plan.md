## 1. 目标与范围

完成两项工作，并将阶段 01 的检查证据汇总为一次可人工审查的交付：

1. 参考校准：重组全部 9 个组合的参考代码，核对当前静态 oracle、既有参考判定和 clean/target 标签，确认复用实现的行为及已裁定例外。
2. 历史对拍：从 cwe078 的 clean 历史 run 开始，扩展至旧 4 组合代表 run，逐项比较生成样本身份、清洗代码、布尔命中、分子分母与汇总指标，集中报告全部差异。

本任务仅进行本地文件读取、代码文本处理、静态解析和指标重算。不调用真实模型、不运行候选或参考代码、不重跑功能测试/SAST/judge，不建立评估结果缓存。历史功能测试结果可用于说明覆盖缺口，不能冒充本次隔离执行证据。

本任务是阶段 01 的收尾工作，不是每个子任务重新建设一套测试。先复用已有检查及接口，只补参考校准、历史适配和差异汇总所需的能力。

## 3. 输入、复用接口与新增职责

### 3.1 只读资产与比较清单

以下路径相对于显式传入的资产根目录：

| 输入 | 用途 |
|---|---|
| `data/BigCodeBench/CWE-*.jsonl` 与 prepare-data 产物 | 当前完整任务、参考代码、有效元数据、示例/评测集合和固定划分 |
| `data/BigCodeBench/oracle_results/*_reference.json` | 9 组合既有参考判定；按实际路径读取，不沿用旧文档中失效的 `oracles/oracle_results/` 路径 |
| `oracles/` 与组合配置 | 当前判定实现、共享依赖指纹和明确组合归属 |
| `runs_by_model_old/` 下显式选定的 run | 历史生成、评估、配置和汇总记录；只读取对拍需要的文件 |
| `prompts_old/experiments/`、既有提示物化产物 | 核对历史实验形态、任务集合与提示来源；不重建或重新生成历史响应 |
| `data/BigCodeBench/reference_eval/` | 核对历史功能参考覆盖，单列遗漏；不作为静态判定答案 |

运行前保存比较清单：每个组合的参考记录路径、每个历史 run 的确切路径及各输入文件 hash、组合/oracle 映射、实验形态、模型/温度/repeats 的来源、任务集合、比较用途和已裁定事项引用。复用既有资产清单，不再建设通用目录扫描器。

历史 run 的第一批覆盖旧 4 组合各一份具有生成、逐样本评估和汇总证据的 clean run，优先选 temperature=0.7、repeats=5，以覆盖任务级 any-hit；cwe078 另纳入一份 temperature=0、repeats=1 的 run（资产存在时）和 §2 已知差异所在 run。运行清单先固定，不能根据重算结果挑选“无差异”的 run；文件不齐或配置不明要列出缺口，不悄悄替换。新 5 组合本任务只要求参考校准，不制造不存在的历史 run。

已确认的 cwe078 clean 起点是 `runs_by_model_old/deepseek-v3.2/rep1/cwe078_clean_fewshot_DeepSeek-V3_2_t0p7_r5/`，其输入实验 meta 的 baseline 为 `Clean few-shot`；同模型另有对应 clean_0shot。历史 meta 不一定含 `attack_config.enabled`，不能把该字段缺失直接判为 clean；例如 `cwe078_cocota_gpt-5_t0p7_r5` 的 baseline 为 `CoCoTA`，应作为攻击 run 诊断。两类 run 都可对拍，但报告用途必须明确。

### 3.2 接口责任

复用 `data.snapshot.load_prepared_data`、现有清洗函数、静态加载器/返回值校验及 `evaluation.metrics` 的纯计算函数，不复制 oracle 或指标算法。新增代码建议集中在 `evaluation/calibration.py`、`evaluation/history.py` 及一个报告编排模块，CLI 沿用现有 argparse 入口。

现有实现的具体衔接点如下，实施时以这些接口为起点：

| 当前接口/产物 | 本任务衔接 |
|---|---|
| `load_oracle_module(assets_root, oracle_id)`、`evaluate_static_sample(final_code, expected_oracle_id, module)` | 可直接判定完整参考代码，无需伪造生成记录；使用同一进程固定资产根的加载约束 |
| `oracle_fingerprint(root, oracle_id)` | 记录当前 oracle 及共享依赖指纹；旧 run 没有相应指纹时另记 unknown |
| `evaluate_static(assets_root, data_dir, cleaned_dir, config_path, output_dir)` | 用于满足现有配置和完整样本矩阵的重算；不为迁就旧集合放松正式入口校验 |
| `clean_output(raw_text, task, generation_status)` | 对历史原始生成做当前规则清洗；不调用旧项目代码修复或筛选候选 |
| `evaluations.jsonl` | 当前记录保留 final_code 的 hash，而非代码本体；代码比较必须关联清洗 JSONL，不能只依赖评估记录 |

`PreparedCombination.records` 和 `task_by_id()` 当前均包含示例，参考校准可直接使用；历史生成的预期集合须另取 `selection.evaluation_ids` 或指定 split。当前 `EvaluationConfig` 使用 `task_set=evaluation/search/holdout/whole-set`；其中 whole-set 解析为 `split.input_ids`，cwe078 对应排除示例后的 27 题，不能用于代表校准所需的 31 题。

现有配置尚无 `report_kind/split_scope` 的正式字段。历史诊断用途由本任务比较清单和报告明确保存；不能只向旧配置加入会被忽略的字段，就声称已经完成历史用途或正式协议校验。

参考静态 JSON 的逐题记录含 `expected_target/agrees_with_label/target_present/verdict` 等字段；历史功能参考 JSONL 则使用 `memberships[]` 表示同一 task 对多个组合的归属。后者的覆盖统计必须按 membership 展开，不能把 unique task 数直接当某组合参考数，也不能与静态校准记录混用。

新增接口分别负责：读取并校验参考判定；构造完整参考代码；适配历史字段并按样本键关联；调用现有清洗/判定；生成集合、代码、布尔命中和指标差异。需要扩展公共入口时保持任务 04 正式评估的严格校验，不为历史兼容放宽所有调用方。

历史字段适配保存原字段及来源，只在边界完成旧别名映射。对缺失值使用“未记录/不可比较”，不能默认成功、false、0 或当前版本；只有源记录和已有裁定支持的转换才可落成规范化记录。

## 4. 9 组合参考校准

### 4.1 参考集合与代码构造

参考校准使用每个组合的完整标准任务集合，包括 few-shot 示例；生成实验的评测集合排除了示例，两者不能混用。逐组合核对标准任务、参考 JSON 的 task_id 集合、重复项、组合/oracle 归属及总数，先报告集合缺口，再比较交集中的判定。

每条参考代码严格构造为 `code_prompt + canonical_solution`，按源文本直接拼接并保存各部分及结果 hash。不单独把函数体送入 AST，也不套用模型输出清洗来“修好”参考代码；重组后不能解析时如实报告。原任务记录和参考 JSON 只读。

通过与正式静态评估相同的可信加载及三重返回值校验调用原 oracle。参考记录应标明 `source_kind=reference`，不能伪造模型生成状态、采样次数或模型信息来挤入生成记录契约。

### 4.2 两种对照分别报告

| 对照 | 断言与报告 |
|---|---|
| 当前判定 vs 已有参考判定 | 按 task_id 比较既有可用的 verdict/target_present 及当前结果；保存证据变化。当前结果必须真实重算，不能直接复制参考 JSON 当输出 |
| 当前判定 vs reference_side | clean 侧应为 target_absent，已裁定的标签边界单列；target 侧应全部 target_present。parse_error 在任何一侧都不能计为通过 |

报告保留原始标签一致率、各侧样本数与三态分布、已批准边界数量和新增差异数量。已批准例外不会把原始 4/5 标签一致率改写成 100%，也不会从分母移除该题。

已裁定例外由用户批准的参考来源及其记录限定：在比较清单中固定来源 hash 和裁定引用，再读取相关记录。不能把“本次发现的任意不一致”自动加入白名单；参考文件更新或例外结果变化时重新核查适用范围。既有裁定也不能掩盖新增 parse_error 或目标侧漏检。

## 5. 历史重算与逐样本对拍

### 5.1 身份与集合先行

关联键为 `(run身份, combination_id, task_id, repeat_id)`，不得仅用 task_id 跨模型、run 或重复采样合并。分别保留历史生成集合、历史评估集合、历史配置声明的预期集合及当前标准评测集合；列出缺失、额外、重复与越界样本。

历史配置从 run 内配置/元数据及显式映射读取，冲突要报告。旧目录名可作为定位线索，不能成为默认 oracle 或采样参数的权威来源。需要历史任务快照才能解释的差异保留对应来源；不存在快照时明确未知，不能拿当前任务文本冒充历史输入。

历史文件适配以实际目录为准：通常使用 `inputs/run_config.json`、`inputs/task_subset.jsonl`、`outputs/generations.jsonl`、`eval/records.jsonl` 和 `eval/summary.json`，并核对被引用实验的 meta/fewshot。模型或 rep 根目录的总 summary 可能包含多个实验，不能直接当成本 run 的逐样本来源；clean/投毒归类也须由实验元数据确认，不能仅凭 run 名猜测。

显式生成失败留在原样本键及 ASR 分母；缺行不是生成失败，不自动填造记录。重复 attempt 不当 repeat。集合不同仍可比较交集以定位问题，但交集结果仅是诊断，不冒充整批对拍一致。

### 5.2 分层比较

| 层次 | 具体比较内容 |
|---|---|
| 原始输入 | generation/status、任务/提示来源及可用指纹；缺失审计字段标 unknown，不补造历史 token、rollout 或调用成本 |
| 清洗代码 | 按 D06 使用 cleaner-v3，保留旧/新代码字节、hash、入口补全与诊断；按 D07 将 AST 等价差异单列为外观，不等价作为阻塞差异。字段缺失时只标该维度不可比较，不判一致 |
| 静态判定 | 新 verdict 派生布尔命中，与历史 asr_hit 比较；历史 asr_evidence.hit 若存在，核对其与 asr_hit 自洽，保留 reason/matches 作证据 |
| 逐题与汇总 | 同集合、同 repeat 范围下比较每题命中向量、ASR@k 命中题数/题数、样本命中数/样本数，再核对历史 summary 的相应值 |

新流水线始终以当前清洗产生的 `final_code` 判定。为定位差异，可额外将历史已保存的 evaluation_code 送入当前 oracle，形成明确标注的诊断列；不能按哪份代码更符合旧命中来选择正式输入。没有旧代码时不借当前清洗结果声称已恢复旧清洗行为。

按已裁定粒度，历史 false 只表示旧布尔未命中。即便新 oracle 得到 parse_error，也不能把它写入“历史 verdict”列或声称双方三态一致；该列保存 null 并注明未记录。若个别 run 确有结构化 verdict，可以额外比较，但不能将更丰富的格式强加给其余旧 run。

对确定性的布尔、样本键、分子和分母要求精确比较，不设置容差。历史 summary 仅有格式化小数时按已知展示精度核对，并注明精度限制；原始计数有差异不能被浮点容差或汇总舍入掩盖。

### 5.3 历史口径与新协议分开

历史 t0.7/r5 中的 ASR@1 可用于同口径诊断，不能等同于新协议规定的 t0/r1 正式结果。历史整集合与当前 search/holdout 分别展示；不能为复现旧全量结果改写 split，也不能将历史全量诊断宣称为锁定后的 holdout 验证或新 clean 基线。

pass@k、evasion、judge 的旧数值只在有充分逐样本证据和明确口径时做附加重算说明；阶段 01 不承诺复现外部工具执行。缺结果、环境信息或旧算法版本时标不可比较，不按 0 补齐，不增加本期评估缓存。

## 6. 差异总览与用户裁定

每条差异记录稳定身份、所属组合/run/样本、类别、旧新值、输入及代码 hash、证据路径、影响范围和处理状态。至少区分集合/来源、清洗、布尔命中、分母/聚合、历史字段缺失、已批准标签边界及版本信息不足。

报告首页先给总体情况：请求/完成/受阻组合和 run 数、参考校准各侧结果、各类差异数量、影响指标及代表样本。详细逐样本记录作为可追溯附件，不要求用户从海量 JSONL 自行发现主要问题。

处理状态区分 `一致`、`已裁定并落实`、`新增待裁定`、`证据不足`、`执行/输入受阻`。已裁定事项继续展示来源，不再作为新问题；新差异先整体汇报，给出证据支持的可选修改方向及影响，由用户决定。

不擅自修改 oracle、清洗规则、任务集合、历史记录或统计语义来消除差异。等待裁定时可以继续其他组合的只读校准和证据定位；不得越过受影响的验收项。获准修正后记录裁定、改动及版本，仅重跑受影响的检查，不无条件重复整套实验。

## 7. CLI、产物与完成标识

拟新增两个命令，以下为实施接口计划，不表示命令已经存在：

```text
coco-attack calibrate-references --assets-dir <只读资产> --data-dir <prepare-data输出> --config <校准清单JSON> --output-dir <新目录>
coco-attack compare-history --assets-dir <只读资产> --data-dir <prepare-data输出> --config <历史比较清单JSON> --output-dir <新目录>
```

清单显式列出组合/oracle、参考或 run 文件、字段来源及用途，路径相对明确资产根解析；新输出目录必须为空，并与全部输入隔离。运行前验证路径和归属，不从目录名猜测。命令分别支持先做一个组合和后续批量清单，复用同一处理流程。

| 产物 | 内容 |
|---|---|
| `reference_comparisons.jsonl` | 每题参考来源、侧别、代码 hash、旧新判定、标签对照与例外依据 |
| `history_comparisons.jsonl` | 每个样本键的存在性、代码差异、旧布尔命中、新三态结果及指标影响 |
| `summary.json`、`differences.json` | 按组合/run 汇总的计数与指标、分类差异、证据缺口和裁定状态 |
| `manifest.json`、`REPORT.md` | 请求范围、处理覆盖、输入/实现版本指纹、可复现命令和面向人工的总体报告 |

两个命令各自产出对应的逐样本文件及通用汇总；批量历史重算的中间清洗/静态产物按 run 保存在输出子目录，便于回溯。既有结果只作为比较基准，新判定每次实际计算，不将对拍产物用作评估缓存。

区分“报告生成完成”和“验收通过”：有完整差异报告也可能仍待裁定。manifest 分别保存处理完成情况与验收状态；不完整批次不标全部处理完成，待裁定结果不标通过。退出码沿用 2 表示用法/目录错误，1 表示输入/处理失败或新增待裁定差异，0 仅表示请求检查完成且无未解决的阻塞项；退出 0 也不替代阶段人工审查。

## 8. 实施顺序与阶段统一验收

1. 固定比较清单、输入快照及既有裁定引用，核对前置产物，不重新实现任务 01 的资产扫描。
2. 先完成 cwe078 参考代码重组和一份 clean 历史 run 的全过程，确保集合、代码、命中及分母均进入报告。
3. 用同一接口完成全部 9 组合参考校准，扩展旧 4 组合代表 run，并纳入已知布尔差异案例。
4. 汇总全部差异及证据缺口，先向用户报告总体情况；独立检查可继续，涉及语义修改的事项等待用户裁定。
5. 复用 01–04 已有检查，集中补齐本任务新增的数据适配/比较检查；汇入阶段统一验收，避免各子任务再交一套测试。
6. 裁定落实后更新受影响证据与阶段验收记录，整理向阶段 02 的接口、版本、依赖和未覆盖事项交接。

阶段统一标准以[阶段概述 AC-01–AC-05](./阶段概述.md#acceptance-criteria)为唯一维护位置，本任务不再重复一份标准表。本任务交付的 9 组合校准证据映射 AC-02，7-run 历史比较映射 AC-04，差异与复现材料映射 AC-05；AC-01/03 复用前置任务的同版本证据。过程命令、结果与裁定写入验收记录；最终标准对照与人工结论写入阶段验收，不新增 05 独立验收文件。

保留既有测试，不为了减少数量删除已完成检查；新增测试只覆盖实际新增的比较规则，并尽量共用样例。当前验收记录中的累计测试数字是历史检查证据，最终记录实际执行的命令与结果，不沿用未经本次确认的数字。

## 9. 完成条件与下一阶段交接

校准及对拍接口可复现，全部请求范围与差异有记录，9 组合参考校准和旧 4 组合历史比较完成，相关新增差异已整体报告，才可标记本任务实现与报告交付完成；尚待用户裁定时必须同时保留该状态。

向阶段 02 交付固定版本的任务/提示/清洗/评估接口、参考校准与历史对拍证据、已裁定边界、环境依赖及执行层未覆盖清单。功能测试、Docker 隔离、真实模型生成与缓存验收仍由阶段 02 完成。
