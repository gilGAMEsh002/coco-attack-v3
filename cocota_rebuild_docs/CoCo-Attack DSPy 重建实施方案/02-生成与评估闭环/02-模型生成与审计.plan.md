## 1. 目标、范围与依赖

在阶段 01 固定的数据和提示上，提供可恢复的模型生成服务。真实来源通过 `dspy.LM` 访问固定 DMX 服务；离线 mock 通过同一调度、DSPy 响应缓存和 ledger 路径返回确定性响应。交付逐样本原始输出、首次用量/成本记录和可供清洗层消费的最终生成文件。

按[用户裁定 D06](./验收记录.md#d06)，本任务不提供受限 search 调用路径与最小调用方；阶段隔离以约定与方法作者自觉为主。

| 本任务负责 | 后续任务负责 |
| --- | --- |
| 请求配置、样本身份、DMX/mock、并发限速、单层重试、DSPy 响应缓存、单写入者 ledger、生成恢复 | 子任务 03：功能测试、执行结果缓存、pass@k 接线 |
| search/holdout 独立生成进程及独立缓存目录（阶段隔离按 D06 为约定） | 子任务 04：SAST/judge 与动态/真实性评估；阶段 04：研究方法入口、反馈策略、计划/动作恢复及候选锁定排序 |
| 向 judge 提供复用模型请求服务的接入方式，向本地测试提供执行记账入口 | 子任务 05：各层集成、统一报告、真实 2 题 × 1 repeat 验证 |

不开展完整 clean 基线、不实现具体研究算法，不重写 cleaner、oracle 或指标。纯生成的离线开发不依赖 Docker；方法容器边界检查及任何生成代码执行须使用[子任务 01](./01-Docker执行隔离.plan.md)的适用隔离能力与检查证据。子任务 01 已有检查记录不等于第二阶段人工验收通过，实施时核对当前实际配置和证据范围。

## 4. 配置、输入校验与采样身份

### 4.1 配置与凭证

真实运行显式提供来源、模型/provider 路由、采样配置、单次输出 token 上限及任务/提示/输出目录；沿用已有超时、并发、基本限速和有限重试配置，不新增累计额度或逐角色限速配置。mock 使用相同调用与审计路径，模拟成本明确标为非真实。

DMX base 固定为 `https://www.dmxapi.cn/v1`。本期实现 chat-compatible 路径并固定 `n=1`，一个请求产生一个样本；不同时建设 text/responses/streaming 多套接口。不支持的模型能力在启动时报告，不自动换模型、改温度或修改提示。阶段 02 真实验收采用 temperature=0、repeats=1；配置和身份实现应能承接 H 的 temperature=0.7、repeats=5，而不在本任务启动该正式基线。

通过显式 `--repo-dir` 定位根目录 `.env`，用 python-dotenv 按 dotenv 语法读取 `DMX_API_KEY`，支持 `export`，禁止 source/执行文件；当前真实入口以该文件解析值为凭证来源，不静默改用其他目录或同名 shell 变量。只将凭证传给可信真实生成 worker。mock 不读取 `.env`，无密钥也能运行；凭证不进入配置快照、ledger、异常文本、方法容器或 Docker 构建上下文。记录去凭证的运行配置字节哈希，秘密只记录来源标识。

单次输出上限只限制一次响应，不承诺整个实验总费用封顶。本期不要求请求/费用预算配置。费用使用响应或已有可靠计价来源，缺依据记未知，不新增强制价格配置；编写计划不构成新增真实 API 请求授权。

### 4.2 固定任务与提示

1. 核对组合/oracle、固定任务集合、示例互斥、split、prompt form、清洗/判定版本来源及所有输入哈希；任务与提示匹配后才建立采样清单。
2. 旧 4 组合直接使用阶段 01 物化的对应形态提示。每题完整 markdown 作为单条 user message 原样发送；`fewshot.json` 用于核对来源，不再拼入已经含示例的提示。不用 `Predict`/`ChainOfThought` 自动添加字段、推理指令或 system 模板。
3. 同时记录原始提示文件字节哈希与实际消息序列的规范哈希，避免“文件没改但适配器悄悄换消息”的情况。新增生成适配器版本进入运行快照和缓存命名空间。
4. 当前标准 clean 物化覆盖旧 4 组合；新 5 组合静态覆盖不等于已有正式 clean 模板。离线检查可以使用显式测试提示，标记测试用途；不得自动把它们计入 H 的正式 clean 基线。
5. cwe078 使用既定 search 18 / holdout 9。其他无 holdout 的组合以 `set_mode=whole-set`、`stage=search` 运行并保留无 holdout 的事实；这里的 search 是调度阶段，不代表新增研究划分。

### 4.3 身份与批次

直接按 E 的七字段 `stage/batch_id/combination_id/task_id/repeat_id/prompt_version/candidate_hash` 构造身份对象，严格检查字段类型、缺值和 repeat 范围，使用 `canonical_json_bytes` 后 SHA-256：完整十六进制串作为 `sample_id`，同一摘要转非负整数作为 `rollout_id`，不截断为易碰撞的小整数，不使用 Python `hash()`。

clean 运行也显式计算 `candidate_hash`：哈希固定的 clean 模板/示例/形态描述，不用随机占位，也不把时间和输出目录混入。具体哈希载荷固定版本并保存。模型调用的 retry attempt 不进入 sample/rollout 身份，因此同一样本的恢复仍能查询同一缓存键。

一个采样批次绑定不可变配置和明确任务/repeat 清单；批次 ID 在首次调度前持久化，恢复不重新生成。新模型、提示版本、采样配置或扩充采样均建立新批次；追加采样只列新增样本，沿用该实验已有的 repeat 编号序列分配新编号，旧样本继续引用原批次配置，不重写旧 run_config 或重新生成旧样本。跨批次汇总由子任务 05 按完整身份去重，并检查模型/温度/任务口径兼容；不能把不同批次的最终行直接拼成一个含重复 task/repeat 的 cleaner 输入。既有静态批次入口要求完整矩阵，子任务 05 应显式构造保留逐行原批次来源的完整评估视图，不把只含新增 repeat 的批次当作已完成全量实验。

## 5. 单机运行与阶段隔离

按[用户裁定 D06](./验收记录.md#d06)：阶段隔离以约定与方法作者自觉为主，本节的受限调用方、holdout 门与越权拒绝不列为本期验收门；保留 DSPy 缓存目录分离与功能结果不跨阶段复用。

### 5.1 进程和数据布局

采用一个可信协调器，search 与 holdout 各自使用独立生成进程；本期可顺序启动两阶段，无需常驻服务。worker 通过 spawn 或新解释器启动，避免继承已初始化的全局 cache。各进程启动时只配置一次 DSPy 缓存，目录按 `source/stage/调用路径版本` 分配并校验物理分离，拒绝相同路径或符号链接指向同处。mock 与 dmx 同样分开，防止离线响应进入真实实验。

配置快照、ledger 和已归档响应存持久盘，不能放到子任务 01 的临时输出 tmpfs。每个 run 由入口持有一个本机锁（`RunLock`）；内部 worker 不再竞争同一把锁。只支持一个控制者管理一个 run，第二个控制者明确失败，不实现分布式锁或多控制者恢复。

### 5.2 阶段数据分离（按 D06 撤回代码强制）

按[用户裁定 D06](./验收记录.md#d06)：不实现受限 search 调用方与容器 search 视图，也不做越权拒绝检查。search 与 holdout 的分离以约定为主：编写方法时不读取 holdout 数据、不让 holdout 结果进入方法反馈或搜索日志。保留的是 search/holdout 各自独立的生成进程与独立 DSPy 缓存目录（§5.1），这是缓存正确性要求。

### 5.3 holdout 边界（约定）

holdout 在锁定前不用于评估、其结果不回流方法，由方法作者遵守；本期不要求代码强制拒绝，也不把访问门当作验收项。完整的功能合格候选筛选、排序、科研目标与成功判定留给阶段 04。

## 6. DSPy 调用、mock 与响应缓存

### 6.1 统一同步路径

在 worker 中构造显式 `dspy.LM(model=..., model_type="chat", cache=True, num_retries=0, api_base=固定DMX地址, ...)`，通过 `lm.forward(messages=固定消息, rollout_id=稳定身份, ...)` 调用。worker 使用固定配置和有界线程池；LM 实例初始化后不在并发任务中修改 kwargs，不在线切换同步/异步调用、模型类型或 cache 配置。

`forward` 返回后直接在该请求上下文中提取完整生成文本、usage、cache_hit、响应 ID/finish_reason 和必要 provider 元数据。原始文本不清洗；缺失内容、空内容、截断、provider 错误分别记录。成功返回空文本保留原始状态和空文本，由既有清洗/静态编排映射 parse_error；多 choices 或无法解释的响应结构按接口错误处理，不静默选择一个凑成成功。

provider 返回的推理字段与最终 content 分开保存，cleaner 输入仍是显式选定的原始 content；不能根据 oracle 是否命中来挑选字段。首次响应即保留用量，不因解析失败或样本被淘汰而丢弃费用。保存响应正文中的生成内容和必要元数据，排除认证 headers、凭证参数和未脱敏异常；不把 `lm.history` 或 SDK 自动日志当成 ledger。

### 6.2 离线 mock

在专用 mock worker 启动时一次性替换 LiteLLM 的同步 completion 边界，随后仍走 `dspy.LM.forward → DSPy request_cache → completion`；真实 worker 不替换。该方式与本地 DSPy `tests/clients/test_lm.py` 的缓存测试边界一致，但本项目仍需离线运行验证。

mock 返回形状完整的 `ModelResponse`，支持正常代码、脏文本、空文本、异常、固定 usage、延迟以及“前几次失败后成功”的固定场景。fixture 由可信配置和请求上下文绑定，版本/哈希进入 mock 批次；attempt 序列依据已持久事件继续，不能重启后把第一次失败重新无限重放。provider helper 已移除 rollout_id，mock 不要求在出站参数中读到它。

不得替换高层 `LM.forward/__call__` 直接绕过缓存；不得用单独 JSON 缓存代替 DSPy。mock 流程不读取凭证、不调用网络，其费用标为模拟，离线结果不冒充真实服务行为。只保留这一条可复现 mock 路径，不增加本地伪 DMX 服务器。

### 6.3 缓存键、来源和限制

LM 缓存键使用请求参数及函数身份，并默认忽略 API 凭证/base 字段；因此本期固定 endpoint，来源/阶段/适配器版本靠独立目录隔离。模型、消息、temperature 和非空 rollout_id 进入请求键；提示版本经 rollout 身份进入键。执行器或 cleaner 的变化不应自动触发重新生成，生成缓存失效与功能缓存失效由各自依赖决定。

请求 helper 在查缓存后才删除 rollout_id；temperature=0 时不同 rollout 仍应产生不同缓存请求，但输出可以相同。验证缓存是否区分应统计 provider 调用次数，而不是断言两个生成文本必定不同。

每次调用记录 `cache_hit` 及来源引用；没有观测到的内存/磁盘层级不猜测，统一记录 DSPy cache。缓存命中不新增独立样本、不重复记原调用费用；命中时 usage 为空，原用量从已持久化响应事件查找。缓存存在但首次用量事件缺失时记未知，不能按 0 补齐。

正常异常不会写入 DSPy 响应缓存；但成功返回而应用认为结构无效的响应可能已经被 SDK 缓存。不要无限重试同一坏缓存，记录接口问题并停止该样本的自动请求；后续修复通过显式版本/批次处理，不暗中换 rollout 或关闭缓存来多采一次。启动前验证请求参数可序列化；缓存故障或恢复调用意外 miss 必须可见，新增请求遵守单次输出限制及既有调用配置，不承诺无条件零重复费用。

## 7. 有界调度、重试与成本记录

范围按[主方案当前运行控制](../CoCo-Attack%20DSPy%20重建实施方案.md#runtime-scope)。

1. 复用已有有界队列、基本限速与本机 run 锁；同一 sample 不并发制造两次请求。请求超时与单次输出上限传到实际 LM，不能把 Future 等待超时当作请求已结束。
2. 只在应用层执行有限指数退避重试，关闭底层隐式重试。鉴权、配置和响应契约错误不盲目重试；不因生成内容不好或不命中而额外采样。
3. 每次重试保留同一 sample/rollout，使用独立 request_attempt_id，记录开始、响应或异常。恢复继承已有重试轨迹，不反复重试已持久化的终态失败。
4. 终态生成失败以空 generation 留在下游分母；人工取消和未发出的样本保持未完成。中断后先确认旧 worker 状态再补做未完成样本。
5. 按 mutator/victim/judge/local_test 记录消耗事实；judge 在 04 接线，mutator 实际调用在阶段 04 接线。未使用角色如实标注。缓存命中不算新请求或新执行，不复制费用。
6. judge 关联被判样本、评估身份和提示版本；纯推理动作按稳定 action ID 审计。使用已有身份和账本即可，不新增预算 scope 或额度分配系统。

## 8. ledger 与 sample 级恢复

### 8.1 单写入者和首次响应

进程内只设一个 ledger 写入者。worker 将当前请求绑定的响应/异常交给该写入者，等待持久化确认后才向调用方发布完成；其他线程/进程不直接 append 同一文件。

至少使用以下事件：`attempt_started`、`response_received`、`attempt_failed`、`sample_finalized`、`run_paused`，以及外部执行记账事件。每条事件有稳定 event ID、sample/request_attempt 关联、序号、时间、配置来源和结构版本。首次 `response_received` 将生成正文、usage、cache 状态、费用依据一起追加并 flush/fsync；大型派生产物可以随后导出，不能先做清洗、评估或报告再记首次用量。

ledger 是审计事实来源，`generations.jsonl` 和汇总是可重建投影。新增 sample 终态后立即追加最终生成记录并刷新；若在两次写入间中断，恢复从 ledger 补导出，不再调用模型。已收到并持久化的响应足以重建终态时，也先本地完成解析/导出，不把“未写 sample_finalized”当作必须重发的理由。

原始事件不覆盖；更正和恢复说明以新事件追加。缓存结果引用原响应事件，成本按请求尝试/事件身份只累计一次。请求已发但未收到可信用量的失败保留未知；缓存缺失或服务端已处理、客户端未落盘的中断窗口也如实记未知。

### 8.2 恢复步骤

1. 获取 run 锁，校验持久 run_config 字节哈希、输入快照、来源、模型和调用路径/缓存目录。恢复不能顺便改参数；变化建立新批次，不能从旧文件名推断实验配置。
2. 顺序读 ledger，验证 JSON 结构、事件身份和因果关系。只有文件末尾的未完成记录允许保存原始尾部字节后移除/修复；中间损坏或身份矛盾明确报错，不能忽略后续完整历史。必要索引由回放重建，不引入独立持久数据库。
3. 按 sample 建立“未开始、未决、有持久响应、终态成功/失败”的恢复视图，去重已完成记录和记账事件。先停止或确认旧 worker 已退出，再处理未决尝试。
4. 完整终态跳过；有持久响应但缺终态的本地补齐；未决样本以同一请求和 rollout 查询原阶段 DSPy 缓存，重试次数继承已记历史。缓存命中却缺首次费用时保持未知；miss 后若需重新联网，遵守本次运行的模型调用授权和调用配置；中断费用保持未知，不能静默填零。
5. 重导出每样本唯一最终记录，保留未完成清单和原批次身份；不会从第一个样本全部重跑，也不恢复 Python 程序计数器。新 request attempt 只代表一次执行尝试，不改变 sample/repeat。

无法确认的中断尝试保留审计记录和未知费用；新请求单独记账。本期不要求恢复剩余额度或持久化预算预留。旧迭代版本只读；版本失配拒绝续跑，新评估另建运行并引用旧输入。

## 9. 产物、CLI 与后续接线

新产物全部写入显式输出目录；采用新 run 与显式恢复两个入口，复用现有路径边界检查。阶段视图、缓存和结果目录由可信入口生成，方法不能指定任意主机路径。沿用已选持久产物根，文档保存实际路径与哈希引用，不因创建本计划自动搬迁或删除既有记录。

| 产物 | 用途 |
| --- | --- |
| `run_config.json`、`manifest.json` | 去凭证不可变配置、批次、输入快照、模型/来源/适配器/DSPy 指纹、完成范围和产物索引 |
| 分阶段物化视图和采样清单 | 允许的任务/提示、完整 sample 身份及对应 prompt 哈希；方法仅挂载 search 投影 |
| `ledger.jsonl` | 请求开始、首次响应/用量、异常/重试、终态、恢复及四类费用来源 |
| 按批次/阶段/组合导出的 `generations.jsonl` | 每 sample 一条最终记录，兼容 `clean_generations` 的四个必填字段；完整身份和来源以附加字段保留 |
| `generation_summary.json`、`REPORT.md` | 预期/完成/失败/未完成数、请求与重试、缓存来源、已知费用/未知消耗、限制及检查范围 |
| 可信锁定记录与阶段边界检查产物 | （按 [D06](./验收记录.md#d06) 为可选加固）锁定绑定、拒绝请求、可见字段与阶段数据分离证据，供子任务 05/阶段 04 复用 |

日志是累计审计信息，整份 generations 文件哈希只作审计；子任务 03 使用本样本原始生成哈希、提示哈希、原 run_config 字节哈希等构造功能缓存指纹，不因别的样本追加而使旧样本全部失效。

拟新增命令如下，均为实施目标，不是已存在或已执行的命令：

```text
coco-attack check-generation --config <配置> --data-dir <准备产物> --prompts-dir <物化提示> --output-dir <新检查目录>
coco-attack generate --config <配置> --data-dir <准备产物> --prompts-dir <物化提示> --output-dir <新run目录> [--repo-dir <真实来源凭证根>]
coco-attack resume-generation --run-dir <已有run目录> [--repo-dir <真实来源凭证根>]
```

配置检查不发送真实请求；阶段内部 worker 不是面向方法的 CLI。完整 holdout 必须由可信锁定状态触发，不能靠附加 `--stage holdout` 绕过。所有未完成/阻塞状态非零退出且保留记录，沿用已有 usage/config 错误与运行阻塞的退出码区分。

子任务 05 负责把生成文件接入 `clean_output` 和完整静态编排，保留生成失败/空输出到 parse_error 的语义。子任务 04 judge 接入本任务模型服务时仍需重新解析、校验其结构化判定；DSPy 响应缓存不等于 judge 结果缓存。

## 10. 集中检查与实施顺序

不为每个模块新增独立测试套件；用一组小型 mock 清单和故障注入验证关键行为，优先复用阶段 01 样例及子任务 01 的 run 锁/容器检查。源码核查、离线 stub、真实 Docker 和真实 API 的证据分别标注。

| 阶段映射 | 必要检查点与预期 |
| --- | --- |
| AC-02 | 提示文件与实际消息对应，三种形态无意外增删；mock 正常/脏/空/失败均有最终记录，下游保留正确分母；新 5 组合测试提示不冒充正式 clean 模板 |
| AC-03：身份/缓存 | 同一样本恢复沿用 rollout；新 repeat/批次/提示版本/模型按规则区分；t0 不同 rollout 产生不同缓存键，用空缓存核对各自首次 provider 查询且允许输出相同；进程重启后磁盘缓存仍可复用，mock/dmx 和 search/holdout 不串缓存 |
| AC-03：调度/费用 | 已有有界在途/基本限速/单层重试；单次输出上限传到模型；首次响应用量持久化；缓存恢复不重计、失败费用不丢；中断样本保持未完成；同 run 第二个控制者被拒 |
| AC-03：故障恢复 | 请求已发未记响应、响应已记未导出、尾部半行、完整终态失败、旧 worker 未结束；按 sample 恢复且费用未知如实保留；中间损坏拒绝，不静默丢历史 |
| AC-04 | 按 [D06](./验收记录.md#d06) 撤回代码强制部分：只核对 search/holdout 独立缓存目录；越权拒绝与访问门不作为验收项（改为方法作者约定） |
| AC-05 | 子任务 05 在离线与隔离检查通过、真实模型和单次输出上限已配置后运行 2 题 × 1 repeat；核对实际 provider 请求、原始文本、usage/cache 标记、ledger 与最终生成记录，再接各评估层 |

实施顺序：

1. 固定输入读回、配置/身份与最终生成契约，直接复用既有清洗输入格式及 run 锁。
2. 实现同步 DSPy 适配和专用 mock worker，先验证真实缓存边界、响应/usage 提取及 t0 rollout 行为。
3. 接入单写入者 ledger、有界调度、Tenacity、单次输出限制和同版本 sample 恢复；集中做中断窗口与重复记账检查。
4. 完成分阶段 worker/cache、search 物化视图、最小容器调用方和可信 holdout 门，用实际 Docker 验证访问边界。
5. 提供 CLI、导出和报告，把版本/接口、未决项与检查点交给子任务 03/04/05；真实 API 完整验证由子任务 05 汇集，不在本任务重复启动付费实验。

交接条件是：同一路径的 mock 与真实来源适配具备可审查接口，离线调度/缓存/恢复/审计及方法容器边界有实际证据，阶段输入输出和费用限制可追溯。尚未执行的真实验证明确保留，不以 mock 通过宣称 DMX 已验证，也不以本任务交接代替阶段人工验收。
