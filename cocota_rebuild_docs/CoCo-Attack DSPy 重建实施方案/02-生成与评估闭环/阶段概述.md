# 阶段 02：生成与评估闭环

依据：[主实施方案](../../CoCo-Attack%20DSPy%20重建实施方案.md)工作包 D、E、F、G；需求对应 F3–F8、E1–E5 及首次响应记账规则。状态：规划阶段，尚未实施或验收。

## 1. 阶段目标与边界

在阶段 01 的领域基座上接通模型生成、隔离执行、各评估器和完整报告，形成支持离线 mock、真实小样本、中断恢复的实验流水线。

静态层覆盖 9 组合；动态层和真实性层仅覆盖旧 4 组合。评估侧只实现功能测试结果缓存，其他评估器正常执行并保留缓存接口；DSPy 模型响应缓存独立保留。本阶段不开展完整 clean 基线，不实现具体迭代算法。

## 2. 输入与前置依赖

- 继承阶段 01 的数据/实验记录、任务与提示快照、显式 oracle 路由、清洗与指标接口、环境依赖清单及校准结论。
- 已知差异不得通过接入新管线静默消除；涉及判定语义或历史对拍差异仍须由用户裁定。
- 需要可用的 Docker 运行环境和固定的 CPython 3.14 评测镜像。Docker 隔离验证是执行生成代码的前置检查，包括会执行代码的 mock 冒烟。
- 真实 API 验证需要用户提供模型、预算及请求限制配置；从仓库根目录 `.env` 加载 `DMX_API_KEY`，不将凭证注入代码执行容器。

## 4. 公共服务与数据流

### 模型生成与阶段边界

- `dspy.LM` 对接固定 DMX base `https://www.dmxapi.cn/v1`；mock 使用相同调度、缓存与审计路径。模型和费用配置显式提供，未知费用不填零。
- 并发上限控制同时在途请求数，限速控制单位时间请求/token 数；重试计入限额和预算。复用 Tenacity，关闭底层隐式重试，避免双层重试并确保每次尝试可审计。
- rollout_id 由阶段、批次、组合、task、repeat、提示版本、候选 hash 确定性派生。恢复身份不变，新增采样使用新身份；它区分本地缓存，不是模型随机种子。
- search/holdout 使用独立进程与独立 DSPy 缓存目录。只创建两个 LM 实例不足以隔离全局缓存；可信协调器在锁定前拒绝 holdout 生成、评估和读取。
- 从本阶段起提供只暴露 search 数据的受限调用路径与最小调用方，用于验证缓存/文件隔离；阶段 04 在此基础上接入方法，不另建一套阶段隔离。
- 单写入者即时追加 ledger，记录首次响应 token/成本、失败与重试、缓存来源；恢复不重复计成本。服务端完成但客户端未持久化的窗口如实记录。

### 隔离执行与功能测试缓存

- 执行容器非 root、根文件系统只读、禁止提权、移除额外 capabilities，只挂载本样本输入与必要输出空间，不挂载仓库、凭证、Docker socket。禁止外网，需要的本地测试服务置于隔离环境内。
- 将时间、CPU、内存、进程数和输出限制纳入评估配置。超时执行 SIGTERM→SIGKILL 并清理容器内子孙进程；校验后完整落盘的结果优先保留，不能只依赖进程退出码。
- 功能测试缓存保存每个生成样本的通过/不通过、完成状态、原因和执行环境。只有完整有效结果可复用；环境不可用、基础设施错误、损坏或未完成结果不复用。
- 采用分阶段 SQLite 索引，指纹包含批次配置、提示、生成内容、清洗代码、任务/测试快照、清洗与 harness 版本、镜像和资源限制。依赖变化重算受影响样本，追加记录不使全部旧结果失效。
- pass@1/@3/@5 从不同采样身份的功能结果重新聚合，不直接缓存汇总值，不把缓存读取算新证据。

### 评估与报告

流程为：归属校验 → 清洗 → 静态 oracle → SAST/judge → 核心结果落盘 → 功能/动态/真实性评估 → 汇总。

其他评估器使用查询总未命中、写入不缓存的接口，仍正常判定和保存产物。LLM judge 可以复用 DSPy 模型响应，但重新执行结构化解析与校验。动态/真实性层不借用静态标签作为行为答案，真实性层不按静态命中预筛。

统一区分评估结论、未覆盖、工具不可用和执行错误；不为未覆盖生成伪 verdict。模型的 prefix cache 信息如实记录，不能假设 DMX 全部模型都支持或必定命中。

## 5. 阶段统一测试与人工验收

子任务仅贡献检查点，由管线集成子任务汇集并去重。复用阶段 01 的输入和断言，不为每个适配器建设重复测试。

| 验收组 | 集中场景与证据 |
|---|---|
| 执行隔离前置检查 | 主机文件/凭证不可读、外网不可达、资源限制生效、超时后子孙进程清理、完整落盘结果保留；先于任何生成代码执行 |
| 离线完整流程 | 少量 mock 样本组合覆盖成功、脏输出、失败、不同 verdict、工具缺失和新组合未覆盖；报告分母与可用性正确 |
| 恢复、缓存与计费 | 一组故障注入覆盖生成/功能测试中断恢复、新 repeat、版本失配、半成品拒绝、pass@k 重聚合及成本不重复 |
| 阶段隔离 | 从 search 受限调用路径访问 holdout 数据、缓存或评估必须失败；功能结果不得跨阶段复用 |
| 真实小样本 | 离线检查通过后运行 2 题 × 1 repeat，核对原始响应、用量、判定、功能结果及完整报告；低重复配置的无效指标标未定义 |

本阶段[验收记录](./验收记录.md)集中列出命令、版本、检查结论与关键产物链接。基础设施未就绪标明阻塞；mock 通过不能代替真实 API 验证，工具降级也不能冒充该工具可用。
