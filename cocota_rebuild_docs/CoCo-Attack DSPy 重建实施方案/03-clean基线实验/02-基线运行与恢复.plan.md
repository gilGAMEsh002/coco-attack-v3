## 1. 目标与控制范围

按运行清单执行全部 24 单元（30 次 pipeline 运行），交付逐单元完整采样记录、评估产物、恢复记录与成本记录，并把每单元终态写回运行清单。

具体边界：

- 编排只做调度、状态登记与恢复入口，评估语义全部复用阶段 02 的 `run-pipeline`/`resume-pipeline`；不在编排层重写指标、清洗或判定逻辑。
- 单元失败如实记录并继续其余单元；不通过删样本、换任务或重抽"好结果"制造完成；未完成单元显式列出，交 03 汇总。
- 本期成本控制只核对单次输出上限已随请求下发并记录；不实施总量准入，但清单登记的请求数基准用于异常核对。
- 真实运行消耗 DMX 配额；启动前向用户确认模型、单次输出上限与运行窗口，1,962 次估算不是费用授权。

## 2. 接入起点

编写本计划时已核对阶段 02 验收后源码（提交 `e0255f9b8`）：

| 事项 | 现状 | 本任务的处理 |
| --- | --- | --- |
| 单单元执行 | `run-pipeline --config <cfg> --output-dir <fresh>`；步骤 generation→cleaning→static→core→other→functional→report；`actions.jsonl` + RunLock | 编排逐单元生成 fresh run 目录并调用；复用其步骤屏障与 core checkpoint |
| 单单元恢复 | `resume-pipeline --run-dir <dir>` 从动作日志续跑；已完成样本去重、不完整尾记录处理 | 中断后先对中断单元做 `resume-pipeline`，不重建 run 目录、不重新生成已完成样本 |
| 单元终态 | 报告 `complete=true` 才记 `complete`，否则 `incomplete`；退出非 0 记 `blocked` | 编排以 pipeline 自报终态为准更新清单，不把进程退出 0 当作完成 |
| 功能缓存 | `PipelineConfig.functional_cache_dir` 可配，`functional-cache-v1/<stage>/` | 全部单元指向基线根目录的共享缓存根；命中记复用来源，不增样本、不重复记账 |
| 响应缓存 | 各 run 目录 `dspy-cache/dmx/<stage>`，仅同 run 恢复复用 | 保持现状；单元之间不共享响应缓存 |
| 成本记录 | 各 run `ledger.jsonl` 按角色记账，未知不补零 | 编排不另立账本；汇总时逐 run 读取，保留各 run 来源 |
| 外部生成 | `--accept-existing-generation` 冻结并校验既有生成批次 | 正式基线单元一律由本单元自行生成，不接外部生成批次 |

## 3. 调度顺序与锁定屏障

1. 执行前重新运行 `check-baseline`（01 §5.2），任一启动条件失效则停止并汇报。
2. 调度顺序：先全部 whole-set 单元与 cwe078 search 运行，最后 cwe078 holdout 运行。启动每个 holdout 运行前执行 01 §5.1 的唯一校验：比对 `baseline-lock.json` 与当前输入快照、单元配置哈希；不一致即阻塞该运行并汇报，不以新配置直接跑 holdout。
3. 单元默认串行；并发度来自 matrix-config（默认 1）。并发度 >1 时并发只发生在不同单元之间，每个单元仍是一次独立子进程（§7），各自绑定单一 stage 与 dmx 来源、启动时配置一次缓存——本条 4 的进程/缓存绑定约束不变；同 stage 并发单元共享该 stage 的功能缓存根，须符合现有 SQLite 持久化语义，有疑虑时保持串行。不建设并发调度系统。
4. 每个进程只绑定一个 stage 与 dmx 来源，启动时配置一次缓存（沿用阶段 02 语义）；search 与 holdout 运行自然落在不同进程与物理缓存目录。

## 4. 中断与恢复

分两级，均限同一版本（[D04](../02-生成与评估闭环/验收记录.md#d04)，口径见 01 §5.2 第 5 条）：

1. **单元级**：运行中断（进程退出、断电、API 长时间不可用）后，对该单元 `resume-pipeline`。已完成样本去重、有效功能缓存命中、未知请求窗口标未知，均沿用阶段 02 已验收语义。
2. **清单级**：编排重启时读取运行清单，逐单元核对 run 目录与状态：`complete` 跳过；`running/incomplete` 先验证版本三元组（git commit + 输入快照哈希 + 评估版本）与清单一致再进入单元级恢复，不一致则标 `blocked` 并汇报，不跨版本续跑；`pending/configured` 按调度顺序新起。
3. 有限重试：单元级恢复对同一单元的次数上限由 matrix-config 提供；超限标 `blocked` 记录原因，继续其余单元。服务端费用无法确认的中断窗口标未知，不填零、不承诺 exactly-once。
4. 恢复只补做没有有效结果的样本；追加采样必须新批次新身份，本期矩阵固定不追加。

## 5. 缓存与成本记录

- 功能缓存：命中读取原功能测试结果并记录复用来源；环境不可用、基础设施错误、未完成或损坏结果不复用。缓存命中不跨 search/holdout 边界；恢复场景 pass@k 按当前固定任务集合重新聚合。
- 其他评估器（静态/SAST/judge，及启用时的动态/真实性）按 F2 始终重新判定，响应解析与校验照常；judge 模型请求可命中同 run 的 DSPy 响应缓存。
- judge rate 与 evasion 的记录口径按[阶段 02 D08](../02-生成与评估闭环/验收记录.md#d08)：judge 失败/缺失样本另列于 availability，不进 judge rate 分母，不等于未检出。
- 成本按 victim/judge/local_test 记录（mutator 本期未调用，如实报告"未调用"，不造费用）；首次响应即落账，缓存恢复不重复累计；judge 重试与 victim 重试各自记账。
- 实际请求数、重试次数、缓存命中数逐单元汇总，与 01 §4.2 的请求数基准对照；差异超出重试可解释范围列入异常，交 03 展示。

## 6. 失败与降级处理

- 生成失败按既有语义转 `parse_error` 留在分母；单元内个别样本失败不阻塞单元其余样本。
- Docker 中途不可用：功能步骤按 D 的降级边界报告 unavailable，单元标 `incomplete`（功能缺口注明），**不退回主机裸执行**；该单元不得宣称可用功能基线，交 03 在报告中单列。
- SAST/judge 工具失败：按 G 与 D08 记录为工具失败/不可用，样本另列、不进 evasion/judge rate 分母，不计逃逸命中；目标规则未覆盖的组合记 `target_rules_uncovered`。
- API 限流/超时：沿用既有有界并发、限速与单层指数退避；不因失败提高并发或绕过限速。
- 任何题数、分母、verdict 口径异常先整体汇报（[C](../CoCo-Attack%20DSPy%20重建实施方案.md#calibration)），由用户裁定后再改实现。

## 7. 编排模块的本任务部分（拟定实现）

在 01 的 `coco_attack/experiments/` 包中实现：

- `orchestrate.py`：按 §3 顺序遍历清单；每单元以独立子进程调用 `python -m coco_attack run-pipeline --config <单元config> --output-dir <units/<unit_id>/<stage>>`，恢复时以子进程调用 `python -m coco_attack resume-pipeline --run-dir <run目录>`；写回单元状态与产物位置。不采用进程内函数调用，保证每单元进程只绑定一个 stage/来源、启动时配置一次缓存（§3.4）。
- 恢复入口：清单级扫描 + 单元级 `resume-pipeline` 子进程包装，含版本三元组核验与有限重试计数。
- CLI：`coco-attack run-baseline --baseline-root <dir>`（按清单执行/继续）、`coco-attack status-baseline --baseline-root <dir>`（逐单元状态、请求/成本快览，不发起请求）。
- 运行日志：逐单元开始/结束/中断/恢复事件追加到基线根目录 `manifest/orchestrator-log.jsonl`（单写入者、fsync，复用 ledger 写入语义）。

至少包含一次受控中断-恢复演练：在开发环境用 mock 来源 pipeline 中断再恢复（证据明确标注为 mock、非基线运行，不与正式单元产物混淆），验证：样本身份不变、已完成样本不重复请求/计费、功能缓存合法命中、清单状态正确迁移。

## 9. 交付与交接

交付：全部单元的 run 目录（采样记录、评估产物、报告）、更新后的运行清单与 orchestrator 日志、逐单元成本/恢复记录、未完成与阻塞单元清单及原因。向子任务 03 移交基线根目录与上述记录；任何单元状态存疑（产物缺失、版本不符、锁定破坏）不得标 `complete`。
