## 1. 目标与控制范围

交付：覆盖核查结论、分组报告、可检索 baseline 索引、阶段审查材料，并向阶段 04 移交对齐的基线产物。

具体边界：

- 汇总只读取既有产物（`report-pipeline` 级语义：身份核对、指标计算、导出），不重新调用模型或评估器，不产生新费用；发现产物缺口标未完成，不补跑——补跑属 02 的范围。
- 不修改单元报告中的指标数值去迁就汇总表；汇总层发现的口径问题整体汇报。
- 不自动选"最好"的形态作为全局基线；索引按口径字段严格匹配。
- 历史结果（含 cwe078 t0.7r5 旧诊断）只作口径明确的诊断对照，不冒充本期正式基线，也不据此重算本期指标。

## 3. 覆盖与分母核查（AC-01/AC-02）

1. 以运行清单为全集核对 24 单元/24 运行条目：每单元状态、run 目录、报告 `complete`、预期 vs 实际样本数（题数 × repeats）、missing/extra 样本列表。未完成、阻塞、功能不可用单元显式列出及原因。
2. 分母检查：生成失败/parse_error 留分母；缓存命中不增样本数；追加样本不存在（本期矩阵固定）；单元之外的样本拒收记录。
3. 口径检查：报告与索引按 `split_mode` 成列——cwe078 search 18 与 holdout 9 分别报告，whole-set 组合按 whole-set 报告且不宣称 holdout 验证；whole-set 单元内部 `stage="search"` 只是实现细节，不出现在对外口径。两种温度、两种 repeats 的结果分别成列；evasion/judge rate 是本次生成样本集上的观测比例，比较时必须匹配采样配置。
4. 整组合口径核查：四组合均整组合运行、无基线 holdout 锁定；cwe078 的 `search-18`/`holdout-9` 结论只能来自索引的派生 split 视图（见 §5.1），不得用整组合数字冒充。

## 4. 指标适用条件核查（AC-02/AC-03）

逐单元核对指标可定义性，未定义的写明原因，不填 0：

- repeats=1 的 12 个单元：pass@3/@5 未定义（n<k），只报 pass@1。
- evasion（SAST 逐工具与 llm）按[阶段 02 D08](../02-生成与评估闭环/验收记录.md#d08) 观测口径：asr_hit 子集上的观测逃逸比例，任意采样配置下 asr_hit 数 ≥1 即给值，不是采样概率估计；登记 `basis="observed"`、采样配置与 `sampled_run` 元数据（t0.7 且 repeats≥5 为 true）、`denominator_definition`；零分母（无 asr_hit）未定义。比较时必须匹配采样配置。
- llm_judge_rate = 检出数 / judge 成功完成样本数；judge 失败/缺失样本单列于 availability，不进分子分母，不等于未检出；无成功样本时零分母未定义。检出口径为本组合目标 CWE（[阶段 02 D05](../02-生成与评估闭环/验收记录.md#d05)），语义版本 `judge_detection_version=target-cwe-v1`（D08）；非目标 CWE 仅诊断另名。
- SAST 目标规则未覆盖的组合记 `target_rules_uncovered` 未定义，不记未检出、不制造"全部逃逸"。
- 三种"没有值"分别标注，不互相冒充：**配置未启用**（默认关闭的 dynamic/realism，开启后才有分布）、**按设计未覆盖**（`not_covered`，本期旧 4 组合不涉及）、**环境不可用**（工具失败/缺失）。配置未启用不得记为未检出或未覆盖。
- 动态层三态、真实性层四态（如启用）分布如实报告，不混入 ASR；本期默认未启用时标"配置未启用"。
- clean ASR 统一称**自然命中率**，不预设趋近 0；显著偏高的单元列入人工审查（§6），样本实际含目标模式与 oracle 误判分别核查。
- 功能测试不可用的单元：功能指标整体未定义并注明环境原因，不得宣称可用功能基线；对应索引条目标功能不可用。

## 5. baseline 索引与分组报告

### 5.1 索引 schema（baseline-index-v1）

每条目登记：组合/oracle、提示形态、`split_mode`（search/holdout/whole-set 口径）、任务集合、模型、温度、repeats、适用 k、`enabled_layers`/`sast_tools`、提示/物化版本、数据契约、cleaner/oracle/静态外壳/harness/镜像版本指纹、`judge_prompt_version` 与 `judge_detection_version`（值来源：evaluator `manifest.json` 与 judge 记录 `sources`）、`basis`/`sampled_run`、run 目录与报告产物位置及哈希、单元状态（complete/incomplete/功能不可用）、登记时间。cwe078 每个整组合单元产生一条 `split_mode=whole-set` 条目，并派生 `search-18`/`holdout-9` 两条视图（按固定 split 的 task_id 从同一次运行切出）；索引构建时校验产物哈希，缺产物不建条目。

查询语义：按口径字段精确匹配；多模型各自成条目；缺失或口径错配时返回"无对齐基线"，调用方不得据此认定候选功能合格（供阶段 04 消费）。索引只登记本期正式基线，烟测子集运行不得入库。

### 5.2 分组报告（每模型一份，Markdown + JSON）

- 矩阵视图：4 组合 × 3 形态 × 2 采样配置，按 `split_mode` 成列，逐格给出 pass@1（/ @3/@5 如可定义）、自然命中率（ASR@1/@k）、evasion 与 judge rate（t0r1 单元同样给出，带 `basis=observed` 与采样配置标注）、功能可用性与单元状态链接。
- 分布与可用性：按启用层呈现——静态 verdict 分布、SAST 工具 × 组合覆盖矩阵、（启用时）动态/真实性分布、执行失败分类（生成失败/解析失败/执行错误/环境不可用分别计数）；未启用层标"配置未启用"。
- 成本：逐角色（victim/judge/local_test）token 与费用、缓存命中与复用来源、重试次数、未知窗口单列不补零；与 01 的请求数基准对照及差异说明。
- 版本与来源：git commit、DSPy 版本、全部评估版本与镜像摘要、`judge_prompt_version`/`judge_detection_version`、裁定引用（D 编号链接）。
- 可追溯性：从汇总单元到 run 目录、逐样本记录、原始响应、final_code、判定依据的链接。

### 5.3 拟定实现

在 `coco_attack/experiments/` 增加 `index.py`（索引构建/校验/查询）与 `summary.py`（覆盖核对、指标适用条件检查、分组报告导出）；CLI：`coco-attack report-baseline --baseline-root <dir>`。纯离线计算，配套单元测试用构造产物覆盖：缺样本、功能不可用、n<k、规则未覆盖、缓存命中不计数、索引口径错配、`basis`/`sampled_run` 登记、未启用/未覆盖/不可用三种状态区分。

## 6. 人工审查材料与阶段收尾（AC-04）

- 异常样本清单：生成失败/parse_error、自然命中率显著偏高单元、judge 非目标 CWE 诊断集中项、（启用时）动态/真实性异常分布；每项链接原始响应、清洗代码与判定依据。
- 显著差异：与历史 run 的对照只作诊断并注明口径（`judge_detection_version`、cleaner-v3、oracle v2 的影响）；新差异按 [C](../CoCo-Attack%20DSPy%20重建实施方案.md#calibration) 整体汇报，不擅自修指标。
- 声明核查：报告与索引中无"由 holdout 结果调整模板"的痕迹；whole-set 结果未被引作 holdout 验证。
- 收尾：按 AC-01–AC-04 把证据汇入[阶段验收](./阶段验收.md)，列出未完成单元、适用限制与未决问题；同步[阶段概述](./阶段概述.md#current-status)当前进度。文档整理不代签人工结论。
