## 1. 背景与动机

当前 clean 基线（Z：4 组合全 whole-set、24 单元/24 运行）为**全串行**执行，实测约 **28 s/样本**，预计整跑 ~13–17 小时。用户提出：能否像原项目那样使用并发来缩短墙钟时间。实测分解（已完成单元 `cwe078-0__clean_fewshot_cot__t0.7r5`，135 样本、总 3219s）：

| 阶段 | 耗时 | 占比 | 备注 |
|---|---:|---:|---|
| generation | 539s | 16.7% | `generation_max_concurrency=1`，ThreadPool worker=1 |
| static | ~0s | 0% | — |
| **SAST** | **2099s** | **65.2%** | 逐样本、逐工具起进程；CodeQL 每样本建库 |
| judge | 115s | 3.6% | 顺序 |
| functional（Docker） | 465s | 14.4% | `max_parallel_containers=1` |
| report | ~1s | 0% | — |

SAST 单工具实测（极小文件，调用方式与代码一致）：

| 工具 | 单次耗时 |
|---|---:|
| bandit | 0.16s |
| semgrep（重载整个规则目录） | 2.25s |
| codeql `database create` | 4.15s |
| codeql `database analyze`（1 条 query） | 8.55s（二次 5.38s） |

原项目 `CoCo-Attack`（参考，非本项目契约）：victim/mutator/judge 用 async 引擎（`asyncio.Semaphore(max_concurrent=5)`、`rate_limit_rpm=60`）；功能测试用宿主机 `ProcessPoolExecutor(cpu_count//2)`；dynamic/realism 用 multiprocessing `parallel=4`。本项目为 Docker 隔离 + 同步 DSPy 路径，不能直接照搬（见 §3）。

<a id="requirements"></a>

## 2. 需求描述

目标：在**不改变实验语义、不削弱执行隔离、不破坏缓存与审计**的前提下，为重建流程引入**可配置、可审计、有界**的并发与提速机制，显著缩短基线及后续阶段的墙钟时间。按建议优先级：

- **R1（SAST 提速，优先级最高）**：降低 SAST 的 per-sample 固定开销。可选手段：CodeQL 批量样本共用数据库并一次 analyze 后按文件映射回样本；查询预编译/热缓存；semgrep/bandit 多文件批调用；样本级有界并发。要求并发/批处理前后**逐样本 verdict 与归属一致**。
- **R2（生成层并发）**：矩阵可配 `generation_max_concurrency>1`，并配合 `requests_per_minute`/`tokens_per_minute` 限速；复用现有 `ThreadPoolExecutor` 与 `runtime/limits.py`，**不引入 async 生成路径**（保持与 E 契约相同的同步 DSPy 调用路径）。
- **R3（Docker 功能测试并发）**：执行 profile 支持 `max_parallel_containers>1`，`run_functional` 用有界线程池并发执行容器；功能结果缓存须线程安全（写锁或 WAL + `busy_timeout`），结果按样本顺序归并；重做资源预算与隔离验收。
- **R4（可配置与可审计）**：并发/限速参数进入矩阵与执行 profile 并纳入版本指纹；运行记录实际并发、限速与重试/429 统计；未知仍记未知。
- **R5（一致性优先）**：并发是**实现手段**，不得改变任务集合、划分口径、指标/分母、judge/SAST 检出口径、缓存隔离与失败语义。

<a id="invariants"></a>

## 3. 必须保持不变的约束（不在本需求内可改）

1. **实验语义**：任务集合、划分（Z：基线 whole-set；cwe078 18/9 属方法阶段）、指标公式与分母、`basis=observed` 口径、`judge_detection_version=target-cwe-v1` 不变。
2. **执行隔离（D）**：容器非 root、只读根、无网络、资源/超时限制、SIGTERM→SIGKILL 子孙进程回收、结果保留语义不得削弱；提高容器并发须重新做资源预算（tmpfs 容量/inode、内存、pids）与隔离验收（原 AC-01 证据是 `max_parallel_containers=1`）。
3. **生成/缓存契约（E/F）**：同一条同步 `dspy.LM.forward` 路径；`rollout_id`/缓存键语义不变；有界并发 + 基本限速 + 单层重试；功能缓存按阶段隔离、指纹完整、不可用不复用、缓存恢复不重复记账；响应缓存不被并发破坏。
4. **评估契约（G）**：逐工具 SAST 覆盖与 evasion 口径不变；CodeQL 批处理后的**结果归属**必须可证明且与逐样本一致；工具失败/未覆盖仍记未覆盖，不计未检出。
5. **版本冻结**：任何实现变更须提交并重新冻结基线（§5.2.5）；不得在运行中的 run 上中途改矩阵/profile/代码。
6. 不新增累计预算/额度控制（沿用[运行控制](../CoCo-Attack%20DSPy%20重建实施方案.md#runtime-scope)与阶段 02 D04）。

<a id="approach"></a>

## 4. 建议实现方向与顺序

1. **SAST（收益最大）**：
   - CodeQL 从“每样本 `database create` + `analyze`”改为**批内共库**：一批样本写入同一 `--source-root`，建 1 个库、跑 1 次目标 queries，按相对文件路径映射回样本；保持每样本独立归属与指纹。
   - semgrep/bandit 一次调用传多个文件以摊薄规则加载/进程启动。
   - 对 SAST 调用加**有界样本级并发**（受 CPU 核数限制；注意 CodeQL 自身吃多核）。
2. **生成层**：`generation_max_concurrency` 小步提升（2→5），必须先设 `requests_per_minute`（如 60）与 `tokens_per_minute`，观察 429/重试/单位时间 token。
3. **functional**：`max_parallel_containers>1` + 有界线程池 + 缓存线程安全；按容器资源（当前 memory 512MB / cpu_quota 1.0 / pids 64）与主机余量确定上限。
4. **judge**：顺序实现开销小（~0.85 s/样本），收益有限，可暂不并发。

<a id="acceptance"></a>

## 5. 验收与证据要求（拟）

- **等价性对拍（必须）**：并发/批处理前后，同一固定输入在 mock 下逐样本 verdict、归属与指标逐值一致；不可用/失败分类不变。
- **隔离验收**：提高容器并发后重跑 `check-execution`/`verify-isolation`，资源包线（tmpfs 容量/inode、内存）与超时回收仍通过；不退回宿主机裸执行。
- **缓存一致性**：并发下功能缓存无 `database is locked`、无半成品复用、无重复记账、阶段隔离不破。
- **限速生效**：单位时间请求不超过配置；429/重试有记录。
- **性能证据**：给出各阶段墙钟时间与吞吐改善对比（含并发度/限速配置）。
- 证据按主方案第 5 节登记到阶段[验收记录](./验收记录.md)。
