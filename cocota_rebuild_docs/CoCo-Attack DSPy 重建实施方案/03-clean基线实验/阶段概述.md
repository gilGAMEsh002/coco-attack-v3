# 阶段 03：clean 基线实验

依据：[主实施方案](../../CoCo-Attack%20DSPy%20重建实施方案.md)工作包 H；需求对应 F2、F3、F6、F8、E1、E4 及 X2 的基线用途。状态：规划阶段，尚未运行或验收。

## 1. 阶段目标与边界

使用已验收的流水线运行旧 4 个组合的 clean 基线，产出功能通过率、自然命中率和可追溯实验记录，为后续迭代的功能约束与增量比较提供参照。

三种提示形态全部不注入触发器、不投毒；复用阶段 01 已准备的素材和阶段 02 的运行/评估工具。本阶段以实验运行和人工核查为主，不另建评估实现或重复测试套件，不根据 holdout 结果调整模板，也不自行确定后续方法的目标权重或 ε。

## 2. 输入与启动条件

- 阶段 01 已固定的数据、示例、评测集合、三种提示、划分和静态校准结论；阶段 02 已通过隔离、离线恢复和真实小样本验收的流水线。
- 用户提供真实模型名称、预算、并发/限速与请求上限；不根据历史 run 自动选模型或推定可用额度。
- 每个采样批次固定任务/提示快照、协议、生成与评估配置、镜像和工具版本，运行前完成检查；配置变化创建新批次，不覆盖原结果。
- 工具可用性和已知限制在运行前列出。功能测试不可用时可保留其他诊断结果，但不能据此宣称得到可用的功能基线。

## 4. 实验矩阵与交付口径

### 固定任务集合

| 组合 | 评测题数 | 报告集合口径 |
|---|---:|---|
| cwe078 | 27 | search 18 / holdout 9，分别报告 |
| cwe094 | 4 | whole-set |
| cwe295 | 33 | whole-set |
| cwe502 | 45 | whole-set |

题数以阶段 01 校准后的清单为输入，若与表中预期不同先报告，不自行增删任务。每个组合的三种形态使用相同评测集合，0-shot 不额外加入示例题。

### 提示与采样配置

- 提示形态：0-shot、4 个 clean 示例无 CoT、相同 4 个 clean 示例带 CoT。无 CoT 版本同时处理示例 cot 和输出 tail，不调用 DSPy ChainOfThought 代替既有素材。
- 采样配置：temperature=0/repeats=1 与 temperature=0.7/repeats=5，独立运行、分别报告。前者无法估计 pass@3/@5，必须标未定义，不借用另一温度的样本补齐。
- 单模型共有 24 个“组合 × 提示形态 × 采样配置”单元。按当前集合，victim 请求数为 `(27+4+33+45) × 3 × (1+5) = 1,962`，不含 judge 和重试；这只是数量估算，不是费用授权或预算数值。
- cwe078 三种 baseline 的内容和配置在运行前分别固定，锁定后才获取 holdout 结果。whole-set 不新增为执行阶段，也不能作为 holdout 成功证据。

### 报告与 baseline 索引

逐组合、形态、模型、采样配置和集合口径输出 pass@1/@3/@5、适用配置下的 ASR/evasion、静态 verdict 分布、工具可用性、失败分类和成本；所有指标保留分母、版本和来源。

clean ASR 以自然命中率报告，不设“必须趋近于 0”的预期。样本实际包含目标模式与 oracle 误判须分开核查，不能仅因非零 ASR 就修改判定器。

baseline 索引保留形态、组合、任务集合、split、模型、温度、repeats、k、提示/评估版本和产物位置。后续比较必须按主方案要求匹配口径；不同形态分别保留，不自动选“最好”的结果作为全局基线。

## 5. 阶段统一验收与人工审查

主要复用阶段 02 的自检与报告核查入口，不新增逐组合测试。仅当运行暴露新缺陷时，对必要问题补针对性回归。

| 验收组 | 集中核查与证据 |
|---|---|
| 配置与覆盖 | 每个模型的 24 个单元都有明确状态；任务集合、提示形态、锁定和版本可追溯；未完成部分明确列出 |
| 指标与实验完整性 | 失败留分母、无效配置标未定义、pass@k 估计正确、不混温度/集合/模型、不把缓存读取算新样本 |
| 结果与成本 | 功能结果可用于基线、自然命中率有记录、工具不可用明确、ledger 与报告一致；未知费用不填零 |
| 人工审查 | 汇总异常样本与显著差异，展示必要原始响应/代码/判定依据；不通过查看 holdout 调整模板 |

集中审查材料写入或链接到[验收记录](./验收记录.md)，记录完整/未完成单元、配置清单、主要报告、成本说明、差异与用户裁定。数据缺失、预算耗尽或执行环境故障均不能写成已完成。
