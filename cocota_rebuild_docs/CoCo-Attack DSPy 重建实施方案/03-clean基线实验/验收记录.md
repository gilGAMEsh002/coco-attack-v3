### 5.1 任务 205：harness 与 multiprocessing 不兼容（已确认 18/18）

- 机制：功能 harness 把「候选解 + 测试」`compile`/`exec` 进运行时构造的合成模块 `types.ModuleType("__test__")`（磁盘上不存在、不可 import）。容器 Python 3.14 默认 start method 为 **forkserver**；`pool.map(execute_command, ...)` 的 worker 反序列化任务时执行 `import __test__` → `ModuleNotFoundError` → worker 崩溃 → pool 挂起 → 外层 30s SIGTERM、无 payload → `incomplete`。
- 证据（真实容器 stderr，`units/cwe078-0__clean_0shot__t0.7r5/search/functional/run/attempts/functional-e0ba2d7d9d74-26401928/stderr.log`）：
  `ForkServerPoolWorker-1 ... _ForkingPickler.loads ... ModuleNotFoundError: No module named '__test__'`。
- 范围：**任务 205 的全部 18 个样本**（cwe078 的 6 个单元 × 3，全部命中同一错误）：17 例记 `failed`（假阴性）、1 例（0shot t0.7r5 r2）30s 超时记 `incomplete`，导致该单元 pass@k 未定义。
- 结论：这是**评测环境缺陷**，非模型逻辑错误；任何使用 `multiprocessing.Pool` 的候选（含 canonical）都会失败。205 已按阶段 01 [D02](../01-领域基座与历史校准/验收记录.md#d02) 纳入 cwe078 评测集，因此 **cwe078 全部单元的功能指标与 pass@k 目前不可用**。
- 合成 probe 说明：我用 `-c` 脚本复现 forkserver 时未失败（惰性启动的 forkserver server 会继承父进程 `sys.modules`）；真实 harness 的 stderr 才是判定依据。

### 5.2 cleaner：内联代码围栏识别缺失（已确认）

- **现象/根因**：`cwe502-0__clean_0shot__t0.7r5` 的 `BigCodeBench/273` r0 候选代码自带
  `try: httpd.serve_forever() except KeyboardInterrupt: ...`，而 harness 的 `_CandidateTimeout` 是 `KeyboardInterrupt` 子类（为让 unittest 不把它记为测试错误）→ 候选**吞掉**超时异常并返回；随后测试再次调用 `task_func()` 阻塞，而一次性定时器已耗尽 → 挂起至外层墙钟 kill → 无 payload → `incomplete`。
  （stdout 佐证：`Server running on port 8000` 出现两次 + `Shutting down server...`。）
- **修复**：harness 把候选超时 `SIGALRM` **覆盖模块 `exec`**，并用 `setitimer(..., interval=1.0)` **每秒重复触发**；`_on_alarm` 置 `alarm["fired"]`。即使候选捕获 `KeyboardInterrupt`，`exec`/套件返回后仍按 `alarm["fired"]` 归因 `candidate_timeout`，经 D04 分类器记 `failed`（c=0）。`HARNESS_VERSION → functional-harness-v5`，重建镜像 `sha256:80da3932…`（check-execution/verify-isolation 均通过）。
- **结果**（[E13](#task-01)）：`273 r0` → `failed`（`candidate_timeout`）；`cwe502-0__clean_0shot__t0.7r5` 的 `unresolved=[]`、pass@1=0.24、pass@5 有定义；**全基线 `passed=None` = 0**（functional 全部 `passed 488 / failed 1474`）。
- **范围**：只影响“捕获 `KeyboardInterrupt` 的阻塞候选”；普通模块级阻塞与普通测试超时同样受益。无新增 victim 请求。
