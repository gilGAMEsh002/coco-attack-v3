# 02 · 模板快照与投毒物化（I1）

依据：[基础设施 I1](./迭代基础设施实施安排.plan.md)、[方法设计 §3/§6](../method/single_candidate_ab/迭代方法设计.md)、[方法实施安排](../method/single_candidate_ab/迭代方法实施安排.plan.md)、阶段 04 D02–D04。前置 I3 直接代码检查已实现，见[E04](../验收记录.md#e04)。本项已交付，实施证据见 [E06](../验收记录.md#e06)，下一项见 [03 单候选训练闭环](./03-单候选训练生成与评估闭环.plan.md)。

## 1. 目标与交付边界

将 clean fewshot 来源转成可追溯的投毒模板快照，支持显式字段补丁与确定性提示物化，使后续生成服务能直接读取，同时使快照中的示例 code 能交给现有 `ExampleCheckRequest / run_example_code_check`。

本次交付：模板快照/读取接口、稀疏补丁与实际差分、投毒物化器、一个离线使用入口及必要检查。只生成当前配置指定的两题提示，不调用真实模型，不跑训练生成、不实现 A/B 循环和三项门组合，不物化 25 题。训练生成/评估闭环留给下一任务。

当前配置用 cwe078-0、四示例、示例 1 冻结、示例 2–4 注入 cf。通用接口接受显式模板/任务清单/攻击配置/允许字段；这些研究参数由调用配置提供，不写成通用服务默认算法。

## 2. 快照、身份与存储

- 一个快照包含四示例的顺序、task_id、instruct_prompt、code、cot、投毒元数据、提示形态及协议版本，并保留原始来源指纹。cot 沿用素材实际结构（现有 fewshot.json 中为字符串；原计划误写为字符串列表，已按 E06/E07 更正），不能不声明协议变化就改成不同类型。
- 快照内容不可变；修改产生新内容版本，调用方持有唯一 current 引用。前一版本、动作、实际差分、创建时间和磁盘位置是旁路审计信息，不形成搜索候选池。
- 模板内容指纹覆盖实际 fewshot、attack_config 和渲染协议。保留既有 `compute_candidate_hash` 作为指定任务提示集合下的生成身份；模板指纹与生成采样身份是两个用途，不强行共用同一个 hash。
- `compute_candidate_hash` 已包含 `meta_sha256/fewshot_sha256/prompt_hashes`。必须使用投毒后的真实文件计算，不使用 `PromptExperiment.content_sha256()` 替代；也不为新物化器改变旧生成身份公式。
- 同内容、同配置、同任务集跨输出目录物化应得到相同内容身份。候选 meta 中不要混入运行目录、时间戳、随机 nonce 或父代链；这些放旁路记录，避免内容没变但身份漂移。已有输入来源用规范相对引用和哈希记录。
- 完整写出文件和哈希清单后才发布 `completion=complete`；读取核对必要文件和内容指纹。不能覆盖已存在但内容不同的快照，不能把半写目录当成可用产物。同版本恢复即可，不建旧格式迁移。

建议在 `iteration/` 新增小型模板/快照服务，在 `prompts/` 或 `iteration/` 新增投毒物化器；只做必要代码组织，文件名不是验收要求。已有 clean 物化和 baseline 服务继续保持其 clean 语义。

## 3. 字段补丁及当前方法约束

补丁一次可替换多个示例的 code 或 cot；未列字段原样继承，应用前整体校验，错误补丁不产生部分更新。明确接口序号约定，区分模型展示的“示例 1–4”和任务 01 loader 的零基 index。

调用方提供允许的示例与字段集合：A 配置只允许示例 2–4 的 code，B 配置只允许这三个示例的 cot；一次 B 补丁可包含三个 cot。公共层负责按给定范围校验，方法层负责何时使用 A/B 配置。

检查拒绝冻结字段、task_id/顺序/测试的修改、未知示例/字段、值类型错误和重复冲突项。记录真实 before/after 差分，不能直接相信模型声称改了什么。空补丁可表示内容未变，但不产生虚假的新内容版本或“门已通过”状态。

快照读写保留 code/cot/instruct_prompt 字符串字节；JSON 的规范序列化不应改变它们的内容。示例 1 的内容与实际提示区块保持原样，不注入 cf。

## 4. 投毒物化与生成入口接线

输入是模板快照、明确的 attack_config、两题任务清单与数据来源。输出沿用生成入口需要的目录关系：

```text
<output>/manifest.json
<output>/<combination>/<form>/fewshot.json
<output>/<combination>/<form>/meta.json
<output>/<combination>/<form>/test_prompts/<对应任务文件>.md
```

模板谱系/动作审计可放同目录旁路文件，不进入实际 victim 提示文本。

具体要求：

1. `attack_config.enabled=true`，trigger/injection_position/poison_parts/mode 与实际物化一致；fewshot 的 is_poisoned/trigger/poison_parts 记录真实情况。按原 F2 区分触发器注入与 code/cot 字段修改，不能因“快照来自 clean”就继续写 enabled=false，也不能把未发生的字段修改写成既有事实。
2. 复用 `prompts/trigger.py` 的剥除/注入规则；只在配置指定的 instruction 上注入，示例 1 不注入，示例 2–4 和两题测试 instruction 注入。不要对整份拼接后的 Markdown 执行一次全局注入，误改示例或代码。
3. 延续现有 fewshot-CoT 提示结构，按示例/测试区块渲染实际内容。fewshot.json 改了还必须反映到 test_prompts；不能直接复制旧完整提示而忽略新 code/cot。代码中的大括号、f-string、换行与缩进按内容保留，不用 `str.format` 解释整份提示。
4. 明确使用新的投毒形态/提示协议标识并记录来源；不为方便复用而伪称 clean 形态。若现有生成配置校验不接受新形态，只做必要注册/参数适配，不放宽 clean baseline 的断言。
5. 不调用 `materialize_clean` 生成投毒配置，不经 `experiments/baseline.py` 准备候选。注册表、prepared data 和阶段 03 索引保持只读；两题属于既有 search 集，可通过显式 `task_ids` 子集接线，不改 search/evaluation 集合。
6. manifest 填齐现有生成加载器所需的 combination、form、prompt_version、meta 和逐任务提示哈希，并补快照读取必要的 fewshot 指纹。物化器对每个输出提示要求有有效声明哈希，不依赖下游“缺值也可加载”的宽松分支。
7. 实际调用 `load_generation_inputs(..., stage='search', task_ids=['BigCodeBench/13','BigCodeBench/1105'], repeats=5, ...)` 验证可读且得到 10 个采样身份；这是离线输入校验，不会调用 LM。不物化、不采样其余任务。

触发器的重复物化从相同快照与规范配置出发，结果必须稳定。提示格式若确需变化，记录具体差分与新协议版本，不隐式改变 baseline 对照形态。

## 5. 接任务 01 的真实接口

从**当前快照**取 task_id 和 code，构造 `ExampleCheckRequest(code_input_mode='example_body', ...)`；code_source/action_id 能追溯到当前模板版本及这次检查。不要误调用 clean loader 后把旧 clean code 送去验证，尤其要覆盖 code 已变的情况。

核对检查结果中的 input_code/final_code 指纹与预期快照和重组结果一致。I1 可以保存结果引用，但不将静态事实组合成 A 门，也不以旧代码检查结果给新代码背书。I3 当前每次显式调用均实际重跑，没有功能缓存，不因 cot 未变/变了就擅自宣称缓存命中。

本项默认用 spy/mock 服务验证传入的是快照字节即可；必要时另做少量真实调用。若实际运行 Semgrep，可在本次配置中显式采用 E04 已验证的 180 秒超时并记录，不因此悄悄修改通用默认值。

## 6. 最小检查与交付

| 场景 | 可判断的结果 |
| --- | --- |
| 初始化与冻结 | c0 保留四示例的 code/cot，按配置注入 instruction；示例 1 内容与提示区块不变，来源资产未修改 |
| 补丁原子性 | 单/多字段修改与实际 diff 一致；一次改三个 cot 可用；冻结/越界/类型错误整体拒绝，不污染父快照 |
| 渲染真实性 | 更新 code/cot 后，fewshot 和两份实际提示对应区块都更新；代码中的括号、字符串、缩进不损坏 |
| 身份稳定性 | 相同内容跨目录身份一致；code/cot/attack_config 或协议改变时相应身份改变；父代/动作时间不混入内容身份；空补丁不伪造新内容 |
| 读取完整性 | 缺失/篡改 fewshot/meta/提示/manifest 或半写产物被拒绝；原快照可读不被覆盖 |
| 生成输入接线 | 真正的 `load_generation_inputs` 读取两题 × 5 repeats，共 10 个身份；提示 hash 与实际字节一致；无其他任务提示 |
| 检查输入接线 | 修改后的示例 code 被传给 `ExampleCheckRequest`，不是重新加载的 clean code；结果引用与代码指纹对应 |
| 已有路径回归 | clean 物化和生成输入相关既有测试仍通过，baseline clean 断言未被取消；只运行直接受影响的检查 |

新增测试应覆盖真实边界，不用只验证自写 hash 等于自身的镜像测试。代码、可复现 CLI/脚本示例、固定输入产物与实际测试命令统一交付，证据追加到[阶段过程记录](../验收记录.md)，状态同步阶段概述。

后续任务用本项产物接单候选训练生成/评估，再补多轮模型与动作恢复；本项完成不代表这些能力已实现。Semgrep adapter 语义版本及历史比较的收尾事项见[E05](../验收记录.md#e05)，不阻塞 I1 独立开发。
