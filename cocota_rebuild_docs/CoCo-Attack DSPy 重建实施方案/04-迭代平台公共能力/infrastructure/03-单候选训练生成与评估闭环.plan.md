## 1. 本次交付

接收一个模板快照及显式运行配置，完成：投毒物化 → victim 生成 → 清洗 → 静态 oracle → Semgrep → 训练反馈与历史 clean 基线切片。提供可调用服务及 CLI/脚本入口，先用 mock 跑通，无须真实模型密钥。

当前接线配置为 cwe078-0、poisoned_fewshot_cot、search 中的 BigCodeBench/13 与 BigCodeBench/1105、温度 0.7、每题 5 repeats。这些由调用方显式传入，不成为通用服务的固定任务集或默认研究参数。每次请求处理一个明确候选，不建立候选池、排名或自动选择。

本项评估 victim 输出的静态 ASR 与 Semgrep evasion。训练功能测试、judge、dynamic、其他 SAST 工具不在本次接线范围；未执行的指标明确记为未评估，不能填零。示例检查仍是任务 01 的独立入口；A 门组合、mutator、B 一次机会、多轮方法恢复及 25 题测试留给后续任务。不自动开启真实模型实验。

## 2. 输入、身份与既有入口

输入包含快照引用、prepared data/只读资产来源、任务清单、组合与 form、stage、模型及 source、温度/repeats、单次输出上限、运行目录和可选 baseline 引用。沿用现有生成请求的超时、并发与重试配置，不扩展总预算系统。

| 环节 | 复用入口与注意事项 |
| --- | --- |
| 模板与物化 | `iteration/template_snapshot.py`、`poison_materialize.py:materialize_poisoned/verify_poisoned_inputs`；真实物化后经 `load_generation_inputs` 获取候选身份，不能用模板 hash 冒充生成 candidate_hash |
| victim 生成 | `generation/service.py:run_generate/run_resume_generation`；使用已支持的投毒 form，复用请求审计、失败记录、ledger 和重试语义 |
| 清洗 | `evaluation/run_cleaning.py:clean_generations`；读取真实 generation 记录，保留失败样本，不自行替换解析器或代码前缀拼接 |
| 静态训练评估 | `evaluation/run_static.py:evaluate_static`；明确配置 `task_set=search`、两题 `task_ids` 与 repeats，避免展开整个 search 矩阵。这里评估 cleaned generations，不是任务 01 的示例直接检查 |
| Semgrep 训练评估 | `evaluation/run_other.py:run_evaluate_other`；同时传 generation_run 和 cleaned_dir，显式仅启用 `enabled_layers=(sast,)`、`sast_tools=(semgrep,)`，并提供按样本身份关联的完整 static_hits |
| 指标与反馈 | 复用 `evaluation/metrics.py` 与可用的报告函数；薄层汇总所需事实，不改指标定义，也不为了复用完整 pipeline 顺带运行 functional/judge/dynamic |

batch_id、candidate_hash、stage、model、task_id、repeat 等关联字段沿用公共身份；读取/合并时校验来源完整一致，不能只用 task_id 拼接不同候选或批次。物化、生成和两种评估均限定相同两题 × 5 repeats；缺失、重复、额外样本必须可见，不能通过静默删行得到完整结果。

沿用当前 DSPy 缓存初始化约束：每个生成进程配置一次。若闭环由一个长期进程多次调用，生成步骤可复用现有 CLI 的独立进程，避免在同进程反复切换候选运行目录的缓存配置；不为此建设 worker pool。source 与 search/holdout 的隔离继续有效。

## 3. 运行产物与最小恢复

在显式新目录中保存输入快照引用和配置、物化包、generation 原始响应/审计/ledger、cleaned、static、Semgrep 原始结果及汇总、feedback/report。目录名可沿用现有约定；总 manifest 记录各步骤状态、输入指纹和产物引用，全部完成后再写完成状态。

仅支持同版本、同输入的单次闭环恢复：生成复用已有恢复入口，已落盘完整步骤不重复执行；中断步骤恢复或明确重跑，不能把半写目录当完成。输入或配置变更须拒绝复用旧完成状态。保留真实重试/重跑记录，不重复计费，也不把未知中断消耗写成零。本项不建立跨候选静态/SAST 结果缓存，不承担 A/B 动作恢复。

报告同时给出：

- 模板/候选/运行身份及逐样本证据引用；原始响应与清洗后实际评估代码分开保存。
- 当前两题的 sample hit rate、ASR@1、ASR@5、Semgrep evasion 及分子/分母；沿用既有无静态命中时的 undefined 语义。
- generation/parse 失败、缺失、unavailable、error、incomplete 的数量与原因。扫描未完成不能解释为未检出，不改变现有分母与指标计算规则。
- 供后续方法消费的精简反馈：按“训练题 1/2 + repeat”展示输出代码、判定与扫描事实。真实任务 ID/hash/平台路径留在审计侧；代码本身的标识符、路径及测试字节不改写。完整 mutator prompt 与四示例测试/规则素材组装留给下一项。

## 4. clean 基线切片与 Semgrep 收尾

从阶段 03 已有 clean fewshot-cot 同配置结果只读提取两题逐样本记录，再按既有函数计算基线；不要把整个 search 集汇总与当前两题比较。保留来源 manifest、版本、任务集、模型、温度/repeats/k 与结果引用。不经 `experiments/baseline.py` 准备投毒候选，也不重新运行阶段 03 基线。

比较沿用主方案 H 的一致性检查：模型、任务集合、采样配置等不匹配时不给可比差值；环境/评估版本差异须展示警告与来源。mock 产物明确标为接线数据，不能与真实 victim baseline 计算研究结论；可用配套 mock fixture 验证差值逻辑，真实基线切片单独验证。不得因 mock 配置写了真实模型名就把它视为真实采样。

落实 [E05](../验收记录.md#e05) 的比较收尾：

1. 对新示例检查和训练 Semgrep 记录统一附带可追溯的 adapter 语义版本或源码指纹，连同工具/规则来源进入产物。Semgrep 二进制版本不能替代 adapter 标识，不改写历史记录。
2. 只读核对历史 baseline 是否保留原始扫描报告，区分“可重核原始 errors”与“原始证据缺失”。仅有 completed 记录不足以排除旧 adapter 丢弃 errors；无法确认时明确历史影响未知，不宣称数值未变。
3. 新旧 `errors → incomplete` 解释差异进入比较提示；不要求为此全量重评，也不主动调用模型。如新路径需要扫描超时配置，最小化透传并记录实际值；180 秒可作为本次运行显式配置，不静默改变通用默认值。

**R2：矩阵相同不等于同一份运行证据。** `_generation_complete` 检查 sample_id 唯一但未与真实输入计算的预期 sample_id 集相等校验；`_completed_run_data_ok` 不核对 generation run_config 身份，cleaning/static 只按 task/repeat 接线；feedback/audit/baseline 仅检查存在。临时副本中将 generation 第一行的 `identity.candidate_hash` 改成另一值、sample_id 改成另一字符串后，真实 `run_training_loop` 仍返回 complete；随后把 feedback.json 写成非法 JSON，仍返回 complete。

- 完成快速返回和逐步恢复使用一致的核验：生成行的 sample_id/完整 identity 与 `load_generation_inputs` 所得预期身份一致，并与生成 run_config/config hash 对应；不能只比较当前 prompts 与总 manifest。
- 复用现有 cleaning manifest 的输入/输出指纹、static manifest 的 evaluations 指纹及其他已有依赖信息，将实际代码/结果字节与上游绑定。补足缺少的最小指纹即可，不建立全层缓存。上游输入发生变化，依赖它的下游须失效或拒绝复用。
