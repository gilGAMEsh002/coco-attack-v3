# 01 · 示例代码检查服务

依据：[基础设施 I3](迭代基础设施实施安排.plan.md)、[方法设计 §5](../../method/single_candidate_ab/迭代方法设计.md)、[阶段 04 D02–D04](../../验收记录.md)。目标追溯：用户要求 A 示例硬门及基础设施独立建设 → 主方案 B/D/F/G/I → 公共代码检查服务。此处只细化必要检查，不增加新的研究目标或平台验收门。

## 1. 本次交付与范围

实现一个不依赖研究方法循环的直接代码检查入口，接收示例任务与代码，分别返回功能测试、静态 oracle、Semgrep 事实及来源。随后方法层才能据此组合 A 的三项门。

优先在 `coco_attack/src/coco_attack/iteration/` 新增小服务；如需提取现有功能执行公共入口或补齐 Semgrep 证据，最小修改 `evaluation/`。可以补一个薄 CLI/脚本入口与 README 使用示例，不要求两套入口都做。具体模块/类名由实施者按代码决定。

本次不开发候选物化、victim 生成、mutator、A/B 循环、锁定、测试集评估；不依赖这些尚未实现的服务。功能缓存复用现有能力，接入尚不方便时明确本入口本次实际重跑，不另建简化缓存或错误命中路径。

## 2. 输入与输出

输入必须明确：组合/oracle 归属、真实示例 task_id、code_prompt、入口、测试、示例 code、来源与内容指纹、实验阶段、执行资源配置、规则来源、动作身份及输出目录。任务与规则应从已有可信资产/注册表加载，不从输出目录名猜归属。

当前 fewshot code 为函数体，入口按 `code_prompt + code` 重组；保留源码字节与重组方式，不重复拼接完整函数。若提供任意 final_code 接口，须明确输入模式，不靠模糊猜测切换两种解释。组合不匹配、缺测试/入口/必要身份时明确报输入错误。

返回至少包含：

- 检查对象来源（示例）、代码/测试/规则指纹及工具/执行版本；审计身份与结果可关联，不伪造 victim 生成样本。
- 语法/入口检查和静态 `verdict/target_present`，保留原 oracle 归属与必要证据。
- 功能结果及完成状态、失败分类、容器执行来源和耗时；沿用现有分类器，环境不可用不算功能失败或通过。
- Semgrep 的 available/completed/detected、目标规则、起止行列等证据、错误或不可用原因；未完成不能表示成正常的 `detected=false`。
- 各层执行/跳过状态及原因、结果文件位置和 local_test 消耗事实；不伪造 token 或金额。

公共结果不包含“允许进入 B”或默认攻击成功结论。通用 CLI 的正常退出可表示服务成功产出结构化结果，不等于三个研究条件全部满足。

## 3. 复用与接线

| 工作 | 现有入口 | 实施注意 |
| --- | --- | --- |
| 数据与归属 | `data/combination.py`、数据加载/快照、现有 fewshot 资产 | 从注册表定位来源；本次只处理示例，不能为适配 CLI 把示例加入 evaluation_ids/search_ids |
| 静态判定 | `evaluation/static.py:load_oracle_module` + `evaluate_static_sample` | 直接输入重组后的代码，复用现有 oracle；不经过面向 cleaned generations 矩阵的 `run_static` |
| Semgrep | `evaluation/sast.py:scan_sample`、`semgrep_target_rules` | 适配所需样本上下文；只启用明确请求的 Semgrep，不用 `run_other` 伪装任意代码输入。补保留原始结果中的位置与扫描错误信息 |
| 功能测试 | `evaluation/run_functional.py` 的执行部分、`execution/supervisor.py`、Docker backend、现有 harness/classifier | 高层 `_build_inputs` 限制评测任务，不能直接传示例 task_ids；提取小公共执行入口或封装底层服务，保持旧调用方语义 |
| 持久化与消耗 | 原子写入工具、现有 ledger/local_test 记录模式 | 执行前保存请求/输入来源，执行后保存完整事实；不给同一次底层执行重复记账，不先建设通用动作状态机 |

现有底层执行/SAST 类型可能需要完整的 sample identity。允许适配真实示例身份并标明其来源；不能冒充 victim 请求或把 A/B 填入实验 stage。固定检查批次与代码/任务指纹要可追溯，字段设计尽量复用已有契约。

功能代码执行只经已验收的 Docker 路径；静态扫描不得 import/exec 候选。现有镜像、资源限制、harness、分类器从当前配置与记录读取，记录实际使用值，不沿旧文档硬抄版本字符串。

## 4. 实施顺序

1. 核对工作区和现有 Python 环境、评测配置及镜像证据。应用包要求 Python 3.14，优先复用已有环境，不照旧 README 重新初始化项目。先检查 Docker/工具可用性及既有执行隔离前置；若执行路径改变，重查受影响的隔离条件。
2. 定义小输入/结果对象和直接静态/Semgrep 适配；接已有 functional 执行与分类，结果落盘。不要改 oracle 本体、原始测试或示例来适配服务。
3. 使用少量固定输入和模拟后端验证接线/错误语义，再对现有 clean 示例 2–4（348、322、810）执行当前环境下的真实功能检查与静态扫描。示例 1 保持只读；本项不需要 victim 调用或 train/test 全集。
4. 记录 348 替代实现的实际来源与结果。clean 示例可以 oracle 不命中或被 Semgrep 检出，这不是基础设施失败；它们只用于确认服务如实返回结果与功能兼容。不能把 clean 示例未满足攻击条件改写成服务异常。
5. 给出一个可复现调用入口，产物写显式指定的新目录；记录完成项、限制与下一项所需的接口。

如果某个 clean 示例功能不过，保留原代码、完整结果与环境信息，整体报告差异；继续完成不依赖该差异的接线和检查，不降低 strict pass，不修改历史结论。Docker 不可用时仍可完成静态服务和 mock 检查，但真实功能验证必须标为未完成。

## 5. 必要检查

沿用 `tests/test_static.py`、`tests/test_evaluators.py`、`tests/test_functional_pipeline.py` 及相关执行/分类器测试中的样例和模拟后端，只补实际接口新增的关键场景：

| 场景 | 应看到的结果 |
| --- | --- |
| 示例身份接线 | 排除在评测集合之外的真实示例仍可直接检查；不改 evaluation_ids；三层结果关联同一份代码 |
| 错归属/缺输入/语法错误 | 错归属或缺必要输入明确失败；语法错误如实报告，不能当目标 absent 或功能通过 |
| 工具扫描状态 | 正常检出/未检出可区分；工具缺失、超时、目标文件未完成扫描或结构化错误不制造逃逸；命中证据对应实际扫描代码行 |
| 功能结果 | 通过、候选错误/超时、环境不可用分别沿既有分类输出；部分失败不丢掉已经可靠落盘的其他层事实 |
| 独立性与审计 | 不加载方法模块或模型密钥即可调用；代码/规则/任务来源可追溯；每次真实执行正确记录一次消耗 |
| 现有调用方回归 | 若提取共享执行器或修改 SAST adapter，运行直接受影响的既有测试，确认生成样本评估语义未改变 |

测试命令使用实际可用环境，所选 pytest 文件/标记与执行结果写入过程记录；本计划不把尚未存在的 CLI 名称、固定成功计数或未执行命令写成证据。

## 6. 交付给下一项

交付代码检查 API、命令/脚本示例、必要测试结果、示例 2–4 的实际结果或环境阻塞说明。后续模板物化服务只需提交模板版本对应的示例代码即可调用，不要求先伪造 generations.jsonl 或完整候选管理框架。

执行证据统一写[阶段过程记录](../../验收记录.md)，状态同步[阶段概述](../../阶段概述.md#current-status)。本项完成表示服务可用及验证范围明确，不表示 A 方法有效或阶段 04 已人工验收通过。
