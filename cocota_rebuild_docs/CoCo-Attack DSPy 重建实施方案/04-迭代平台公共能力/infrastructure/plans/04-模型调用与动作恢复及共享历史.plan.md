## 1. 本次目标与范围

交付一个可供方法调用的多轮 messages 服务、一套最小动作持久化/恢复接口，以及确定性的反馈投影与历史装配。用 mock 串起“持久化请求 → 返回原始响应 → 解析稀疏补丁 → 应用模板 → 接收反馈 → 下一次请求”，并验证中断后继续同一动作。

本项不实现 A/B 调度、门组合、五轮循环或真实模型实验。调用方给出角色、允许字段、下一动作和方法状态；公共服务保存并执行，不解释阶段含义。允许纯文本推理动作不生成补丁或候选。单个进程/运行目录的顺序执行即可，不引入队列平台、worker pool、数据库、通用插件注册或旧版本迁移。

## 2. 复用与接口边界

| 已有入口 | 本项如何复用 |
| --- | --- |
| `generation/source.py:DspyLMSource.generate/MockSource/extract_response/is_retryable` | 已支持 messages、rollout_id 与同步 LM.forward；抽取必要的共用调用配置或加薄适配，避免给 mutator 伪造 victim task_id/组合/样本。既有 victim 行为保持 |
| `generation/runner.py`、`runtime/ledger.py` | 复用“尝试开始→响应及用量落盘→导出”的顺序、单写者和断尾恢复；普通动作建立独立身份，不能冒充 victim sample 来迁就现有投影函数 |
| `runtime/limits.py`、`runtime/cache.py`、现有生成锁 | 沿用限速/单层重试、进程缓存配置与运行排他；首次和恢复使用相同进程边界，不在长期方法进程中反复切缓存目录 |
| `iteration/template_snapshot.py` | 应用补丁用 `apply_patch` + 调用方 `PatchPolicy`，持久化真实 diff；原始 cot 是字符串，示例展示序号与内部索引明确转换 |
| `iteration/code_check.py`、`iteration/training_loop.py` | 消费其原始事实和输出引用，构建反馈投影。方法完整输入需要的 available/completed/扫描行证据若现有精简 feedback 未带齐，从原记录读取，不从 detected=false 猜测 |

接口名称由实施 agent 决定，建议放在 `iteration/` 的少量模块中。至少接受：action_id、角色、messages、模型/source、温度/单次输出上限/超时/既有重试配置、提示协议版本、输入引用、输出位置。返回原始响应引用、状态、用量/成本事实及可选解析结果；方法可以决定下一动作而无需访问执行器内部状态。

真实 backend 沿用 DMX 和既有密钥加载方式；本轮仅 mock，接口可为真实 backend 留好接线，不加载密钥。mock 应走同一调用/审计边界，使用固定响应 fixture，并清楚标记来源。

## 3. 动作与响应的持久化顺序

1. 调用方先给稳定 action_id 和输入。保存请求计划：实际 messages、模型/采样/输出配置、协议与素材版本、输入模板/反馈引用、方法状态引用及内容指纹，然后才开始执行。同 action_id 不同输入拒绝复用，不覆盖旧件。
2. 每次真实尝试记录独立 attempt 身份和开始事件。响应一旦返回，先持久化原始文本、finish_reason、response_id、usage、缓存来源及成本事实，再解析/应用/投影。角色费用引用底层请求事实，不在动作层重复累计。
3. 补丁解析只是后处理：合法结果交 `apply_patch`；未知字段、类型错误、越界或无效 JSON 保存为解析失败。不得在基础设施里偷偷请求第二份修复决策；是否再请求由方法决定。普通推理结果允许直接是文本。
4. 模板新版本/实际 diff 与动作结果先落盘，再提交“当前模板+共享历史+方法状态”引用。跨文件操作不假定原子；用动作完成记录作为提交点，恢复只完成缺失后处理，历史追加及当前指针更新幂等。
5. 已有持久化响应时恢复不再请求模型；已有合法完成结果时校验身份、依赖和实际产物再返回。仅有 attempt_started、无持久化响应的中断窗口标为结果/费用未知；按显式既有重试策略继续或暂停，并保留旧尝试，不能宣称服务端请求绝对只执行一次。

优先用一个小型动作清单、追加日志和原子状态文件即可。动作状态名称不作强制要求，但必须分清“计划已保存、请求可能已发送、响应已保存、后处理完成”。仅支持同版本恢复；损坏的派生文件可从可信响应重建，损坏/错配的原始证据应拒绝继续或明确暂停，不能换旧候选蒙混。

沿用当前成本范围：真实尝试、重试和失败可追踪；未知费用不填零，mock 不伪装真实费用，缓存命中不重复计费。只配置单次输出上限及已有执行限制，不新增累计预算/额度系统。

## 4. 反馈与模型可见输入

投影采用字段白名单与显式展示标签，原始结果保留在审计侧。使用“示例 1–4”“训练题 1/2”等标签；task_id、sample_id、hash、运行目录等审计字段不进入 messages。不要在代码、测试、规则文本或模型原始响应上做全局正则替换；程序自身标识符和路径保持原样。

最小投影应携带方法设计 §8.1 所需事实：示例功能 outcome/失败原因、oracle verdict、Semgrep available/completed/detected 及行列证据、训练样本 repeat/实际输出代码/判定、指标分子分母及 undefined 原因。响应原文和清洗后评估代码明确区分；未执行层写未评估，未知或错误状态不能转成成功。mock 的基线差值不可作为真实结论。

支持装配固定素材和当前模板全文：四示例 test、code_prompt 与入口，目标 Semgrep 规则源文本，以及调用方提供的任务/约束/先验/输出格式。素材版本和内容指纹进入实际请求身份；只接给定 search/示例素材，不加载 25 题测试反馈。研究性先验和具体 A/B 请求文本由后续方法层提供，本项用固定 fixture 验证装配完整性，不新增攻击策略。

## 5. 共享历史与上下文长度

一个逻辑历史按已提交动作顺序保存，每次请求实际使用的 messages 单独落盘。调用方给 system 固定块、当前模板全文、历史事件/摘要事实及上下文配置。公共层按确定性策略装配，恢复使用已保存的实际请求，不能重新摘要后发出不同请求。

- 固定保留 system 的任务/约束/先验/四示例测试/规则/输出格式和当前模板全文，按模型上下文窗口预留本次输出空间。
- 未超限时保留完整历史；超限才将最早的完整交互单元压成每单元一行事实摘要，近期交互保持原文。摘要仅由已存字段确定性生成，不额外调用模型，也不按“固定保留 N 轮”替代 token 计量。
- 请求前对完整 messages 计量，包含角色/消息开销并记录 tokenizer/估计方式；优先复用本地可用的模型计数能力。估算与 provider 实际 usage 分开记录，不能把 `字符数/4` 称为精确测量。不可得的模型计数需明确降级方式与余量。
- 固定块本身超过可用上下文时返回明确不可装配状态，由调用方调整；不能悄悄裁掉测试、规则或当前模板。摘要策略/计量器/素材变化进入请求协议身份。

这里的上下文容纳检查不是累计 token 预算；不引入总额度管理或检索记忆系统。当前方法共用一条历史，但公共服务不按 A/B 自动拆分历史。

## 6. 最小验证与交付顺序

先完成 messages 调用与原始响应落盘，再接动作后处理/恢复，最后接反馈和历史。提供一个离线示例入口，用任务 02 的快照及任务 01/03 已有事实或明确标注的 fixture，完成两次普通 mutator mock 交互；修改字段由调用方策略给定，不宣称运行了研究方法的一轮 A→B。

| 检查 | 需要证明的行为 |
| --- | --- |
| 调用与审计 | 实际 messages/模型/温度/max_tokens 传入 mock provider；每次请求有 action/attempt 来源、原始响应和费用事实；纯文本推理无需创建候选 |
| 响应后中断 | 在响应持久化后、解析/模板/历史提交前注入故障；恢复不再调用 provider，模板 diff 和历史仅提交一次，ledger 不重复累计 |
| 其他中断点 | 计划后未发送可继续；发送后无持久化响应如实 unknown；完成后产物丢失可重建派生结果，输入或原始证据错配拒绝复用 |
| 补丁合法性 | 合法稀疏补丁接现有模板接口；非法/越界补丁只返回失败且原模板不变，不自动追加修复请求 |
| 输入投影 | 四示例测试/前缀/入口、规则源文本和当前模板齐全；审计字段不进入 messages，程序自身路径/标识符字节不变；扫描未完成与未检出分开 |
| 历史长度 | 足量上下文不压缩；不足时确定性压缩旧交互、保留固定块与近期完整交互；固定块超限明确失败；恢复消息与原请求一致 |
| 现有接口回归 | 只运行受影响的生成/账本/模板/反馈测试；如改动公共模块，按仓库约定完成相关回归。mock 与真实证据分列 |

交付源码、配置示例、CLI/脚本入口、少量必要故障测试及可复现产物；README 说明恢复边界。执行证据追加到[阶段记录](../../验收记录.md)，同步[当前状态](../../阶段概述.md#current-status)。无真实模型调用、无 25 题测试、无 Git 自动提交。

本项完成后再写任务 05 的方法接入短计划：初始功能检查、A 三项门和失败重试、一次性 B、单候选/共享历史及大迭代状态。方法级 B 机会约束由任务 05 验证，本项只提供“不重复消费已保存响应”的基础能力。
