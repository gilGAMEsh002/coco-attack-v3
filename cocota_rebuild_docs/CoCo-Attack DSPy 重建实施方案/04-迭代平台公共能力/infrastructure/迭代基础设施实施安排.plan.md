# 阶段 04 · 迭代基础设施独立实施安排

> 依据：[用户决定 D04](../验收记录.md#d04)、[主方案公共契约](../../CoCo-Attack%20DSPy%20重建实施方案.md#shared-contracts)。与[具体方法实施安排](../method/single_candidate_ab/迭代方法实施安排.plan.md)分开维护。本文件是需求分析与独立建设计划，尚不代表代码已实现；进度见[阶段当前状态](../阶段概述.md#current-status)。

## 1. 建设边界

独立建设一组可被不同迭代方法调用的本地服务，复用阶段 01–03 的数据、生成、评估、Docker、缓存和指标实现。方法交出明确的输入与动作，基础设施执行并返回事实；方法决定下一步做什么。

“独立”指职责、代码依赖和检查可分开，不要求另建仓库、常驻服务、网络 API 或插件注册框架。建议在 `coco_attack/src/coco_attack/iteration/` 放少量组合服务，方法放在独立 `methods/` 模块；文件布局是工程建议，可按实现调整。已有领域模块仍保留原位置，不先做全库搬迁。

依赖方向：`具体方法 → 迭代服务 → 现有领域模块`。基础设施不导入具体方法，不把 A/B、单候选、5 轮、训练两题或三项硬门写成公共接口的默认值。

缓存、执行隔离和消耗审计横跨上述服务，复用已有公共实现。当前只提供功能测试结果缓存，其他评估器不增加缓存实现；DSPy 响应缓存继续保留。恢复已完成动作不等同于跨动作复用整份评估结果。

## 3. 必须保留的方法边界

以下规则留在当前方法配置或流程中，基础设施只提供执行它们所需的能力：

- 唯一当前候选、示例 1 冻结、只改示例 2–4；A 改 code，B 每大迭代一次 cot 修改，可同时改三个示例。
- A 的功能通过、oracle 命中与 Semgrep 不命中三项硬门；A 未过门不得进入 B；通过后才生成训练样本。
- 四示例测试用例/前缀/入口、Semgrep 规则源文本及概括先验必须进入当前方法输入；单一共享历史和当前模板固定保留。
- cwe078-0、触发器 cf、两题 train / 25 题 test、temperature=0.7、repeats=5、5 个大迭代一批、当前不跑测试或锁定。
- 训练 ASR/evasion 用于反馈；示例门通过不能直接推出 victim 输出逃逸或攻击有效。

基础设施接受显式配置，但配置能力不意味着本期必须实现所有历史算法。Origin 的候选分数、GEPA 的前沿/选父、staged-reflect 的固定阶段和修复循环都不是基础设施流程。

`search/holdout` 是既有实验执行阶段；A/B 是方法内部步骤。不得把 A/B 加到公共 `Stage` 枚举中。示例代码与 victim 输出应在检查对象的来源字段区分，不靠伪造 task_id 或新增实验阶段区别。

路径相对 `coco_attack/src/coco_attack/`。

| 服务 | 复用位置 | 要补的边界 |
| --- | --- | --- |
| I1 | `data/`、`prompts/trigger.py`、`generation/inputs.py` | 新投毒物化器必须写 prompt manifest；身份覆盖投毒后的 meta/fewshot 与实际提示内容。不能调用 clean 物化器生成投毒配置，也不能经 `experiments/baseline.py` 的 clean 准备断言 |

| I3 直接代码检查 | `evaluation/static.py:load_oracle_module/evaluate_static_sample`、`evaluation/sast.py:scan_sample`、Docker supervisor/harness | 静态入口直接处理重组代码；SAST 包一层显式样本上下文；功能执行接显式代码/测试，不把示例加入 evaluation_ids 来迁就高层 CLI |
| I3 生成样本评估 | `generation/service.py`、清洗入口、`evaluation/run_static.py`、`evaluation/run_other.py` | 保留 generation → cleaned → static/其他层的真实输入关系；`run_other` 需要 generation+cleaned 输入，不能当任意代码扫描器使用。显式选择层/工具，避免默认启动全部层 |
| I4 | 原子写入工具、`runtime/ledger.py`、已有 resume 流程 | 增加方法动作清单及状态快照。动作完成记录引用底层请求账本，消费记录从实际调用汇总一次，不在上下两层各累计一遍费用 |
| I5 | 既有评估记录、请求消息和素材文件 | 新增事实投影与展示标签映射；审计 ID/hash/运行路径只在旁路，源码和测试自身的路径/标识符不改写；扩充 Semgrep 行列证据和扫描未完成状态 |
| I6 | `evaluation/metrics.py`、`experiments/index.py`、`evaluation/reporting.py` | 可离线对所选 train 任务切片；不覆盖旧索引。身份/采样错配拒绝比较；评测环境差异按主方案 H 提示，不重新引入全字段硬拒绝 |

生成 CLI 当前会激活 DSPy 进程全局缓存，不能在方法进程里为每个候选随意切换缓存。服务应复用阶段专用的生成进程/既有进程入口，每个进程一次配置；search 与 holdout 独立。具体用短进程还是常驻进程按实现便利决定，不扩成进程调度平台。

功能结果复用必须满足现有完整指纹；B 没改 code 不能单凭这一点复用缓存。提示协议、输入测试或规则内容变化进入对应请求/产物身份；真实 oracle 本体不因方法需要而改写。

## 5. 最小接口与独立验证方式

方法入口接收 `配置 + 方法状态 + 服务句柄`，不用规定复杂继承体系。服务最少允许：保存模板、物化指定任务提示、请求模型、直接检查代码、生成并评估样本、保存下一动作/完成状态、构造反馈与查询消耗。名称和结构在实现时确定，不把这些示意名称作为需求。

每个动作至少关联运行/动作身份、实验阶段、请求与结果引用、配置/版本及内容指纹；是否关联模板由动作决定，纯推理可以没有模板。模板版本和采样批次身份分别保留；不同任务集合下采样身份变化，不应丢失模板来源关系。

响应已落盘后，恢复只继续解析、评估或投影，不重新调用模型作相同决策。已发请求但响应未可靠落盘的窗口，沿用未知消耗记录；不承诺远端调用恰好一次。执行事实只追加，最终汇总可重建。

用一个小型、固定配置的离线调用脚本直接调用服务即可验证独立性：保存素材/模板 → 普通推理 mock → 直接代码检查 → victim mock 生成/评估 → 反馈/报告 → 中断恢复。脚本不包含 A/B、单候选循环或方法目标，不算第二种研究方法。必要的真实 Docker 检查仍单列，不能以 mock 冒充隔离或功能证据。

阶段 01–03 已完成。这里的“建设”是补齐迭代服务边界及缺口，不重新初始化独立包、重做资产清单、重建缓存或重跑整套历史验收。功能检查中的静态、SAST 与 Docker 调度次序是实现选择，公共层不固化当前方法的门顺序。

| 顺序 | 基础设施交付 | 可独立判断的检查 |
| --- | --- | --- |
| 1 | I1 模板快照/投毒物化、I3 两类检查入口、I6 基线与指标复用 | 改投毒内容改变身份；示例直接检查不用评测矩阵；victim 结果经生成/清洗链；示例结果与 victim 指标不混；无 A/B 流程也能调用 |

| 3 | 单个离线服务检查入口、使用说明及同版本恢复证据 | 固定输入断点重放得到一致事实/动作结果；无需加载具体方法；Docker/工具不可用如实输出，不当作通过 |
| 4 | 具体方法接入（由 method 计划负责） | 方法组合三项硬门、维护唯一当前候选、控制 A/B 及 B 一次机会；无需修改底层判定语义 |

沿用现有集中测试，新增检查聚焦接口接线、身份与恢复等跨模块缺陷，不为每个包装函数单独建套件。基础设施检查与具体方法行为检查分别记录，前者通过不代表方法有效。

锁定、holdout 正式验证属于通用实验协议能力，但当前方法明确暂缓：先保存运行配置与全部必要审计事实，后续单独补通用锁定执行服务及方法提供的规则。独立基础设施建设不等于本轮恢复原阶段概述的全部平台验收项。

本期不新增累计预算/费用准入、逐角色 RPM/TPM 体系、强制数据访问沙箱、全评估层缓存、旧 run 迁移、远程服务平台。单次输出限制、真实消耗审计、Docker 隔离、同版本恢复与现有缓存失效规则继续执行。
