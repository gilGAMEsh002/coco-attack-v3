## 3. 最小契约与身份

在 `contracts.py` 定义少量明确的数据类型及序列化/校验入口，字段命名可按实现调整；不要复制旧方法整套配置或预造所有后续字段。

需要表示：

- 方法 ID 及本项协议/schema 版本，与旧方法版本区分。
- 初始模板引用与固定比较基线引用两个独立字段；路径、内容哈希及来源身份可追溯。初始模板由调用方显式提供，本项不擅自决定真实运行起点。
- 当前组合 `cwe078-0`、形态 `poisoned_fewshot_cot`、四示例顺序 `562/348/322/810`、可改示例 `2/3/4`；训练题引用为 `BigCodeBench/13`、`BigCodeBench/1105`，用于后续对接，不读取或运行 25 题。
- 候选逻辑身份：run、轮次、方法阶段 A/B、固定候选序号；B 的 seed/父候选引用；模板快照路径和内容哈希另外保存。`A/B` 是方法阶段，不扩充公共 `search/holdout` 阶段枚举。
- B 修改请求：父模板内容哈希、逐示例重命名映射和可选新 CoT。每项映射标明作用域 ID、原变量名和新变量名。
- B 修改结果：候选/父模板引用、是否合法、是否实际变化、错误类别及原因、真实 diff、成功时的新快照身份。基础设施 I/O 故障与候选非法区分，后续编排才能分别暂停恢复或占用名额。

身份须确定性地构造，不能依赖并发完成顺序、临时绝对路径或随机 Python `hash()`。同一逻辑候选恢复保持身份；不同轮次/候选即使内容相同仍有不同逻辑身份，模板内容哈希可以相同。本项不实现排名、候选归并或底层 rollout/cache 键。

无实际变化时如实返回 `changed=false` 与原模板身份，不伪造新版本；本项不自行决定它是否训练、补候选或推进阶段，编排规则由后续方法接线落实。

## 5. B 重命名与 CoT 物化

### 5.1 可修改目标与请求校验

提供一个离线入口，枚举父模板中可安全支持的局部变量目标及作用域 ID，供 02 构造甲的输入。作用域 ID 对同一父快照稳定，并与父快照身份绑定；不要求模型凭空猜测任意作用域路径。

首版采用保守、明确的支持范围：至少支持普通函数体中能解析绑定关系的局部变量声明及引用。对嵌套函数/闭包、推导式、类作用域、`global/nonlocal`、动态名称访问等复杂情况，可按相关作用域或映射返回明确的“不支持”原因，无需实现通用 Python 重构器。不要把“无法分析某处重命名”扩大为禁止该 seed 做 CoT-only 修改。

名称必须是合法标识符且不是关键字；重复/冲突映射、不存在的目标、错误作用域、父哈希不匹配以及修改冻结位置均拒绝。检查新名称与局部绑定、参数及所引用外层/全局名称的冲突，避免同名引起绑定变化。多项映射按原父模板解释，不能用顺序字符串替换产生级联重命名；首版无法安全处理的交换/交叉映射可以明确拒绝并记录。

函数签名、导入名称、函数/类定义名、属性和关键字参数名冻结。实际调用的局部变量引用可随其绑定同步改名，但不能替换调用目标；代码字面量、运算符和控制流程不变。

### 5.2 程序替换与模板提交

根据作用域绑定识别要替换的标识符位置，再按源码位置修改；不能使用文本全局替换，也不能将所有 `Name` 无差别规范化后仅凭 AST 相等就认定合法。保留非目标源码文本，包括注释、字符串、格式；不要通过整段 `ast.unparse` 无意改写这些内容。涉及 AST 字节偏移与字符串/词法位置转换时，覆盖含中文或 Unicode 的源码用例。

CoT 作为允许自由修改的字符串处理，只做字段/类型与冻结示例检查，不审查其措辞、推理结构或与 seed 的语义一致性。映射为空而 CoT 有修改时是合法请求；代码无须重命名。

先验证整个候选请求，再物化全部示例修改，最后调用公共 `apply_patch` 得到新快照和实际 diff；只有合法结果才可通过 `write_snapshot` 写入调用方显式给出的新存储目录。只要其中一个映射或示例非法，就拒绝整个候选，不部分应用合法项，也不丢弃非法映射只保留 CoT。

校验结果不能调用或冒充功能测试、oracle、Semgrep 结果。模板内容身份由公共实现计算；保留示例 1、题目、触发词和其他非可改字段，公共补丁服务维护的投毒元数据沿用其既有语义。

### 5.3 对下游的最小接口

交付可从新方法包导入的入口，至少能完成以下调用链（名称由实现确定，并在交接中给出真实签名）：

```text
显式模板引用 → 读取/验证快照与基线描述
父快照 → 枚举可重命名目标及作用域
父快照 + B 请求 → 校验/物化结果（合法、非法、无变化）
合法结果 + 新快照存储目录 → 保存并可再次 read_snapshot
```

02 将用目标列表构造请求；03 将根据非法结果占名额、不训练，或在 I/O 故障时暂停。01 不建立角色请求账本、轮次状态或故障重试循环。

集中在两个新测试文件内覆盖下列实际风险，不为每个数据包装函数单独写镜像测试。

| 检查 | 预期 |
| --- | --- |
| 候选与父模板身份 | 同一输入重建结果稳定；不同轮次/候选不混淆，内容相同不导致逻辑候选归并；陈旧父哈希被拒绝 |

| 普通局部变量重命名 | 声明和引用同步修改；其他作用域同名变量、属性、字符串、注释、关键字参数和非目标源码不变 |
| 绑定与结构边界 | 新名称冲突、捕获外层名称、错误作用域、非法标识符、冻结签名/导入及不支持的复杂作用域均明确拒绝 |
| 多项映射与 Unicode | 不产生级联替换，未涉及的代码位置准确保留；含中文文本时偏移不破坏源码 |
| 自由 CoT 与冻结示例 | CoT-only 可用，即使 seed 含不支持重命名的结构；示例 1 或非允许字段的修改被拒绝 |
| 原子性与持久化 | 一个非法项使整个候选失败，原模板不变、不写半份快照；合法结果落盘后哈希可复核且重复保存沿用公共语义；no-op 保持原内容身份 |
