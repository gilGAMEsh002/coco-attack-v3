## 3. 甲的输入与输出协议

### 3.1 共用输入边界

为 A、B、乙分别定义有版本的提示和 JSON 响应协议。记录协议版本、实际 messages、输入来源及解析结果，不能只记录提示模板路径。

甲的结果反馈只能来自显式传入的、已提交的经验版本；可含经验中的指标观察与证据标签，不额外接入逐样本生成代码或原始反馈报告。甲还需要任务素材、四示例当前模板、修改范围、结构描述，以及 B 的可重命名目标。历史中混有乙原始结果时不得整体拼接。

本项以“一次提案对应一个预定候选名额”为最小入口。调用方提供 01 的 `CandidateIdentity`、父快照和固定经验版本；不由模型生成候选序号、seed 身份、路径或内容哈希。03 负责在任何本阶段训练反馈返回甲之前完成整批提案，整批甲调用均使用同一阶段入口经验版本。允许传入已提出结构的描述以减少重复，但不能夹带同阶段训练结果。

### 3.2 A：结构描述与 code 补丁

A 输入使用调用方显式提供的初始模板；不从最新 B 快照自动推断父模板。输出至少包含结构描述及示例 2–4 的 code 稀疏修改。结构说明是模型提出的描述，不等于结构差异已经由程序证明。

解析后使用公共补丁契约校验字段范围，返回可供后续检查的提案/物化结果与真实 diff；示例 1、CoT 和其他冻结字段不能改动。不运行三门，也不把“补丁合法”写成“示例过门”。若响应采用包裹对象，先验证和拆出补丁，再复用 `parse_sparse_patch`/`apply_patch`；不得把新格式直接当成旧解析器支持的格式。

### 3.3 B：映射与 CoT

由 `enumerate_rename_targets` 给出可支持的目标和拒绝原因。为模型提供可读、在本父快照内稳定的作用域标签及变量名，另存标签到真实 `scope_id` 的映射；不要求模型构造内部哈希。CoT-only 不依赖存在可重命名目标。

模型仅输出逐示例的 `renames` 和可选 `new_cot`。解析器补入可信的候选身份和父内容哈希，转换为 `BModificationRequest`，调用 `apply_b_modification`；不得要求模型回传完整 code 后直接接受。未知字段、未知作用域标签、类型错误或越界字段明确拒绝，不静默忽略。不能丢弃非法 rename 后只应用 CoT。

保留 01 的 `legal/no_change/invalid`、错误类别和原子性。格式/修改非法与模型请求故障、I/O 故障分开返回；名额消费、训练与暂停由 03 决定。本项不为非法甲提案自动追加纠错调用或替代候选。

## 4. 乙的单模板证据包

### 4.1 输入组成与完整性

提供从公共训练反馈产物装配单模板证据的入口，使用其实际字段格式，不能仅实现测试专用 JSON 协议。03 提供明确的产物引用或已读取记录；本项不扫描 run 目录猜测“最新候选”，也不发起训练。测试可在临时目录构造与公共产物同格式的 fixture。

每次乙输入包含：

1. 此前已提交的结构/字面经验摘要及证据标签。
2. 当前模板、结构描述、实际 diff，以及 A 门事实或 B 修改合法性事实。
3. 当前模板两题各 10 次的全部训练记录：逐样本代码、生成终态、静态判定、检测状态/原因/行证据；失败样本保留位置和原因。
4. 总体与逐题的命中/逃逸指标、分子分母及可用性；当前样本数 N、命中 H、命中且检测完成未检出 U 和工具证据缺失事实。
5. 固定比较基线的实际训练统计及比较来源；B 另有对应 A seed 的总体/逐题结果与差值。无需再次拼入 seed 全部生成代码，但不能只给一个未读取的文件路径充当比较事实。
6. 调用方标记本阶段首次有效归纳时，附 A 未过门或 B 非法变体的失败概要及证据引用；后续通过经验继承，不重复增加失败证据数。

校验候选/快照/父 seed 对应关系、两题的采样身份和重复序号集合、反馈与审计/静态/检测记录的关联。不得只凭数组长度为 20 认定完整；重复、缺项、异候选混入、陈旧 diff/父引用需拒绝。哈希、来源与匹配配置通过已有公共核验入口尽量复用，不另造通用产物迁移层。

生成重试耗尽的终态失败是完整记录的一种，留在分母；不能伪造代码或要求失败样本存在成功生成后的扫描。尚未完成的生成/必须的静态判定不同于终态失败，要返回证据未就绪。检测缺失或失败如实保留，单独的 evasion 未定义不阻止归纳；`hit=0` 也必须可归纳。`defined=false` 时 `value=null`，不能填 0、按 U/H 补算有效数值或据此声称逃逸成功。

固定比较基线快照已准备，但真实采样未做。02 测试使用明确标为 mock 的统计，不从快照推导或补造基线指标；真实接线要求传入实际比较产物，缺失时明确报告输入未就绪。若比较指标本身未定义，保留原因并不计算该指标差值。

### 4.2 模型可见事实与审计映射

送模内容使用模板、题目、样本和作用域的可读标签；内部候选 ID、样本 ID、文件路径、哈希及配置身份保存在独立审计映射与 `input_refs`。标签必须能稳定回指事实，不得因每次归纳都从同名标签重新编号而混淆旧经验来源。不要为清除审计字段而改写候选代码自身的字符串、路径或标识符。

保存实际送入的投影、来源文件/内容指纹及标签映射，区分“只在审计中登记”与“模型本次确实读到”。乙不能引用未知、未来或未提供的证据；旧经验引用可以沿已提交版本追溯。引用校验只保证来源可追溯，不宣称能自动验证任意自然语言因果断言。

## 5. 经验协议与上下文容量

### 5.1 分开记录、逐次更新

乙的结构化输出包括本次新增/修订条目和该经验类别的更新后摘要。每条至少有：条目标签、`observation` 或 `hypothesis`、描述、实际变化/比较对象、证据标签和不确定性。修订旧条目必须明确引用旧条目，不能覆盖历史版本；指标事实由程序随证据关联，模型文字不能改写报告指标。

A 只更新结构经验，B 只更新字面/诱导经验，另一类原样保留并可供读取。模型须把有限样本观察与假设区分；B 同时改命名和 CoT 时不单独归因于命名，不把相对 seed 的差值写成固定基线差值，不从两题 20 次宣称稳定因果提升。为这些边界提供提示约束和结构化比较来源，不引入新的研究指标或额外验证实验。

每次成功归纳产生不可变经验版本，至少关联前一版本、逻辑归纳身份、实际成功调用动作、证据指纹和本次条目。初始空经验也有明确表示。引用同一样本/旧条目不增加独立证据数；版本重放不产生第二次更新。条目全文与证据永久保留，后续模型使用摘要，无需每次装入所有历史全文。

乙归纳当前模板时使用上一模板提交后的经验；甲只能读取调用方明确指定的已提交版本。不要在构造甲输入时自动读取全局 `latest`。03 负责保存阶段入口版本、固定候选顺序以及阶段完成后可反馈给下一阶段的版本，02 不自行推进轮次。

### 5.2 首版摘要与容量策略

首版采用“两份滚动摘要＋完整条目归档”：每次乙在归纳当前模板的同一次响应中刷新所属类别的摘要，另一类别不变。摘要是可读内容并保留关键证据标签；完整历史与引用链仍在归档。不要额外调用一次模型归并经验，也不把历次原始响应不断追加成输入。

对摘要字段设置明确、固定且有版本的长度上限，并记录计数口径；实施者根据 8192 输出上限选择保守的工程上限，在交接中给出数值和依据。超过上限的输出视作协议失败，保留原响应、暂停；不得通过截断 JSON 或截断证据引用使其“通过”。该上限是输入管理参数，不改变科研采样数或模型参数。

每次请求使用 32768 上下文、8192 输出预留、余量 0，输入预算为 24576 tokens；沿用 `max_tokens=8192`、温度 0.7、超时 60 秒、请求最大尝试次数 2。甲乙模型身份为 `deepseek-v4-flash`，本项来源仅 mock。若沿用 `HeuristicTokenCounter`，报告其估算性质，不将本地估计当成服务端实测用量。

先装配固定系统规则、必要模板、当前完整证据及已有两类摘要，再作容量检查。不拼接旧原始训练结果或混合角色历史。当前模板的 20 条结果不能被自动删样本、裁代码或只保留高分样本；仅给路径也不能替代结果。必要输入超限时返回明确的容量阻塞及估算明细，在调用模型前暂停，由后续运行层处理；不自动增加摘要调用或改成多模板/分片归纳。

## 6. 动作、提交与中断恢复

### 6.1 请求与经验提交

角色调用前先保存请求，原始响应、finish reason、用量和费用先于解析/经验更新落盘。使用公共动作接口，不能另建一套脱离既有账本的调用日志。解析失败也保留原始输出和实际调用成本；未知用量/费用保留未知，不能记成 0。

逻辑归纳身份由 run、轮次、阶段、候选和协议标识确定；输入还须锁定前一经验版本、当前证据指纹、比较来源及失败概要。重复进入同一归纳不得重新读取变化后的最新经验或结果来组装不同请求。输入发生变化应明确冲突，不覆盖旧请求；不同候选即使模板内容相同也不能合并归纳。

最小持久化流程为：固定输入/请求 → 原始响应 → 已校验解析结果 → 不可变经验版本 → 逻辑归纳提交记录。每步记录可交叉核验的身份。经验版本文件存在但提交未完成时，恢复复用它并补齐提交；提交完成后不得再次追加经验或历史。若有 `HistoryStore` 记录，使用同一动作身份保证幂等；历史仅作审计或受控投影来源，不绕过甲乙输入边界。

`ActionStore.write_commit` 存在“文件已写、事件未追加”的中断窗口，恢复利用 `read_commit` / `ensure_committed_event`，不能通过重复写 commit 反复追加事件。方法经验存储也需覆盖自身文件与提交记录之间的中断窗口。损坏或身份冲突要明确拒绝，不凭存在文件就当成成功。

### 6.2 普通恢复与显式重试

公共 `run_role_call` 会优先返回已有 durable response，包括格式不合格的非空响应。必须区分：

| 情况 | 本项行为 |
| --- | --- |
| 响应已落盘，解析/经验提交中断 | 普通恢复重用响应，继续本地处理；不再次调用 source |
| 乙格式、引用、摘要长度不合法，或输出被截断 | 保留失败解析结果并暂停；普通恢复仍返回该失败，不陷入自动调用循环 |
| 调用方显式要求重试失败的乙归纳 | 同一逻辑归纳下新建关联的调用动作/重试序号，沿用已固定的证据与前经验版本；旧动作及成本保留，只允许一个成功经验提交 |
| 请求已开始、无终态也无可复用响应 | 沿用公共 unknown/orphan 处理，默认暂停；不得自动开启 `allow_retry_after_unknown` |
| 归纳已提交后再次恢复或请求重试 | 返回已提交结果，不重新归纳、不再次计费或增加证据 |

显式内容重试与公共单请求最多 2 次网络尝试是两层概念；持久化二者关联，交接示例中展示清楚。02 只提供可调用的重试参数/入口，不做 CLI，也不自动重试到成功。响应截断须根据 finish reason 判断，不能因为局部 JSON 恰好可解析就接受。

I/O 故障和模型内容非法分别报告。源调用注入应支持已落盘响应恢复时不构造真实 provider、不读取密钥；测试用一调用就报错的 source 证明恢复路径没有隐式模型调用。

## 7. 对 03 的最小接口交接

交付能独立演示以下调用链的入口，实际名称和签名由实施确定并写入 README 后续接口节：

```text
候选身份 + 初始模板/seed + 固定经验版本 + 任务素材
  → A/B 请求 → mock 角色调用 → 已校验提案/物化结果或明确失败

当前模板的落盘结果 + diff + 基线统计 + 可选 seed/失败概要
  → 单模板证据包 + 审计映射

证据包 + 指定前经验版本 + 逻辑归纳身份
  → 乙请求 → mock 调用 → 新经验版本/提交或暂停原因

同一归纳恢复 → 复用响应与提交
失败归纳 + 显式重试 → 新关联调用、同一逻辑归纳最多一次提交
```

03 仍负责整批候选先固定、A 检查与训练、排序/seed 选择、乙归纳顺序、首次失败概要标记、阶段完成和后续阶段可见的经验版本。02 可验证显式输入的关系，但不能自行筛 top5、跳过低分候选、替补失败名额或决定下一轮起点。
