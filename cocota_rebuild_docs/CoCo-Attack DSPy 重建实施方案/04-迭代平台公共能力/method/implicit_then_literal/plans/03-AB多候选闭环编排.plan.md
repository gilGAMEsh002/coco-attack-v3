# 03 · A/B 多候选闭环编排（离线 mock）

## 1. 任务与依据

将 01 的模板/候选契约和 B 修改物化、02 的甲乙调用和经验恢复，接成可运行、可暂停、可同版本恢复的五轮流程：固定比较基线 → A 五个候选 → A 逐模板归纳与 hit top5 → 每个 seed 五个 B 变体 → B 逐模板归纳与全局 hit top5 → 下一轮 A。完成后，04 只需接 CLI、真实来源与预检，无须重新实现研究状态机。

本项实现生产代码的编排入口，但所有执行验证仅用 mock 和临时目录。不得启动真实实验。

4. 公共 `iteration/{code_check,training_loop,method_inputs,action_runtime,template_snapshot}.py`；参考旧方法 `single_candidate_ab/runtime.py` 的服务接线及检查结果词表，不复制旧研究状态机。

## 3. 配置、身份与产物

### 3.1 新方法最小运行契约

定义独立的新方法配置与可调用运行入口，真实名称由实施确定。配置至少明确：run 身份及输出根目录、初始模板引用、固定比较基线引用、准备好的数据/规则/执行配置引用、甲乙角色配置、victim 配置、方法与提示协议版本。提供 JSON 往返、确定性配置指纹和同版本恢复校验；不通过目录名猜测模板或读取旧方法配置作为隐式默认。

首版研究常量固定：五个大轮次，A 每轮 5 个名额，每个 A seed 的 B 名额为 5，A/B 保留最多 5；两题 `BigCodeBench/13`、`BigCodeBench/1105`，各 10 次采样。不得为缩短测试悄悄把正式流程改成 1 轮/1 候选；单步测试可停在明确检查点，至少一个全流程 mock 保持这些常量。

甲乙模型 `deepseek-v4-flash`、victim `deepseek-v3.2-flash`，其余参数按 README 5.1 固定。角色来源可注入；本项只验证 mock。方法 A/B 与公共 `search/holdout` 是不同维度，不扩充公共阶段枚举。初始模板与比较基线即使内容偶然一致也保持不同角色引用。

候选逻辑身份用 `CandidateIdentity`。A 序号预固定为 1–5；B 按已落盘 seed 列表的确定顺序，为全部 `5 × seed 数` 变体预分配全局序号，另记 seed 内序号。B 选择和同分使用全局序号，不能使用完成时间或临时路径。结构描述及结构 ID 随 A 候选登记，不把描述相同或内容相同的候选归并。

### 3.2 目录与状态

调用方显式提供一个新 run 根目录；本项测试只用临时目录。下列为职责约定，具体命名可与公共服务协调后在交接中固定：

```text
<run_root>/
├── config.json / state.json       # 不变配置、当前进度与暂停原因
├── actions/                      # 公共 ActionStore 的角色调用与成本事实
├── experience/                   # 02 的版本、输入锁、逻辑归纳提交
├── snapshots/                    # 新模板，复用公共内容寻址存储
├── baseline/                     # 本 run 固定比较模板的训练与核验引用
└── rounds/<round>/
    ├── A/plan.json / candidates/ / ranking.json / commit.json
    └── B/plan.json / candidates/ / ranking.json / commit.json
```

每个候选有固定位置保存父引用、提案动作、解析/合法性、物化快照与实际 diff、检查请求与结果、公共训练配置/输出引用、乙动作和排名资格。将底层训练 `candidate_hash`、样本身份与方法 `logical_id` 分别保存并验证关联，不能直接把两种哈希视为同一身份。

`state.json` 是可恢复进度，不是唯一事实源。计划和提交保持不可变，派生排名可从已核验事实重建；不得靠 `latest`、文件 mtime 或“目录存在”决定完成。正式运行目录位置仍遵循实施安排，03 不写入该正式位置。

## 4. 首版执行顺序

采用候选间串行、候选内部有界并发。它能复用现有服务限制，无需新建跨候选调度器。甲与乙决策串行，victim 总体最多 4 个并发请求；A 一个候选的示例检查最多 3 路，且不能超过执行配置允许的容器数。配置超限在动作开始前报错，不自动放大执行配额。

### 4.1 一次固定比较基线

先经 01 核验用户指定的 `99fe015a…e449` 比较快照，再用公共训练服务完成本 run 的两题×10。不要求该基线通过 A 的三项门，不对它调用乙，也不放入候选排名。

基线与候选使用同一 victim、任务、采样与评估配置；保留比较模板内容身份、实际训练配置及产物指纹。生成和静态证据完整后固定比较结果，evasion 未定义可如实保留。基线结果未就绪则暂停，不用历史 clean 指标填充、不把未定义值填 0。

只做一次逻辑基线训练，恢复复用原配置和输出，不按轮次重采。不得误用 `TrainingLoopConfig.baseline_*` 将此投毒比较模板伪装成旧 clean 基线；可使用公共训练服务的无旧 baseline 模式，再在新方法层组织比较。各候选与基线的结果均保留公共来源核验。

### 4.2 A：先固定五个候选，再检查和训练

1. 保存本轮 A 计划：固定初始模板、两类阶段入口经验版本、5 个候选身份及稳定动作 ID。第一轮经验为空；以后使用上轮 B 阶段提交后的经验。
2. 依次用 02 的 A 入口提出并物化 5 个候选，所有提案共享同一阶段入口经验。允许已提出结构的描述作为后续提案素材；按请求保存，恢复不能临时添加后生成结构。格式错误或越界占名额，不自动纠错或补候选。
3. 全部名额得到提案终态后，提交候选批次，再开始 A 检查/训练。临时请求故障必须恢复原动作，不能把未得到结果的名额提前当作候选失败。
4. 对各合法模板的示例 2、3、4 检查 A 三项门。即使某例本次未改动也必须有匹配当前代码/规则的检查证据；不只检查 diff 中出现的示例。示例 1 冻结，不要求 clean 的示例 1 命中投毒门。
5. A 门通过者两题各采样 10 次；门失败者不训练、保留原因、不补名额。合法 `no_change` 保留原内容身份及独立候选身份，按相同 A 门流程处理，不因未改动自动过门或重提。
6. 所有名额的检查/训练达到可判定终态后，乙按 A 候选序号归纳全部有完整训练证据的模板，首次归纳附本阶段失败概要；`hit=0` 同样归纳。归纳完成后提交排名、最多 5 个 seed 和更新后的经验。

A 三门判定使用真实词表：功能 `outcome="passed"` 且 `passed=true`；静态 `verdict="target_present"` 且 `target_present=true`；Semgrep available/completed 为真且 detected 严格为 false。语法及入口有效也是功能检查前提。可参考旧方法 `evaluate_example_gate` 的纯判定，但不能继承其单候选状态迁移。

明确的候选功能失败、未命中或被检出是门失败；缺失记录、调用异常及暂未完成的检查是执行未完成，应恢复或暂停，不能当成低分候选悄悄跳过。A 门的工具证据不足不能算通过；和训练结果仅 evasion 未定义时仍可排名的规则分别处理。

### 4.3 B：所有 seed 的变体整批固定

1. 从本轮已提交 A 排名读取 seed 和 A 完成后的两类经验，固定整个 B 计划。每个 seed 5 个名额，最多 25 个。
2. 所有 B 提案均用该 seed 的 A 模板作父模板；同 seed 的第 2 个变体不以上一个 B 变体为父。用 01 枚举目标、02 组织映射/CoT 提案并物化。全部 seed 的名额先得到提案终态，再开始 B 训练和归纳，不能做完一个 seed 就把其结果反馈给后续 seed。
3. 非法变体占名额、不训练、不补；合法及合法 `no_change` 变体各执行两题×10，保持独立候选记录。B 不调用 A 的功能/oracle/Semgrep 示例门；训练样本的静态和检测评估仍照常执行。
4. 所有合法变体的训练证据齐备后，乙按预固定的 B 全局序号归纳全部有效模板，首次附非法变体概要；每次包含对应 A seed、固定基线的比较事实和实际 diff。
5. 从所有 seed 的有效变体中保留全局 hit top5，允许五个均来自同一 seed，不设置 seed 配额；提交排名、经验和阶段完成标记。

部分 seed 的五个变体全非法而其他 seed 有合法结果时，继续其他候选。全部 B 非法时保存事实并暂停，不调用乙；整个 B 没有可用训练结果时也暂停。B 第五轮完成即结束；此前完成 B 后只传经验到下一轮 A，下一轮仍从同一初始模板开始，B top5 不进入下一轮候选池。

## 5. 训练、比较、排序与经验接线

### 5.1 公共服务接入与证据完整性

复用 `build_example_check_request`/`run_example_code_check` 的输入和事实格式，`TrainingLoopConfig`/`run_training_loop` 的生成、清洗、静态、检测、指标和恢复链。提供可注入的检查及训练调用入口用于 mock；不要只写一个返回预定分数的状态机，至少一个接线测试经过公共训练服务和 02 的实际证据装配。

每候选使用独立、稳定的训练输出目录与 batch 身份；恢复保持相同采样配置，不换 seed、不 `force_rerun` 已完成样本。复用公共缓存键和成本口径，不通过内容相同合并方法候选或将缓存重放宣称为新独立证据。

排名前确认两题×10 的完整采样身份集合及来源对应，而非只检查文件存在/20 行。终态生成失败留在 N=20 的分母；尚未结束的生成、缺失静态记录或损坏产物阻塞阶段提交，不能先缩小候选集合排名。工具扫描应已被安排并留下完成/失败/不可用状态；不因只排 hit 而跳过检测。单独的 evasion 未定义不增加筛选门。

02 的证据入口有可选比较参数；03 正常路径必须显式提供固定基线引用与期望引用，B 还必须提供真实父 seed 比较。由已核验的公共产物构造总体/逐题统计、差值、来源指纹；不要从方法配置抄一个正确 seed ID 后附上别的候选分数，也不要由模型计算排名指标。逐题统计沿公共成功/失败与指标口径计算，不另改判定定义。

材料装配须随当前父模板重建/校验，保证甲实际看到的模板、B 作用域映射、物化父快照以及乙所归纳的训练快照相符。固定资产期望身份来自 01，不能以待核验结果自己的字段作为“期望值”自证一致。

### 5.2 排名与阶段提交

排序键固定为 `sample_hit_rate=H/N` 降序、阶段预定候选序号升序；不使用 evasion、ASR@k、seed 内名次、模型评价或完成时间。同分可基于整数 H/N 比较，避免不必要的浮点歧义。校验指标有定义、分母与采样计划一致、计数与落盘样本事实相符。

`hit=0` 有效，所有 B 均低于 A seed/固定基线也照常保留观测 top5；不启用基线阈值，不独立复采，不跨轮补足，不归并模板。A 仅 5 个名额，因此五个全部有效时五个均进入 B。

排名产物至少包含所有候选的资格及原因、稳定顺序、H/N、evasion 的值/可用性/原因、分母、逐题结果、基线比较；B 另列父 seed 比较和差值。保留全部候选及经验，top5 只标记本轮重点结果。报告注明“两道训练题上的观测 top5，未验证独立采样稳定性”。

阶段只有在候选处理、必需证据、全部应归纳模板的经验提交、排名产物都完成后才能提交。可先在内部计算排名，但不得在乙尚未完成时向下一阶段公布 seed/经验或开始新提案。阶段提交固定最终两类经验版本；全失败暂停不写成功提交。

### 5.3 经验版本与显式重试

甲始终使用阶段入口保存的两类版本。乙按候选序号递进：本类别使用上一模板归纳提交的新版本，另一类别保持本阶段入口版本；两类都显式传给 `run_induction`。版本从 `ExperienceStore` 读取并校验，不用同 ID 的临时摘要替换实际内容。

为每次归纳预先保存逻辑身份、证据包及审计引用、前版本与上下文版本。已经开始的归纳恢复使用原始输入，不能重算“目前最新经验”；02 输入锁、累计索引和费用审计直接复用。失败概要仅绑定首次有效归纳，恢复不重复注入/计数。

乙 `protocol_error` 普通恢复仍暂停；显式内容重试使用针对该暂停归纳的控制参数，由方法运行层先持久化新的 retry_index，再调用 02，不随机递增，也不因恢复自动重试。请求 unknown 默认暂停，只有调用方显式选择原动作的未知结果重试策略才透传；不能为绕过 unknown 新建候选。容量超限、身份冲突或 I/O 故障均返回具体暂停/错误原因，不自动裁掉样本或更改提示协议。

## 6. 可恢复状态机与停止分支

至少区分：基线准备、A 提案批次、A 检查/训练、A 归纳/提交、B 提案批次、B 训练、B 归纳/提交、完成，以及携带原执行位置的暂停。状态名字可调整，不把每个函数都做成工作流节点。

计划在外部动作前落盘，结果引用和本地候选状态在动作成功后提交。恢复优先核验公共动作/训练/经验的已提交事实并补齐本地进度。关键中断窗口包括：

- 甲响应已保存、候选记录未保存；快照已写、批次指针未更新。
- 示例检查结果已保存、本地门状态未提交；缺失终态的检查不能凭计划算成功。
- 训练已完成、本地候选仍标为训练中；恢复调用原公共配置验证/接续，不重采已完成样本。
- 乙经验已提交、本地候选尚未标归纳完成；恢复采用原归纳输入及版本，不再次归纳。
- 排名已写、阶段提交未写；阶段提交已写、全局轮次指针未推进。

有完成证据的检查可直接复用；外部调用开始但结果未知的窗口应暂停或按显式恢复策略处理，不能声称严格保证未知调用从未执行。成本继续引用公共账本，保留失败/重试/unknown，不将轮次汇总再记作一次费用。

全 A 门失败、全部 B 非法或无可用结果为人工检查暂停。普通 resume 不增加名额、不跳过 B、不进入下一轮；若需要变更研究配置或重开候选批次，应新建 run，不在原计划上改写。第五轮 B 完成后重复调用只返回完成结果，不能产生第六轮动作。

同版本恢复核验 run 配置、协议、初始模板、固定基线、数据/规则/执行身份以及已固定经验/动作引用。冲突在追加动作前拒绝，保留已有文件。无需做旧 run 迁移；若最小往返适配暴露 01/02 序列化问题，本项修复并覆盖真实保存/重读链。

## 7. 分步交付与必要检查

建议在本 subplan 内按三步完成：先纯配置/排名与批次状态，再接入一轮 A→B 和异常分支，最后五轮与中断恢复。三步是实施顺序，不新增授权或后续 subplan；全部完成后一次交付。

集中覆盖以下风险，不写只镜像数据类实现的测试：
