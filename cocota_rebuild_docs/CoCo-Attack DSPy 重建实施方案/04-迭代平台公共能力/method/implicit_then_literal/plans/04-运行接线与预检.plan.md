## 3. 配置与来源必须一致

### 3.1 显式服务身份

03 的 `_training_config` 当前固定 `source="mock"`。04 必须让 victim 来源成为显式、可序列化、参与配置身份的字段，并传入 `TrainingLoopConfig`；不能仅替换 runner，而让落盘配置仍写 mock。甲、乙继续使用各自的 `RoleCallConfig`，检查服务也明确区分真实服务与离线替身。

首版提供两个清晰配置用途：完整离线 mock，正式真实方法。混合来源仅允许明确标注的接线测试，不能作为真实研究结果。配置与 CLI 的来源选择冲突时拒绝，不采用“CLI 覆盖后继续沿用旧 hash”。mock 入口不得落入默认真实 gate/scanner；生产代码不能导入 `tests/_itl_runtime_fakes.py`。

保持方法 ID、五轮/5 个 A/每 seed 5 个 B/top5/两题各 10 次，以及 `enforce_formal_constants=True` 的正式约束。关闭该约束仅供明确的离线测试，正式真实命令拒绝使用。新配置字段影响身份，旧 mock run 不能被直接切换成真实 run，不做旧 run 迁移。

甲乙使用用户指定的 `deepseek-v4-flash`，victim 使用 `deepseek-v3.2-flash`。SDK 需要的 provider 前缀与实际模型名分开记录，说明从研究模型名到有效调用名的确定映射；不把 `openai/` 一类路由前缀误当成允许改用其他模型。配置、角色请求、victim 配置与报告必须能核对有效模型身份。提供方真实可用性留给后续连接验证，本次不猜测或宣称 API 已支持。

端到端保持 README 5.1 参数：甲乙温度 0.7、输出 8192、超时 60 秒、请求最多 2 次；victim 温度 0.7、输出 8192、超时 30 秒、请求最多 2 次；甲乙上下文 32768/输出预留 8192/余量 0；victim 最多 4 路，A 检查最多 3 路且不超过容器预算。检查超时按现有约定传递，不能只写在配置说明里而实际调用采用另一默认值。

### 3.2 真实来源与恢复

复用现有 DMX 路径：`resolve_role_source`/`DspyRoleSource`、既有凭证加载函数、公共生成首次/恢复子进程和 DSPy 缓存配置。不要新接 SDK、新建密钥系统或复制公共请求重试循环。甲乙来源分别绑定角色配置，victim 仍按公共生成路径独立接线。

角色来源延迟到真正需要发送请求时初始化。只读预检、读取报告、已完成运行、复用 durable response/已提交归纳都不应读取密钥或构造真实 LM。使用延迟代理/factory 时覆盖创建和调用次数；不能只证明 provider.generate 没调用，却已经在命令入口读了 `.env`。

04 实施和离线测试不读取真实 `.env`。后续明确启动真实请求时，由程序使用既有 `load_dmx_api_key` 路径读取 `DMX_API_KEY`；凭证不写入配置、报告、异常文本或命令行。测试使用哨兵凭证和调用计数，不能依赖开发环境恰好存在密钥。

缓存沿用公共 namespace/rollout/ledger 语义，不修改缓存键来伪造独立采样。进程级缓存初始化按既有模式一次完成，不因每个候选反复重置；角色与 victim 路径的隔离按公共实现落实。provider、工具或模型名不可用时报告原因，不自动切换模型、关闭检测或降级到 mock。

### 3.3 路径和启动绑定

明确配置相对路径的基准并在加载时一次解析；CLI、预检和运行必须使用同一有效配置与身份。初始模板、固定比较基线、数据、规则、执行配置、输出位置及来源选择在开始动作前完成校验，拒绝输出与只读资产/旧实验结果重叠。

固定基线使用 01 核验的 `99fe015a…e449` 资产，不能用同路径下的新内容或其他可读快照替代。**每轮 A 的初始模板是另一个显式输入**；目前用户提供的固定比较模板不等于已选定 A 初始模板。真实草案若仍缺该引用，要保留明确待填写项并让预检报告未就绪；不得自动采用基线、历史 clean 或最新 B 模板。缺少该参数不妨碍完成其余代码与离线交付。

真实运行前记录配置引用文件的内容身份/来源绑定，恢复时核对；同路径文件被修改不应被当成相同运行。复用已有资产及请求指纹，只补方法启动需要的绑定，不另造全仓库快照系统。

## 4. CLI、状态报告与受控停止

提供新方法独立的预检、启动、恢复、乙内容重试和只读状态入口。可采用一个运行命令加互斥模式，或多个子命令；名称须清楚包含 `implicit-then-literal`，在交接中给出最终命令与完整 `--help`。CLI 只负责解析/校验/接线，调用 03 的运行入口。

| 操作 | 必须保证的行为 |
| --- | --- |
| 只读预检 | 不创建正式 run，不实例化 MethodRuntime 的有副作用部分，不构造 provider，不执行工具 |
| 新运行 | 正式真实模式要求来源明确、正式常量开启、启动绑定齐备；已存在且有运行事实的目录不可当新 run 覆盖 |
| 普通恢复 | 使用原配置和输出，保留 03/02 同版本约束；protocol_error/unknown 不触发新内容调用 |
| 乙内容重试 | 必须指定当前实际暂停的 round/stage/candidate；仅内容协议失败适用，错误目标、已完成目标、非归纳暂停拒绝且不递增 retry_index |
| 只读状态/报告 | 只读取已落盘事实，不调用 run/resume 来获取状态，不修补提交或重新评估 |

区分成功完成、按请求停止、因失败暂停、用法错误/配置冲突，退出状态与 JSON 状态一致，不能所有暂停都 exit 0。普通恢复与内容重试给出不同命令示例。结果未知的动作默认暂停；若本项提供 unknown 显式重试控制，必须按具体原动作接入公共审计，不可用乙内容重试绕过 unknown。

同一 run 的运行/恢复/重试不得并行写入，复用已有 `RunLock` 或等价的现有单写者机制；只读报告无需启动写者。不要新建调度服务。

为后续小步真实验证提供两个可恢复的运行控制检查点：`baseline_complete` 和 `round_1_complete`（名称可按实现调整）。在该检查点全部持久化完成、下个阶段尚未发起外部动作时停止；再次显式 resume 可继续同一五轮 run。停止控制不改变候选、采样数或研究配置身份，与失败暂停明确区分。继续后不重采基线、不重提首轮候选；第五轮完成规则不变。

机器可读状态和简洁 Markdown/终端报告足够，不开发新的 UI。至少列出阶段/轮次、暂停或停止原因、下一步对应命令、各轮 top5 与 seed/基线关系、hit 分子分母、evasion 可用性、经验版本，以及所引用的结果位置。消耗直接关联公共账本；计划上限、已完成采样槽位、实际请求/重试、缓存复用与未知消耗分别解释，不将 03 摘要中的完成槽位数当作付费 API 调用次数。不要修改指标定义来满足展示。

## 5. 只读预检契约

新方法 `preflight.py` 输出结构化结论、错误、未验证事项及对应来源。预检与运行共用配置解析和校验，不能各实现一套互相矛盾的正式约束。允许显式写一个报告文件，但不得创建 `run/state.json`、actions、训练或经验目录。

预检至少检查：

- 初始模板与固定比较基线身份、四示例顺序、可改字段及只读来源，二者角色分开。
- 准备好的两题数据、规则和执行配置可读且归属匹配；沿用历史数据不等于沿用历史 clean 分数。
- 甲/乙/victim 的来源、模型映射、参数、协议、正式常量及整体并发上限；容器预算与既有执行配置资源声明相符。
- run 路径隔离、已有目录的恢复身份、输入绑定是否变化；冲突说明具体字段，不创建覆盖性文件。
- 甲的已知静态材料可否装配、已有样本证据是否能装入上下文（仅在确有这些数据时）。未来生成代码长度未知，不能声称所有乙请求都必然小于 24576 tokens；仍由运行时容量检查处理。
- 固定基线的状态分清“快照已准备”和“本 run 20 次结果尚未生成”。对新 run，尚无采样是正常待执行项，不因此要求事先另做一次基线；对已有 run 的基线完成声明则核验其证据。

只读预检不得探测密钥值、访问网络、运行 `docker`/`semgrep` 命令或执行候选。文件存在不证明工具可运行或模型可调用；相关字段标记 `not_checked`，不要打印统一的“真实环境 ready”。可用 `offline_preflight_passed` 表示文件与配置检查通过，真实连接/工具状态另外列示。

真实启动模式在执行前复用这些必需校验，不依赖“用户曾经运行过一次 preflight”。mock 与正式预检的差异必须来自明确服务选择，不因本机缺工具而自动选 mock。

## 6. 配置样例与离线验收

交付可通过实际 CLI 执行的 mock 配置及所需响应材料，按动作身份稳定绑定响应；新进程恢复不能因脚本游标重置把别的候选响应用于当前动作。mock 检查/训练输出与公共格式一致，并经过 02/03 的证据核验，不仅返回固定汇总分数。

真实配置草案覆盖全部必要字段，使用已确认的模型、参数和基线；未确定的 A 初始模板等标记清楚，不塞入假 hash 或虚构路径使其看似通过预检。草案命名标明用途，启动说明说明如何补齐为有效配置。可准备独立执行配置样例，资源值来自既有约定；不修改机器或扩大现有执行权限。

新增测试以三个文件集中覆盖下列反例，优先验证实际入口而非只检查对象字段：

| 验收组 | 必须出现的反例与结果 |
| --- | --- |

## 7. 后续真实验证的启动顺序（本项不执行）

在本方法 `实验启动说明.md` 写出下面每一步的实际命令、预期状态、产物位置和继续条件。研究配置保持五轮与每模板 20 次，不通过缩减正式常量冒充原方法验证。

检查点是可选的运行控制：后续若一次明确授权完整流程，就在授权范围内继续，不逐步重复询问；若只要求验证到基线或首轮，则在对应检查点停止。
