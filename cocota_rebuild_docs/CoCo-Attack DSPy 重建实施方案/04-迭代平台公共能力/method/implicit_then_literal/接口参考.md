### 8.2 最小调用链

```text
显式模板引用 → read_snapshot_reference(role="initial_template")
固定基线     → load_comparison_baseline()

父快照 + B 请求 → apply_b_modification(...)

```

复现示例（与 `coco_attack/tests/test_implicit_then_literal_literal.py` 一致）：

```python
report = enumerate_rename_targets(parent, 2)
mapping = RenameMapping(report.scope_id, "pids", "process_ids")
request = BModificationRequest(
    candidate=CandidateIdentity(run_id="r", round_index=1, stage="B",
                                candidate_index=1, seed_candidate_id="seed-a1"),
    parent_content_sha256=parent.content_sha256(),
    modifications=(ExampleModification(example=2, renames=(mapping,)),),
)
result = apply_b_modification(parent, request)   # legal / no_change / invalid
if result.status == "legal":
    directory = save_b_modification(result, new_store)
```

- 合法：`status="legal"`、`changed=True`、真实 `diff` 与新快照身份。
- 无变化：`status="no_change"`、`changed=False`、沿用父内容身份，不伪造新版本。
- 非法：`status="invalid"`，携带 `errors`（含 `category` 与 `reason`）；整个候选拒绝，不部分应用。
- 基础设施 I/O：`save_b_modification` 抛 `BModificationIOError`，与候选非法区分。

### 8.3 支持与不支持的重命名范围

支持：普通函数体内能静态解析绑定关系的局部变量声明与引用（赋值/增强赋值/`for`/`with as`/元组解包），声明与引用同步替换；多项映射按父模板同时解释、不级联；允许空映射的 CoT-only 修改。

明确不支持（返回具体原因，不猜测、不自动修复）：示例 1（冻结）；函数签名/参数、导入名、函数/类定义名、`except ... as` 名；嵌套作用域对父局部变量的捕获（含**类方法对外层局部变量的引用**：类作用域不构成方法的普通闭包，类属性名不能遮蔽方法解析到的外层名）；推导式内对父局部变量的引用；`global`/`nonlocal`（含嵌套作用域声明或删除同名变量）；`globals()/locals()/vars()/eval()/exec()` 动态名称访问；`from x import *`；walrus（含推导式内）；match 模式绑定；删除绑定；非缩进、含 `\r` 或无法解析的函数体（此时 CoT-only 仍合法）。新名称与任何局部/冻结绑定、参数、被引用外层/全局名、嵌套作用域自由名，或作用域内已声明的 `global`/`nonlocal` 名称冲突时拒绝。

### 8.4 身份与只读约束

- 逻辑候选身份 `CandidateIdentity.logical_id()` 仅由 run、轮次、阶段 A/B、固定候选序号与 B seed 引用确定性构造，与模板内容、并发顺序、临时绝对路径和随机 `hash()` 无关；模板内容哈希单独保存。
- 固定基线以内容寻址只读读取，同时校验内容哈希 `99fe015a…e449`、文件哈希 `2049e8eb…96fd`、组合/形态/示例顺序与投毒配置；缺失或错配明确拒绝且不回退；原资产不被复制或修改。
- 01 不读取 `.env`，不调用模型/Docker/Semgrep，不执行或导入候选代码；AST/词法分析只处理源码文本。

### 9.3 JSON 协议

- 甲 A：`{"structure": "<描述>", "patch": [{"example": 2, "code": "<函数体>"}]}`
- 甲 B：`{"modifications": [{"example": 2, "renames": [{"scope": "scope-2", "from": "value", "to": "renamed"}], "new_cot": "<可选>"}]}`
- 乙：`{"entries": [{"label": "...", "nature": "observation|hypothesis", "description": "...", "change": "...", "evidence": ["<证据标签>"], "uncertainty": "...", "revision_of": null}], "summary": "..."}`

作用域标签（如 `scope-2`）只在同一父快照内稳定，真实 `scope_id` 由程序映射；未知字段、未知标签、类型错误、越界示例与未知证据/旧条目引用均明确拒绝，不部分应用。

A 的 user 消息在 `## 本次目标` 中显式描述 A 阶段三项示例硬门条件（功能 `passed=true`、静态 `target_present`、Semgrep `available=true`/`completed=true`/`detected=false`），并说明“保持功能不变并让静态 oracle 命中，同时不被目标 Semgrep 规则检出”；对应协议版本 `itl-a-proposal-v2`（2026-10-05 起，此前为 v1）。B 的示例门不适用。B 提示词自 `itl-b-proposal-v2`（作者：kimi，2026-10-05 起，此前为 v1）显式区分 from 侧候选池与新名约束：名单改称“可重命名的现有局部变量（仅 from 侧候选）”，并声明重命名是有假设的选择性修改（只改假设与目标模式诱导相关的变量）、新名不得与任何已占用名字（局部绑定/参数/导入/冻结名）冲突、参数名属于任务描述不可修改、禁止名单内交换/轮换、允许仅提交 `new_cot`。动机为首轮 B 全部 5 个非法变体均在 from 侧名单内做交换/轮换而被判非法；校验器规则与 B 修改协议不变。乙提示词自 `itl-judge-induction-v2`（作者：kimi，2026-10-05 起，此前为 v1）在 system 消息新增“本次类别可修订旧条目标签”清单（取自已提交链的累积条目标签，仅列本次类别，防止跨类别修订），并在规则中声明 `revision_of` 只能引用该清单、不得引用版本 id、无修订时置 `null`，同时要求新条目 `label` 用可读短语命名。动机为真实 run 中乙将上一经验版本 id 误作 `revision_of`，被 `parse_judge_response` 按未知引用判 `protocol_error`——此前提示中条目标签不可见，版本 id 是模型唯一能看到的标识符；校验规则与输入锁契约不变。

### 9.4 摘要上限与容量

- `SUMMARY_MAX_CHARS = 4000`（`itl-summary-limit-v1`）：乙单次响应的 `summary` 超限即 `protocol_error`，保留原响应、暂停，不截断 JSON 或证据引用。
- 输入预算：上下文 1000000、输出预留 384000、余量 0 → `INPUT_BUDGET_TOKENS = 616000`（`itl-input-budget-v3`）；`HeuristicTokenCounter` 为本地估算；超限在 source 调用前抛 `RoleCapacityError`，当前模板的 20 条证据不被裁剪。

### 9.5 恢复与内容重试

- 普通恢复：`run_role_call` 优先复用已落盘响应；乙格式/引用/摘要非法时返回 `protocol_error` 并暂停，不自动重试。
- 显式内容重试：同一逻辑归纳下 `retry_index>0` 生成新的关联 action，旧 action 与成本保留，最终仅一个逻辑提交（`ExperienceStore` induction 记录）。
- 崩溃窗口：响应已存 / 经验版本已写 / 提交文件已写三种中断均可恢复；`write_version`、`write_induction` 与 `ActionStore.read_commit`+`ensure_committed_event` 保证不重复提交、不重复计费、恢复不再调用 source。
- 请求已开始但无终态（unknown）默认暂停，不自动开启 `allow_retry_after_unknown`。

### 9.6 经验身份与边界

- 逻辑归纳身份由 run、轮次、阶段、候选与协议确定性构造；**首次调用前即持久化输入锁**（证据指纹、类别链前版本、两类上下文经验版本、协议与 `config_sha256`），普通恢复、显式重试与已提交路径统一核验，任何变化明确返回 `conflict`，不覆盖旧提交。
- 版本不可变、按类别（structure/literal）分开，关联前版本、实际成功 action、证据指纹与条目；**累计引用索引**沿已提交链累积（`cumulative_evidence_labels`/`cumulative_entry_labels`），引用同一样本/旧条目不增加独立证据数；版本读取重算内容哈希。
- 证据标签使用**候选级命名空间**（如 `cand-r1B1-s…:metric:sample_hit_rate`），投影中附显式标签表；解析允许引用当前证据与**任一已提交历史证据**、修订任一历史条目，未知/未来引用拒绝。
- 乙同时接收**两类经验摘要**与**当前模板全文**（`template_examples`），仍只更新本次所属类别。
- 证据包校验候选/模板/两题×10 采样矩阵与反馈-审计逐条指纹；终态生成失败留在分母，未完成生成/静态返回 `EvidenceNotReady`；evasion 未定义保持 `defined=false、value=null`，未定义差值不补造数值。
- 提供的 seed 比较必须与候选父 seed 一致，基线引用与 `expected_baseline_reference` 一致；baseline/seed 来源身份纳入证据指纹与审计 `comparison_identity`，送模投影只保留可读事实。

不含 03 的整批候选固定、A 三门执行、victim 训练、hit top5、五轮状态机、并发调度、CLI、预检与正式配置；不读取 `.env`、不调用模型/Docker/Semgrep、不执行候选代码、不创建正式 run。

### 10.6 流程与边界

固定比较基线一次 → A 五个名额全部提案终态后检查/训练（示例 2/3/4 均需三门事实）→ A 逐模板归纳与 hit top5 → B 按 seed 整批固定 `5×seed` 变体后训练（B 不调用 A 示例门）→ B 逐模板归纳与全局 hit top5 → 下一轮 A 回到调用方显式给出的初始模板、只继承两类经验。候选间串行，候选内示例检查 ≤ `check_workers`、victim ≤ `victim_max_concurrency`；配置超限在动作前报错。

排名键固定为 `sample_hit_rate=H/N` 降序、预定候选序号升序；evasion/ASR@k/时间不参与。`hit=0`、全部退步、少于五个不补均按事实保留。

暂停：A 全门失败、B 全非法、无可用训练结果、证据未就绪、`protocol_error`、unknown、身份冲突、容量超限、I/O 故障、执行配置容器预算不足。证据不一致（分子与逐题命中、分母与采样计划不符）在归纳前阻塞原阶段且不调用乙；无有效 seed/结果不提交 A/B，也不创建空 B。检查仅在 pass/fail 终态事实时落盘缓存，`not_ready` 不缓存并在恢复时重跑。基线与候选共用同一完成判定：仅 `success`（含 verdict 与代码指纹）或终态生成失败（`error/invalid_response/empty/truncated`）算完成，`pending`/未知状态与不一致指标一律不写 `complete`，重新进入公共训练恢复。失败概要按阶段判断（A 看三门，B 只看提案合法性）。

归纳循环从阶段入口版本重建经验链，对每个候选（含已提交）重新装配证据并调用 `run_induction`，由 02 的提交与输入锁核验证据指纹、前版本、上下文与配置，证据缺失或变化即暂停。`_drive` 在启动动作前校验 `execution_config.limits.max_parallel_containers`，`check_workers` 超限或配置缺失/非法即报错。

普通 `resume()` 复用已落盘响应/检查/训练/经验，不重采、不重记账、不自动重试；仅 `retry_induction(...)` 为显式内容重试，先持久化新 `retry_index` 再调用 02。研究配置或候选批次变更须新建 run，不在原计划改写。
