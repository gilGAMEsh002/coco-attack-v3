## 0. 首步补齐初始检查恢复的输入绑定

[E21](../../../验收记录.md#e21) 的 Lunar 复核确认任务 05 的 F1–F4 主体已落实，但 `_load_existing_check` 仅比较代码哈希。真实检查接线前，需同时绑定当前任务/组合/stage、实际 code_prompt 与 test、启用检查层、执行配置内容和相应检查协议/工具来源。方法状态内的逐例完成记录与磁盘结果兜底复用使用同一核验，不能因配置文件路径没变就认为内容没变。

复用现有检查结果中可用的身份与指纹；若缺少完整请求指纹，最小化补一份按实际依赖计算的 request 指纹。校验结果结构与检查是否完整，故障占位不能充作有效完成证据。初始只启用功能检查时，不要求无关层具备成功结果；已完成的功能失败仍是失败事实，不改成通过。

用临时检查记录验证：相同代码而 task/test/code_prompt/执行配置内容变化时拒绝旧证据或明确重检；相同输入的完整已落盘记录恢复不重复调用。保留旧件；只修同一动作 checkpoint，不新增跨动作静态/SAST 结果缓存。无需真实容器执行，完成后继续下列来源接线。

## 1. 本次交付与边界

让方法入口能明确选择脚本 mutator 或既有 DMX 角色来源；mutator 与 victim 的模型/source/采样配置分别传到实际调用处。交付无副作用的离线预检入口、mock 配置示例、真实运行配置草案及启动/恢复命令模板。

本项只实施与离线验证，不加载真实密钥、不请求真实模型、不运行 Docker/Semgrep、不启动真实一轮或五轮实验。不增加 provider、候选池、总预算、锁定或测试阶段。模型与上下文最终取值未决定时，配置草案明确列缺项，不凭可用默认值视作运行已获授权。

## 2. 角色配置与身份

现有 MethodConfig 的 model/source/temperature/max_tokens 同时用于 `_role_config` 与 `_training_config`，CLI 又始终创建 ScriptedMutator。改为两个显式角色配置（字段组织可按现有代码最小实现）：

- mutator：source、model、temperature、max_tokens、request_timeout、既有 max_request_attempts、context_window/output_reserve 与计量余量、可选价格及其版本。复用 RoleCallConfig，不伪造 victim SampleIdentity。
- victim：source、model、temperature、repeats、max_tokens、既有超时/重试配置；沿用 GenerationConfig/TrainingLoopConfig。当前方法训练固定两题、0.7/5，模型必须与所选 baseline 对齐；mutator 模型可以不同。
- 检查：示例执行配置、Semgrep 规则来源、实际扫描超时及示例执行超时。初始检查、A 门和训练扫描均透传有效配置，不能接受字段却忽略；通用默认不擅改。

完整角色配置进入方法配置身份，实际请求对应其角色配置。source 与运行日志/cost 标记一致，不能用 ScriptedMutator 配上 source=dmx 伪装真实 mutator；混合“真实 mutator + mock victim”若用于接线，明确为混合来源，不可计算真实研究差值。

不建立旧配置迁移。新配置协议可升级；旧 run/产物只读保留，不续写旧格式来证明兼容。更新配置往返与身份测试；可读配置样例中的两个角色即使选同一模型，也显式列明。

## 3. 来源、密钥与缓存的接线

复用 `resolve_role_source/DspyRoleSource`、`generation/service.py:load_dmx_api_key` 及现有 ledger/重试约定。方法业务逻辑只依赖角色调用接口，不读取凭证；执行入口在显式真实执行路径才加载密钥和构造真实来源。预检、帮助、mock、仅重建已有响应的恢复都不应为无实际请求加载密钥。离线测试以假的凭证加载器/LM 边界验证接线，日志不输出凭证。

为角色调用明确 DSPy 进程级缓存初始化位置和目录。mutator 进程在启动时配置一次，victim 继续复用现有独立生成进程；不能随 A/B、候选或动作切换全局缓存，也不改变已有 victim 请求键。使用新方法 run 的显式缓存路径，保留 source/stage 隔离和实际命名空间记录。mock 接线可用替身验证配置次数和实际参数，无需网络缓存热身。

CLI 按 source 构造来源：脚本分支要求明确脚本并接受列表或 `{action_id: response}`；DMX 分支不强制脚本且不偷偷回退脚本。对 mock/真实检查、mock/真实训练等相互冲突选项执行前报错，不按分支先后悄悄选一个。现有 `--allow-real-training` 只表示选择真实训练服务，不等于 mutator 来源已选择真实，帮助与报告须说清。

已持久化角色响应的恢复沿任务 04 协议，不因重新选择来源而重请求；unknown 窗口仍按显式恢复选项处理，不能自动换动作/脚本重发。脚本身份校验继续保留。

## 4. 离线预检报告

新增预检模式或独立命令，解析/验证配置、只读资产及必要接口，输出可审阅清单；仅写显式报告目录，不创建可恢复的“已开始实验”状态，不执行门或模型调用。

报告至少包含：

| 项 | 需要呈现的事实 |
| --- | --- |
| 运行范围 | 方法/配置协议、两题 search 清单、四示例、轮数、冻结/允许字段、真实与替身服务选择；25 题未参与 |
| 模型来源 | mutator/victim 独立 model/source/采样/输出上限、实际传参、DMX endpoint、缓存目录与进程归属；不读出或打印密钥 |
| 上下文 | 四示例素材/规则/当前模板的计量、计量方式、上下文窗口、输出预留与余量；不足明确失败，启发式不冒充精确 token 计数 |
| 示例检查 | Docker 执行配置引用、规则源/检查协议/超时；只读确认配置完整，不把配置存在称为 Docker/Semgrep 已验证可用 |
| baseline | 以 victim 角色匹配模型、温度/repeats/任务集合，引用既有来源绑定检查；版本差异警告，缺少来源不可比，mock 不能生成真实差值 |

| 待决定项 | 未指定的真实 mutator 模型/上下文/输出参数、victim 与基线对齐结果、实际检查是否已执行；明确“离线预检通过”与“真实环境可用/方法有效”不同 |

可先提供完整 mock 配置和有明确未决项的真实配置草案。真实配置未齐时报告 not_ready 与具体缺项；不需要为此阻塞接口代码开发。用户给出配置并决定真实执行后，才另安排少量实际检查和首轮观察。

## 5. 必要验证与交付

1. 用调用边界 spy 验证 mutator/victim 可不同模型/source，max_tokens/temperature/timeout 到达各自正确入口；mutator 变化不覆盖 victim baseline 配置。
2. mock 列表/映射脚本都可从 CLI 加载并恢复；source/脚本/真实服务开关矛盾拒绝；配置变更拒绝续写旧 run。
3. 预检执行时将密钥加载、provider、Docker、Semgrep 入口替换为“调用即失败”，仍能产出完整报告；缺配置/基线不匹配/上下文不足给出准确结果。
4. DMX 来源构造与同步 LM.forward 参数通过替身验证；已保存响应恢复不加载密钥、不调 provider，缓存配置只初始化一次。未用真实 DMX 的结果标记为接线测试。
5. 重跑受影响的配置/CLI/角色/方法接口检查，不重建已验证方法状态机，不为此全量重跑阶段 03。沿用 F1–F4 的反馈和恢复回归。
