# 07 · 示例检查与模型采样并发

依据：[用户并发要求 D07](../../../records/00-裁定记录.md#d07)、[当前接口核对 E29](../../../records/02-单候选方法实施.md#e29)、主方案 [D 执行隔离](../../../../CoCo-Attack%20DSPy%20重建实施方案.md#execution-contract)/[E 生成审计](../../../../CoCo-Attack%20DSPy%20重建实施方案.md#generation-contract)/[F 缓存](../../../../CoCo-Attack%20DSPy%20重建实施方案.md#cache-contract)。复用任务 01–06，不改方法决策或评估口径。

## 1. 调度范围

- 并发单位一：同一快照、同一批次内的不同示例检查。初始例 2–4 与 A 累计待检示例可以并行；每例内部仍使用已有直接检查与独立 Docker 容器，不将单个 unittest 测试套件拆并行。若直接检查同时包含 static/Semgrep，则该例按原调用顺序完成，反馈仍保留各层事实。
- 并发单位二：同一候选训练批次的两题 × 5 次 victim 独立请求。复用 GenerationRunner 的 ThreadPoolExecutor、有界并发、限速、重试与 ledger，不再套一层进程/线程池。
- mutator=1；A 改写、门、训练、B 与下一轮依次推进。单候选和共享历史有数据依赖，不并发 A/B 决策，不跨候选/轮预取。
- 第一份并发配置建议：示例检查 workers=3、victim max_concurrency=4；用户只指定要开启并发，数值是工程建议，需在交付配置中显式记录。现有默认保持 1，便于回退；不更改采样次数和输出上限。

## 2. victim 并发参数透传

新增或接通 `VictimRole.max_concurrency → TrainingLoopConfig.max_concurrency → GenerationConfig.max_concurrency`，替换训练闭环内部固定为 1 的接线。字段校验正整数，参与 JSON 往返与配置身份；恢复沿用原生成配置，换并发值不能静默续写旧 run。更新预检 roles/实际参数输出。

底层模型仍按既有同步 dspy.LM.forward、单进程一次缓存配置、单层重试与线程安全 ledger 执行。不改变 rollout/sample 身份算法；新增配置字段按同版本约定处理，不迁移历史 run。不新增角色 RPM/TPM 平台或累计预算系统。

## 3. 示例检查调度与状态提交

为方法配置增加显式 `example_check_workers`（名字可调整）。协调线程先确定当前快照与待检集合、构造请求/请求指纹和独立输出目录，再将未完成检查交给有界线程池；worker 只返回事实或错误，不能并发写共享 state.json、方法事件/共享历史。协调线程接收完成结果，逐例即时落盘，最终按示例号稳定汇总。

保留 E20/E26 的恢复能力：先校验逐例完整 checkpoint，已完成且身份一致的例不重新执行；结果已落盘但方法状态未写时仍可复用。初始与 A 检查都应在同一批次内登记逐例结果，A 累计待检集合不能因某个较早完成的成功结果而丢失其它例。输入/超时/配置变化按现有指纹拒绝复用。

初始只依据功能结果推进；A 要求所有待检例完整过门再训练/进入 B。工具异常或 future 失败显式记未完成/错误并阻止推进；正确回收已启动工作、保留已完成证据，未知执行窗口仍记未知。线程停止不等于容器停止，继续使用已有超时/子孙进程回收，不退回主机执行。

复用各例独立 run 目录/RunLock/ledger。不要让多个例共用一个执行目录或并发覆写同一 JSON；不要把工作池 worker 数误当成多个独立 run 合计的主机总容量。

## 4. 执行配置与资源上限

新建本次并发专用执行配置副本，不修改历史或仓库公共 execution.local.json 来假装旧运行也是并发。将 `limits.max_parallel_containers` 与方法 worker 实际上限对齐；该字段本身不是任务调度器，方法必须真实有界提交。预检明确 effective workers、容器数与每容器限制、输出 tmpfs 总需求；超出配置上限应拒绝或明确收窄并记录，不能悄悄忽略。

保留每容器时间/CPU/内存/pids/output/网络隔离配置。共享输出目录采用既有唯一样本路径和资源检查；核对并发数放大后的 tmpfs 需求，不能只改一个数字。主机可用资源随时变化，本次只读观察不能替代启动时 check-execution。

## 5. 必要验证与交付

1. victim 用同步屏障/事件控制的 mock source 验证峰值大于 1 且不超过配置，10 个样本身份唯一、响应/用量不重复；测 CLI/方法→训练→生成实际参数，而非只检查配置对象有字段。首次与恢复均走既有独立生成进程边界。
2. 示例检查使用有计数器的阻塞替身验证实际重叠与上限；workers=1 与 workers=3 的事实/门结论相同、反馈按示例号稳定。一个例失败不得触发训练或 B。
3. 中断窗口覆盖部分例已完成、结果落盘但共享状态未更新；新对象恢复仅补缺失例，账本与历史不重复。不以仅同进程对象记忆证明恢复。
4. 使用临时目录/新目录完成 mock 接线；不加载密钥、不调用真实模型/Docker/Semgrep、不运行 25 题。生产 Docker 并发的实际可用性留待后续明确执行，不把替身峰值称为真实容器峰值。
5. 新建并发配置、执行配置副本与预检报告，保留 E28 串行配置和报告。建议存于 `cocota_runs/phase04/method-ab-flash-v32-concurrent-preflight-20260923/`；预定实验输出采用未用的新目录。更新[启动说明](../实验启动说明.md)为实际交付路径。

交付必要源码、配置/CLI/恢复/并发回归、实际峰值与样本/账本计数、可复现命令、预检和限制。文档记录仍使用阶段 E 编号；不新建通用工作流框架，不重建阶段 01–03。
