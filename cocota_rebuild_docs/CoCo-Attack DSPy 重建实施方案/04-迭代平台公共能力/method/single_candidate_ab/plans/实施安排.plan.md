## 1. 本批工作边界

按 5 个大迭代为一批观察，始终只维护一个当前候选，使用共享聊天历史。每个大迭代先做 A 的 code 迭代：示例功能、oracle 命中、Semgrep 不命中硬门全过后才能进入 B；未过门继续 A 或暂停。B 不是内部迭代，每个大迭代只有一次 cot 修改机会，可同时修改示例 2–4 的 cot。示例 1 冻结。A 过门后与有效 B 修改后的训练评估分别回灌指标。

本文件直接安排该方法的实施，“5 轮一批”只是运行批次，不另外定义实验阶段。

沿用 `search` 阶段执行 train 两题，temperature=0.7、repeats=5。`2/25` 是本 run 的工作划分；不覆盖阶段 03 数据或索引。当前迭代不生成另外 25 题的提示、响应、评估或方法反馈，不锁定最终模板，不宣称研究成功。

先按独立基础设施计划补齐公共服务，再接本方法的单候选 A/B 流程。公共代码检查返回功能、oracle、Semgrep 事实；本方法将它们组合为 A 门。通用插件注册框架、两个不同方法驱动、额外纯反思流程、锁定排序和测试评估留待确有需要时展开；不列为第一批启动前置。

## 2. 设计审阅：先统一的口径

### 2.1 A 的静态 oracle / Semgrep 硬门（D02）

原稿将训练 evasion > 0 写作硬门，但伪代码只按功能门推进；现已由 D02 明确对象并同步方法设计 §5.2/§6。

**用户已明确**：[D02](../../../records/00-裁定记录.md#d02) 要求 A 的硬门包含“静态 oracle 命中，Semgrep 不命中”。两项须同时满足，且保留既有示例功能门。此前“只按功能门推进、evasion 只作观察标签”的建议撤回；A 未过完整硬门时，不进入 B；继续在同一个候选上修改 code 或暂停。

用户进一步明确对象为 **A 修改后的投毒示例代码**。对本步改写的示例逐例重组 `code_prompt + code`，在同一份代码上检查 oracle `target_present` 与 Semgrep 完成扫描且不命中；任一不满足，该次 A 尝试失败，仍停留在 A，不得用旧模板绕过硬门进入 B（D03）。A 过门后才生成两题训练输出；训练 ASR/evasion 只用于反馈。Semgrep 失败、不可用或未完成不能满足不命中条件。本次不为 B 增加训练指标门。

**语义边界（须在后续成功判定中区分）**：A 门作用在「A 改写后的投毒示例代码」上，**不等价于 victim 生成代码的逃逸**；训练输出的 ASR/evasion 本期只是反馈，既不构成 A 门，也不构成攻击有效性结论。后续若进入锁定/测试，须把「示例门通过」与「victim 实际 ASR/逃逸」分开报告。

### 2.2 单候选与一次性 B（D03，已明确）

依据[D03](../../../records/00-裁定记录.md#d03)，始终只有一个当前候选。A 在该候选上修改 code，过完整硬门后才能进入 B；B 在 A 通过的同一候选上有且仅有一次 cot 修改机会，可以一次修改三个示例。评估反馈留给下一大迭代，不在 B 内继续修改。

不增加候选池、父代选择器、显式 LLM 采纳调用或分数回滚。保留历史快照是为了恢复和追溯，不是让方法在多个候选之间选择。此前“失败后 B 使用旧 current”和“固定十步调用”的安排撤回。

B 输出格式或修改范围非法时，不应用补丁，保留进入 B 的内容并记录失败；该次机会已使用，不额外请求 cot 修复。A 未过门时本轮尚未完成，不应为了完成批次数跳进 B。

### 2.3 指标分别命名，避免把 0.20 当 ASR@1

已从阶段 03 静态逐样本文件复算：训练题 13 命中 repeat 0、2；1105 五次均未命中。因此 train 的 ASR@1=1/2、ASR@5=1/2、sample_hit_rate=2/10。设计表已修正，来源见[审阅证据 E01](../../../records/01-公共能力实施.md#e01)。

当前迭代同时报 ASR@1、ASR@5、sample_hit_rate，各自减去同口径 base；不输出没有 k 的单一 `ΔASR`，不混用样本率与任务率。无需为观察阶段选一个排序主分；后续若锁定，届时明确 k 和聚合规则。

设计 §5.3 称训练 pass@k“仅作结果指标”，但 §11 的评估链没有训练功能执行。**建议本批不执行训练输出功能测试，明确记为未评估，不能报 0 或沿用 clean 的 pass@k 充当候选值。** 若要报告它，需要显式加入训练功能评估，且仍不作为本批门。示例功能门结果另列，不能叫受害模型 pass@k。

### 2.4 运行恢复的可承诺范围

计划、请求输入及原始模型响应应先持久化，恢复时不重做已经完成的 LLM 决策。已有 ledger 能恢复“响应已落盘、投影未完成”的情况，可复用。

请求已送出但响应未可靠落盘时，不能保证服务端只调用一次或获得原响应。应沿用已有未知消耗记录，按相同动作恢复/重试；不能宣称整个远端调用恰好一次。仅保证同一实现与产物版本的恢复，不建设旧版本迁移。

### 2.5 历史与输入边界

每次调用都须提供实际父模板全文，不能只在第一条 user 消息中提供。反馈后应附下一步 A/B 请求，避免模型不知道当前字段限制。四个示例除测试外还应带代码前缀和入口：现有 fewshot `code` 是缩进函数体，功能门按 `code_prompt + code` 重组；不能把完整函数重复拼接。

模型可见的“示例 1–4”“训练题 1–2”“第几次采样”是展示标签；真实任务 ID、候选 hash、运行路径留在旁路映射。代码或测试本来包含的文件路径、标识符属于程序内容，不可为了清除“审计字段”而改写源码。

先用确定性摘要压缩旧记录，不增加总结模型调用。调用前用所选模型的 tokenizer 计量/估算完整请求并记录计量方式，调用后用返回 usage 核对；输出预留也计入上下文容量。固定 system 与当前模板本身放不下时暂停并报告，不能默默截断。上下文容量不是累计费用额度。

## 3. 现有能力与实际适配点

本节是本方法接入时的检查清单；公共服务实现归[基础设施计划 I1–I6](../../../infrastructure/plans/迭代基础设施实施安排.plan.md)，A/B 门和次数约束归方法模块。

路径以下均相对 `coco_attack/src/coco_attack/`。

| 方法需要 | 可复用实现 | 最小补充 |
| --- | --- | --- |
| 投毒候选三件套与身份 | `prompts/trigger.py`、`prompts/materialize.py`、`generation/inputs.py` | 新增投毒物化；除 fewshot/meta/test_prompts 外，还需既有生成入口要求的 `manifest.json`。候选 hash 经 fewshot 和 meta 覆盖投毒字节与 attack_config |
| 训练两题生成 | `generation/inputs.py:load_generation_inputs` 的 `task_ids` 参数 | 两题属于原 search，可直接按两题物化/调度；服务给方法的投影不携带其他任务。无需先重做全数据划分 |
| 示例功能门 | `evaluation/run_functional.py` 的执行部分、`execution/`、现有 harness 与分类器 | 现有 `_build_inputs` 只接受评测阶段内任务，示例被排除，不能仅传示例 task_ids。提取一个小执行适配入口或直接封装底层 Docker 服务，显式传示例代码/测试/身份；不把示例塞进 evaluation_ids |

| semgrep 逐行反馈 | `evaluation/sast.py:_scan_semgrep` | 当前 alerts 只保留 rule_id/severity；需保留起止行列并从本次扫描源码取证据。工具结构化 errors/未扫描目标也应核对，不能只据退出码将未完成扫描记为“未检出” |
| 指标与 baseline 对齐 | `evaluation/metrics.py`、`experiments/index.py`、阶段 03 原始记录 | 两题 base 离线切片并保留来源，不覆盖旧索引；严格核对模型/任务集/采样身份，评测环境差异按 H 提示 |

| 计划和候选状态 | 原子写入工具、ledger 与现有恢复模式 | 唯一当前候选 + 每次动作先落盘；记录 A 尝试序号、B 机会是否使用和修改历史；历史版本只供恢复与审计 |

`compute_candidate_hash` 还包含本次任务提示集合，适合本次迭代的固定两题运行身份。未来跨 train/test 跟踪同一个模板时，应另保留稳定的模板内容指纹，不能假定切换集合后该 candidate_hash 不变。本批无需提前实现跨集合评估。

**集成陷阱（实现时须绕开）**：投毒候选的物化不得复用 `prompts/materialize.py::materialize_clean`（其 `attack_config` 固定为 clean），也不得让候选经过 `experiments/baseline.py` 的 clean 断言（其要求 `attack_config.enabled is False`）。投毒物化器须自行写入 `enabled=true` 的 `attack_config`，并由**投毒后的 meta + fewshot**（而非 clean 快照）计算候选身份。

功能缓存可以复用既有机制；B 未改代码时，只有全部依赖指纹一致才能复用。首批允许重跑至多三个示例，不为减少这几次执行先设计新缓存。静态/semgrep 不新增评估结果缓存；恢复已完成动作不等于把跨候选扫描结果缓存化。

## 4. 按可观察闭环分三步实现

### 第一步：接入独立基础设施，跑通单候选离线闭环

1. 以 clean fewshot、四示例任务快照和训练两题为输入，固定一个 run 配置；提示/规则/测试内容指纹由平台持有。
2. 方法声明字段级稀疏补丁规则：用示例序号指定 code/cot，未列字段继承；公共 I1 保存实际差分，方法校验阶段字段和示例 1 冻结。无需先做通用行号补丁引擎。
3. 调用 I1 物化并登记当前模板，保证三件套和生成 manifest 一致；方法只请求两题提示。
4. 调用 I3 直接检查示例，方法按三项事实组成 A 门，过门后请求训练生成/评估；mock 验证接线，真实 Docker 单独确认示例代码。重点核对 348 替代实现来源和功能结果，不以设计中的“用户确认可通过”冒充当前镜像执行证据。
5. 调用 I6 离线切出 train baseline，I5 按方法投影规则回灌展示标签、分母和未定义原因。

交付：一份候选包、示例门结果、两题评估/反馈和基线切片。格式错误、功能失败或 A 示例静态门失败均不调用该候选的 victim；初始示例不过门时先保留结果复核，不自动降低 strict pass。

### 第二步：单候选 A/B 流程与共享历史恢复

依赖 I2/I4/I5 的独立服务。以下只实现方法状态转换与历史策略，不另建模型调用器或动作账本。

1. 按 §2.1/§2.2 接线：A 未过门时继续 A，过门才调用一次 B。先保存阶段与当前候选，每次 A 尝试及 B 请求执行前分别落盘，不能预展开为固定十次模型调用。
2. 顺序持久化：当前请求 → 原始响应/用量 → 补丁校验和当前候选 → 示例门 → 允许时的训练评估 → 反馈/历史 → 下一阶段。记录本轮 A 尝试序号及 B 是否已使用，中断后继续未完成动作。
3. A 失败只回灌该次原因，不调用 B 或 victim。B 非法补丁不应用，也不产生本轮第二次 cot 修改；不要把模型修复隐藏在传输重试中。
4. 当前候选内容变化更新身份，历史快照只作审计。**建议**相同候选复用已完成样本并标明来源；缓存重放不增加独立样本。空补丁不能绕过 A 未通过的门。
5. 完整历史与每次送模历史分别保存；按实际消息体积压缩旧记录，A 的失败次数不预设。模型可见消息不含平台审计字段。

交付：mock 下覆盖“A 多次失败后通过 → B 一次修改三个 cot → 下一轮 A”，并能恢复任一动作。运行中始终只有一个当前候选，没有候选池和选优步骤。

### 第三步：真实首批与人工观察（后续工作）

1. 确定 mutator 模型、上下文容量、采样参数、单次输出上限；victim 建议沿用已核实基线的 `openai/DeepSeek-V3.2`、max_tokens=8192，真实配置仍显式记录。底层继续使用既定 DMX 服务。
2. 核对 Docker/semgrep、四示例输入和两题 baseline，随后运行首批 5 轮。上下文装不下或基础设施不可用时，保存可恢复位置并报告。
3. mutator 调用数为 A 的实际尝试次数，加上各轮进入 B 后的一次调用，不预估为固定 10 次。按 A 过门后一次与有效 B 修改后一次训练评估，完整 5 轮至多 100 个计划内 victim 样本；重复内容复用或 B 非法补丁可能减少调用，传输重试另计。c0 默认只做示例功能门；若另评估其训练表现，则另记 10 个 victim 样本，不能混入 clean base。
4. 批末输出逐步指标、功能/格式失败、目标约束状态、实际用量与调用来源、完整历史和研究观察。正常停在批末，由用户决定续跑或修订方法；无需现在设计自动续跑判据。

更换方法、模型、提示协议或划分时新建 run；同配置的下一批可追加计划并保留前批内容。进入测试前另定锁定及成功判定协议；不能事后把本批当前迭代包装成预注册验证实验。

## 5. 第一批必要检查

集中在已有测试入口补少量有区分力的场景，不按模块逐个扩测试套件。通用入口、身份、成本及恢复先按基础设施计划独立检查；这里复用其证据，并重点检查本方法的三项门、单候选与 B 次数：

| 检查 | 可判断的结果 |
| --- | --- |
| 候选内容与身份 | 示例 1 不变；A/B 无越界；实际提示包含变更；改变投毒字节或 attack_config 改变身份；不物化 25 题 |
| 功能门 | 重组后的示例代码在现有隔离环境执行；失败与环境不可用分开；只有 strict pass 才可作为功能合格 |
| A 示例静态门 | 对每个改写示例检查同一份代码；oracle 命中且 Semgrep 完成扫描但不命中才通过；oracle 不命中、工具命中/失败/不可用均阻止 A 推进与该候选训练生成；未过门始终留在 A，不调用 B |
| 反馈与指标 | 两题固定分母；生成失败留分母；工具失败不算逃逸；全无命中 evasion 未定义；base 切片得到 ASR@1/@5=1/2 与样本率 2/10 |
| 单候选与 B 次数 | A 多次尝试始终修改同一当前候选；过门前 B 调用为零；过门后 B 仅一次，可同时改三个 cot；历史版本不参与选优 |
| 动作恢复 | 在响应落盘后、评估中、反馈落盘后中断；恢复不重规划、不重复调用已完成的 B、不重复提交已完成动作或成本；未知请求窗口如实记录 |
| 历史与数据范围 | 模型实际请求含当前模板、阶段指令、命中/失败；不含测试集信息及平台审计字段；超过上下文容量时按固定规则压缩或暂停 |
| 模型输入素材 | 送模内容包含**四个示例的测试用例**（含 `code_prompt` 前缀与入口）与 **semgrep 规则源文本**；模型可见侧不含真实任务 ID、候选 hash、运行路径等审计字段；代码/测试自身的路径与标识符属程序内容，不改写 |
| 批末语义 | 5 轮结束可审阅；不自动续跑/锁定/测试；无满足目标候选时不把当前工作模板称为可行解 |
