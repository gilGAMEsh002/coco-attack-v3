# 阶段 04：迭代平台公共能力

依据：[主实施方案](../CoCo-Attack%20DSPy%20重建实施方案.md)工作包 I，并复用工作包 E、F 的服务；需求对应 F8、E1、E4、X1–X3。

公共契约按[主方案阅读入口](../CoCo-Attack%20DSPy%20重建实施方案.md#shared-contracts)查阅；文档与验收组织遵循[主方案第 5 节](../CoCo-Attack%20DSPy%20重建实施方案.md#documentation-conventions)。

<a id="current-status"></a>

当前进度：规划阶段，尚未实施或验收。

## 1. 阶段目标与边界

在已验收的生成、评估与基线之上提供可插拔方法所需的公共执行服务，使方法能够登记候选、请求生成/评估/纯推理、获得受限反馈、查询消耗记录、持久化计划并按协议锁定结果。

能力边界与科研参数遵循[实施范围](../CoCo-Attack%20DSPy%20重建实施方案.md#scope)及[平台协议 I](../CoCo-Attack%20DSPy%20重建实施方案.md#platform-contract)；本阶段交付公共服务和两个确定性测试驱动，具体研究方法后续单独设计。

## 2. 输入与依赖

- 接收阶段 01 的任务/提示接口及已裁定版本，阶段 02 的生成/评估服务、ledger 和缓存入口；阶段隔离按阶段 02 D06 以约定与方法作者自觉为主。
- 接收阶段 03 的 baseline 索引和报告，按[H 的基线匹配条件](../CoCo-Attack%20DSPy%20重建实施方案.md#baseline-contract)检查本次比较所需配置与产物是否齐备。
- 子任务 01 准备符合[I 的参数要求](../CoCo-Attack%20DSPy%20重建实施方案.md#platform-contract)且明确标注为测试用途的驱动配置；子任务 03 根据[B 的实际划分](../CoCo-Attack%20DSPy%20重建实施方案.md#domain-contract)校验成功判定所需条件，不为未配置 holdout 的组合补造验证结果。

## 3. 子任务与推进顺序

| 子任务 plan | 主要工作与责任边界 | 依赖与交付 |
|---|---|---|
| `01-方法接入与执行服务.plan.md` | 最小插件入口、候选登记、生成/评估/纯推理服务、search 受限视图，接入两个测试驱动 | 依赖阶段 01–03 公共接口；交付平台服务边界与测试驱动 |
| `02-计划持久化与预算审计.plan.md` | 计划先落盘、稳定动作身份、动作恢复、四类成本记录、候选来源与字段差分记录 | 依赖 01；复用阶段 02 ledger 与缓存，交付可恢复运行记录和成本账本 |
| `03-反馈边界与锁定协议.plan.md` | 按阶段过滤反馈、校验 baseline、执行预固定锁定与成功判定，集中验证平台 | 依赖 01、02；交付锁定记录、隔离检查和平台验收报告 |

先明确服务边界和数据投影，再细化持久化与锁定。子任务 plan 只约束运行时对外能力，不把一种历史方法内部流程写成所有方法必须遵循的接口。

## 5. 阶段统一测试与人工验收

由子任务 03 汇集平台检查，复用前阶段的生成、评估、隔离和缓存检查。用两个确定性驱动和少量共享场景覆盖本阶段新增的接入、恢复、成本审计与锁定行为。

| 编号 | 验收组 | 集中场景与证据 |
|---|---|---|
| AC-01 | 方法接入与纯推理 | 两个驱动使用不同调用顺序，均能登记/评估候选；不产生候选的推理动作可完成并记账，无需改数据或评估层 |
| AC-02 | 动作恢复与成本审计 | 动作中途 kill 后恢复，不重新规划，不重复计算已完成动作成本；失败、重试和淘汰可追溯 |
| AC-03 | 反馈与阶段边界（按阶段 02 [D06](../02-生成与评估闭环/验收记录.md#d06) 撤回代码强制部分） | 按约定过滤反馈字段、不回流 holdout；阶段隔离靠方法作者自觉，不要求越权拒绝证据 |
| AC-04 | 锁定与结果 | 全量功能合格候选排序、平分规则、全失败、baseline 错配、不同目标配置与缺失成功条件 |

轨迹一致性优先用确定性 mock 或固定 DSPy 缓存重放验证；真实 API 即使 temperature=0 也不作为服务端绝对确定性的承诺。记录动作序列、输入输出引用、成本和恢复位置作为证据。

本阶段收尾材料引用两个驱动的产物、动作轨迹、反馈约定和锁定结果，按 AC-01–AC-04 汇入[阶段验收](./阶段验收.md)，说明平台能力、未决问题及研究方法尚未实现的边界。

## 6. 完成条件与后续衔接

公共服务可被两个测试驱动使用，恢复、成本审计、阶段边界、锁定及全失败处理通过集中验收，且文档明确科研参数和能力限制后，可将本阶段标为完成。

后续每种研究方法单独制定 plan，决定内部算法与实验配置，并在本平台上实施真实对照。本阶段不自动启动付费方法实验，不将平台测试结果写成攻击效果或方法优劣结论。
