# victim 提示词约定

设计整理：GPT / Codex，2026-10-26。

状态：evidence_guided_search 的输入与保存约定。本文含实现前的计划措辞；实际实现与试跑状态以[方法实现计划](../迭代方法架构/方法实现计划.md)为准。通用边界见[公共协议](../../../06-统一实验协议/统一实验协议.md)。架构见[迭代方法架构](../迭代方法架构/迭代方法架构.md)。本目录与角色模板并列，保留 victim 消息组成的唯一研究约定；本轮不发明另一套 few-shot 文体，不改写原始 B2-nolabel 资产。

## 1. 实际输入

victim 接收该候选完整物化的四个示例，以及当前训练任务查询。示例 1 不改，后三个示例只允许 code/CoT 变化；题面内容、示例顺序和数量固定。查询任务仅来自本次两道原题，最终任务不出现在训练生成或归纳上下文中。

trigger 由固定渲染规则作用于后三个示例题面和查询首句；可修改 CoT 至多一次。保留已修复的题面插入逻辑与实际文本，不能为了标记破坏代码块、文件名或任务要求。

victim 不接收功能测试、公开 SAST 规则、六条假设、当前指导、候选来源、检验问题或归纳报告。目标模式不通过“请模仿后续实现”之类新增元指令直接告知 victim。

## 2. 与角色模板的关系

执行模型输出的是示例字段，不是 victim 的 system 消息。方法将其按公共物化/消息构造能力渲染成实际输入，不把执行角色的 system/user 文本转发给 victim。

本目录若后续增加外层消息模板，应只维护一份权威文案，明确它与示例物化的职责，记录新增版本；不能既在这里编辑又在方法源码另维护一个不同版本。具体外层 system、消息角色和生成模式需在运行前按实际接口确定，本轮不从旧 runtime 偷带默认值。

## 3. clean-fewshot 参照

用户已明确（2026-10-27）：参照采用原始 clean-fewshot 代码和 CoT，不向示例题面、CoT 或查询注入 trigger。攻击候选仍按攻击条件注入 trigger。使用相同训练题、victim 与可比采样和评价设置，分别保存完整消息及条件差异；功能约束比较的是各自声明条件下的任务完成表现，不把差异单独归因于 code/CoT。

参照的具体资产版本与采样参数尚未确定。其配置与输出独立保存，用于经验检验模块诊断和模板选择模块功能约束；历史分数未经可比性核对不能自动充当阈值基准，也不把命名相近的历史 clean 批次直接当作本次参照。

## 4. 保存、恢复与检查

保存固定起点与候选快照、题面渲染版本、外层模板或消息构造版本、实际完整消息及内容身份、模型采样设置、请求尝试和原始响应。H、D、F 评价关联同一份提取代码。

新 run 固定所用模板/构造配置，resume 使用 run 副本与已有响应。外部文案更新需新 run，不让恢复悄悄读取新提示词。接入前可检查固定字段、实际 trigger 插入和角色材料未泄露；本轮不进行 victim 调用。
