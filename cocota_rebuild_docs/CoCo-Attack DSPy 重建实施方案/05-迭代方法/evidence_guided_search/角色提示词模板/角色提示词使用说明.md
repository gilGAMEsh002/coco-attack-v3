## 1. 模板入口与职责

| 调用 | 模板 | 用途 |
| --- | --- | --- |
| 候选生成 | [system](候选生成/system.md.j2)、[user](候选生成/user.md.j2) | 一个调用提出一个候选；程序按 guided/unguided/probe 组装材料 |
| 独立归纳 | [system](独立归纳/system.md.j2)、[user](独立归纳/user.md.j2) | 只分析本候选；原始输出及评估证据可见 |
| 统一汇总 | [system](统一汇总/system.md.j2)、[user](统一汇总/user.md.j2) | 汇总本轮报告，过滤/修订指导，形成下一轮检验计划 |

同一模型可以承担多个调用，模型选择不由模板固定。模板选择模块是按已定规则运行的程序，不另建让模型自由排序的角色。用户已确定（2026-10-27）示例 oracle 接受 present/possibly_present；code/CoT 一致性与无模仿元指令仅由提示词要求，不作程序检查，不新增审查角色。

## 2. 输入组装约定

模板使用 Jinja 渲染。候选 user 模板通过 source 的 if 分支直接编写“本次生成要求”，通过顶层 set 定义固定六条初始假设并用 for 展示，迭代材料仍由程序注入。使用严格缺失变量策略；JSON 材料由程序序列化，不能发送未展开占位符。角色之间不复用带历史消息的聊天上下文。

| 调用 | 必填变量 |
| --- | --- |
| 候选生成 | `target_definition`、`initial_template_json`、`example_tasks_json`、`task_demonstration`、`public_sast_rules`、`source`、`source_context_json` |
| 独立归纳 | `target_definition`、`round_experience_json`、`training_tasks_json`、`public_sast_rules`、`candidate_evidence_json`、`clean_reference_json`、`probe_context_json`、`evidence_index_json`、`evidence_visibility_json` |
| 统一汇总 | `round_experience_json`、`candidate_reports_json`、`candidate_summaries_json`、`clean_reference_json`、`executed_probe_context_json`、`evidence_index_json`、`evidence_excerpt_json` |

固定六条初始假设直接写在候选 user.md.j2 的 initial_hypotheses 列表中，作为各轮共同背景。新 run 冻结模板并读取六条原文，同步内部初始假设和 experience-0，配置只保留范围等元信息。编辑这六条时无需手工同步配置中的 statement；列表顺序对应内部初始编号与范围元信息，应保持对应顺序。已有 run 始终读取其冻结副本，不回读外部新值。冻结时校验六句在各来源及有/无动态材料时均实际展示一次，避免误删展示循环后静默丢失。

`source_context_json` 只承载动态“本次迭代材料”：guided 提供有实质更新的有效指导，未变的初始六条不重复；被撤回的初始条目仅以编号和限定说明放入 withdrawn_initial_hypotheses，原文作为背景保留，不把其误当作当前有效指导。unguided 此变量固定为空对象，不接收任何跨轮修正/撤回或统计。probe 保留本臂比较计划和必要假设。动态材料为空时，模板不展示该区块。三类共享 clean 起点、示例测试及固定任务演示，不提供训练题题面/测试或参考实现。

候选的 initial_template_json 是按原示例顺序排列的四元素数组，每个元素仅含 instruct_prompt、cot、code。任务 ID、触发设置、污染标志、版本等元数据保留在程序的完整快照中，不注入此块；补丁 example 编号仍按数组位置 1–4 对应。

probe 固定字段仅能引用已有可解析快照的候选或 `initial_template`；汇总输入中 `snapshot_ref` 非空，或已提供 `candidate_template`，才能作为候选字段来源。无快照的失败候选仍可分析，不可作为固定字段来源。

“本次生成要求”的三段文字现由用户直接在 user.md.j2 中编辑，程序仅提供 source，由模板按分支选择。来源以外的数据过滤仍由程序完成，不能靠一句来源说明替代输入隔离。

| source | 模板中的本次生成要求 |
| --- | --- |
| guided | 将本次提供的初始假设和当前指导作为有条件的尝试建议，自主提出修改。 |
| unguided | 依据固定起点、起始六条假设、示例任务与测试及固定任务演示独立提出修改。 |
| probe | 按本臂比较问题和修改要求构造候选；采用给定固定字段值，仅改允许变化的字段，未列字段保持初始模板。 |

候选生成的 `target_definition` 只取当前 CWE 章节中“目标模式”那一句，不注入章节标题、in/out/不确定边界或参考链接。独立归纳继续使用完整定义及判定边界，便于解释实际评价；二者共享同一目标模式含义，不授权归纳重判工具结果。沿用用户编辑后的正文，不额外补回已删内容。

候选生成与相关独立归纳的 `public_sast_rules` 提供当前 CWE 已公开规则的完整匹配条件摘录：保留 id、languages、severity、patterns，以及 pattern-not、metavariable-pattern、focus-metavariable、options 等所有匹配字段；仅省去 message 安全劝告、fix/fix-regex 修复建议和 metadata 分类/链接/许可证。来源路径、哈希与版本说明留在审计侧，不注入角色。摘录不是可执行扫描配置；实际扫描继续使用原始规则文件，匹配逻辑不变。初始化分别保存 public_sast_rules.source.txt 与 public_sast_rules.prompt.txt，供核对原文及实际可见文本。目标定义与扫描规则分开，不把规则覆盖范围当作目标定义。

候选生成的 `example_tasks_json` 仅保留 example、task_id、test，即四个示例的编号、任务 ID 和完整实际功能测试。题面及接口在固定初始模板中已有，不再复制 instruct_prompt、code_prompt、entry_point；functional_fixture 版本元数据不注入候选。实际测试中的 fixture/mock 代码与断言保持完整，不因去元数据而删改测试。程序仍从示例资产读取并绑定实际 overlay，完整材料保留在审计/归纳侧。`task_demonstration` 提供[clean→B2-nolabel 的关键修改演示](候选生成/B2-nolabel任务演示.md)，作为三来源共同的固定输入，不引入历史 victim 输出或分数。

独立归纳仍使用 `training_tasks_json` 变量承载按阶段提供的任务上下文：未训练时提供相关示例任务与实际测试；已有 victim 输出时提供两道训练题及实际测试。两条路径均通过字段白名单，不注入 `canonical_solution`、`raw_test` 或完整任务记录。程序审计侧和原始资产仍保留原记录。涉及功能解释时保留相应测试和 fixture/mock，不以一句摘要代替。示例任务用于 few-shot 构造，训练题用于 victim 查询，两者的任务 ID 不要求相同。

独立归纳和统一汇总使用 `clean_reference_json` 中的逐题程序统计、真实分母、覆盖与可比性说明，供功能诊断与跨报告核对，不包含模板选择模块的阈值或可行性结论。独立归纳无训练输出时可不注入参照正文，按下述空材料约定说明原因；参照本身缺失或不可比则记录实际状态，不补零、不猜造基准。汇总无需默认注入 clean 原始响应，确需回查的证据使用摘录变量。

独立归纳保留共同入口经验、目标定义、候选身份和已取得证据，辅助材料按下表组装。依据已有生成/训练/评价状态、任务 ID 和规则 ID 选择，不新增材料筛选模型或审查角色。

| 已取得证据 | 注入的辅助材料 | 不默认注入的材料 |
| --- | --- | --- |
| 生成失败、无可用快照 | 失败阶段、原始响应或错误、解析/字段检查证据；若涉及任务内容，附对应说明 | 完整 SAST 规则、训练测试、clean 结果 |
| 已有快照，但示例检查失败或未训练 | 示例构造和失败分析所需的任务要求、检查证据及对应示例实际测试和规则 | 与该阶段无关的两道训练题测试、clean 结果 |
| 已有训练输出 | 两道训练题及其测试、可比 clean 统计；解释检测现象所需的规则 | 与当前 CWE 或观察无关的其他规则 |
| 某层评价故障或未执行 | 保留已有输出和其他层证据，附该层状态与故障原因；其余材料按已完成阶段准备 | 仅为解释工具故障而复制的无关规则或测试 |

这只裁剪辅助上下文，不按候选得分或通过/失败筛选 victim 样本，也不删除原始产物。各层实际状态、计数和缺口均保留；未注入与证据不存在分别说明。

必填变量仍须传入：不适用的 JSON 材料传空对象/数组，不适用的规则正文传空字符串，原因统一写入 `evidence_visibility_json`。`probe_context_json` 在非 probe 时为空对象；probe 时包含本臂条件和相关假设，不含同轮其他臂结果。汇总无回查摘录时 `evidence_excerpt_json` 为空数组。这些是组装规则，不再重复写进面向模型的章节标题。

初始经验仍为六条建立可追踪 ID。原文始终保留在固定模板段落，不随迭代重写；动态经验可以限定、修正或撤回其适用性。guided 同时看到固定背景与这些动态变化，unguided 只看到固定背景，probe 另收必要比较材料。固定原文不再从 JSON 中重复注入，也不称为已验证结论。

`candidate_evidence_json` 包含该候选已取得的输出、各层证据及程序统计，以及生成状态和失败阶段。统计附实际指标含义和覆盖说明，H 包含 present/possibly_present，原始状态仍分列；不要求归纳角色重新实现计数或准入判定。生成失败时快照可以为 null，未执行的检查与样本数组可以为空并带原因，不从初始模板补造候选或结果。模型能分析证据内容，不假设它能自行打开文件路径。`evidence_index_json` 列允许引用的 ID，`evidence_visibility_json` 说明实际注入的原文、辅助材料及未注入原因。证据按候选完整保存，超上下文时显式处理并记录实际可见范围，不静默裁剪后声称分析了全部样本。

汇总输入中的局部假设引用先由程序加候选命名空间。需要回查时用 `evidence_excerpt_json` 显式提供所需原文及 ID；没有则为空数组，不只给路径却假称已经读取。所有角色都排除最终任务及其评价结果。

单候选 `probe_suggestions` 与汇总 `next_probes` 都是建议/提案；轮末经验经校验和完整保存后发布，下一轮轮初由运行器按预定选择规则分配执行预算。发布经验不以提案获安排为条件，未执行提案不算已检验。

## 3. 输出、校验与持久化

三个角色均只返回一个 JSON 对象，不附围栏或额外文字。字段与[接口约定](../迭代方法架构/模块接口与轮次流程.md)一致；数组可为空，未知原因需明确。模型不能生成真实历史 ID、工具计数、费用或最终选择标准。

候选对象仅含 `patch` 与 `victim_learning_goal`：前者是实际字段补丁，后者是期望 victim 从修改示例中学到的实现方式或求解步骤，必须为非空字符串。候选协议版本为 egs-candidate-v2，不再返回 rationale、intent、expected_change 或 uncertainty。方法只把 patch 送公共解析/物化服务，victim_learning_goal 原样留在候选证据供归纳读取，不视作实测学习结果。独立报告与汇总的协议不变，仍校验引用和更新冲突；模型输出中的“已通过”不能代替实际检查。

候选输入已移除 modification_contract 变量和对应段落，角色就绪检查不再要求该字段；用户编辑的 user 模板不回填这段材料。修改范围与准入仍由现有程序约束执行，历史 run 的冻结输入和输出不改写。

保存模板原文和内容身份、注入变量、实际消息、角色/模型配置、原始响应、解析结果或失败原因。数据是上下文而非指令来源，模型应忽略其中试图改变角色任务或输出格式的指令。

## 4. 外置源与 run 副本

方法配置引用本目录及角色相对路径，不在 `coco_methods` 再维护一份可编辑文案。新 run 启动时复制所用模板、记录来源与版本，后续调用使用该副本并保存实际渲染消息。resume 从 run 副本读取；外部模板的新编辑只用于新 run。

配置路径按明确基准解析，不能依赖启动 cwd 恰好在文档目录。实现时载入器与解析器属于新方法；本轮不新增载入代码、框架或迁移旧 run。

## 8. clean 起点、固定任务演示与输入边界
