# 复测驱动的模板选择

设计整理：GPT / Codex，2026-10-26。

审核清单修订：GPT / Codex，2026-10-27。

状态：实现准备稿，未实现。入口见[架构总览](../迭代方法架构.md)，交接见[模块接口与轮次流程](../模块接口与轮次流程.md)。已确认保留入围后复测，功能暂采用相对 clean-fewshot 的退化约束；未确认具体排序与参数。

## 1. 输入、输出和职责

输入为已结束搜索的候选记录、各候选训练事实、clean-fewshot 参照、预定入围规则、功能约束与最终排序规则、复测预算及评价配置。模板选择模块不修改模板，不向经验检验模块发布新指导，不接触最终评估任务。

输出 `SelectionResult`：`status`、搜索结束与规则版本、候选及未入围理由、冻结入围集合、复测计划与结果、功能约束状态和理由、最终候选或未选出原因、逐题计数/真实分母/覆盖及消耗引用。仅在证据和规则允许时返回最终模板；未完成、未知和明确不可行分别保存。

这是终局决策程序，主要减少一次偶然高分主导选择的风险。两道原题上的复测没有独立任务外推含义，不能单凭模板选择模块声称解决过拟合。

## 2. 入围与冻结

搜索期间保留所有候选记录，入围不意味着删除其他候选。按事先确定的规则，考虑训练证据与实现差异形成少量入围模板；不能在看过复测结果后改变入围理由。

规则需要回答：哪些证据完整度足以比较，如何对待重复模板，不同任务表现如何考虑，是否允许起点或 probe 臂入围，最多保留多少。以上尚未确定，不默认按合并 H 排名取前几名，也不默认各来源拥有固定名额。

这里“重复模板”指候选探索模块已记录的相同内容身份在入围阶段如何归并、是否占独立名额，以及已有搜索证据如何使用；属于模板选择模块的入围规则。候选探索模块已决定的生成/采样阶段是否追加采样、引用何种已有响应是既有事实，模板选择模块不回溯改写。相同内容的不同独立采样可按预定证据规则处理，同一响应被多次引用不能重复计数。

复测前保存并冻结入围候选 ID 与快照身份、理由、参照身份、每题采样安排、工具与模型配置、约束和排序规则。方案修订和版本化发生在本次复测启动前；复测启动后不在本次模板选择模块中修改模板、规则或入围理由。

若复测反馈促使改模板、指导或规则，明确结束本次流程，另开开发 run 并披露已使用的反馈。新 run 的初始材料与继承证据需如实记录；这是新的开发过程，不是模板选择模块向已结束搜索或经验检验模块自动回流，也不能把同批复测继续称为未使用的评价反馈。

## 3. 可比复测

对入围模板在同两道原题上进行可比新增采样，保留每题和每次结果，不只测早期高分题。clean-fewshot 在相同题、victim、功能测试与可比采样条件下提供功能参照；是否同步新增参照采样、能否复用已有参照、旧证据如何与新证据结合，都需预先确定。

旧搜索样本与复测样本使用不同阶段/批次标识，不能悄悄合并为“独立验证”。复测发生的 API 失败和未知消耗也另报；工具复评不是新增 victim 采样。入围后每候选的采样安排和预算不足处理提前声明，不按已看到的高低分任意追加。

## 4. 相对 clean-fewshot 的功能约束

研究选择是：候选相对 clean-fewshot 的功能表现满足预定退化限制后，再比较模式与指定检测表现。约束对象是 victim 训练输出，不是示例准入；二者分别记录。

约束统计量至少需要以下明示配置：

| 项目 | 待确定内容 |
| --- | --- |
| clean-fewshot | 原始 clean 代码与 CoT，不向示例题面、CoT 或查询注入 trigger；具体资产与渲染身份、采样量和可复用范围待定 |
| 比较范围 | 逐题都满足还是总体约束；逐题统计始终保留 |
| 允许退化 | 差值或其他具体口径与阈值，不默认零退化或任意百分比 |
| 随机不确定性 | 采用何种估计/判定方式、样本量与覆盖要求，不现场选有利算法 |
| 证据来源 | 用复测、搜索还是预定组合；参照与候选使用一致评价版本 |

clean-fewshot 不能被 clean-0shot 或攻击起点替代。clean 接近零时不通过率相除；参照缺失或不可比时，约束状态未知，不能默认候选满足。缺失功能结果不自动记为失败，但也不算通过约束；任务本身的真实功能失败仍原样计数。

程序将单候选约束判为满足、不满足或未知，保留逐题计数和原因。具体覆盖不足怎样处理需在运行前确定，不能利用少量完成项的高通过率过门。全部候选明确不满足时才可据此报告无可行候选；若尚有未知且不足以作出选择，应记录证据不足，不把“未观察到满足”写成“已证明全部不满足”。不依据最终测试或候选表现事后放宽阈值。

## 5. 在可行候选中选择

模式与指定检测是研究主要对象，但尚未确定最终主指标、聚合方式和并列规则。本模块提供按规则过滤与选择的接口，不用旧 runtime 的 H 排名填空，也不临时把功能改成联合目标。

仍分别报告 H、H∧¬D、F、H∧F、H∧F∧¬D。每个指标有自身定义域和覆盖，SAST 超时没有 ¬D，oracle 无判定不算普通 absent。静态命中不等于已验证可利用漏洞。

最终记录应能解释：为什么入围、复测取得什么证据、功能约束如何判、用哪个已定排序规则选中。统计和选择由程序执行，不让模型凭论文叙事选“最有说服力”的候选。

`SelectionResult.status` 采用以下轻量区分，不改变待定的功能或排序公式：

| status | 含义 |
| --- | --- |
| `selected` | 预定判定已结束，证据与规则足以选定一个最终模板 |
| `no_feasible` | 判定已结束，可比较集合中候选均明确不满足可行要求 |
| `undetermined` | 预定步骤已结束，但约束或比较仍未知，证据不足以选定或断言全部不可行 |
| `incomplete` | 预定复测或判定步骤尚未完成，例如暂停、请求未结束或预算不足导致计划未完成 |

后三种状态的最终模板引用为空，分别保留不满足、未知或未完成原因。已有可行候选但部分比较未知时，能否按预定规则作出选择仍由事前确定的证据要求决定，不在此补写默认选择规则。

## 6. 与最终评价、预算和恢复的关系

搜索前从同一方法运行总预算内部预留入围复测额度，不另加免费预算；搜索和检验只能使用分配给它们的可用额度。阶段预留与请求派发时的在途额度是两层记账，均不等于已经发生的消耗。额度及是否允许事前调整分配仍待定。

若预算不足，按复测前既定规则调整尚未冻结的安排，或按实际状态报告未完成；冻结并启动后不能因看到部分成绩而取消剩余复测、事后缩小计划再声称完成。成本按阶段分别列出，方法总预算比较时共同计入，最终评价预算另列。

模板选择模块中断后以 incomplete 保存进度；恢复同一冻结集合、计划与规则，复用已有响应和评价，仅补未完成步骤，再记录实际结果。已完成结果复用；规则或模板变化按前述另开开发 run，不以“保存新版本”为由修改本次已启动复测。最终模板固定后才在其余任务评价，最终结果不再反馈本次选择。

后续实现验证关注：规则与集合在复测前固定、比较使用同题同口径、未知约束不默认为通过、无可行候选合法、旧新证据未混淆、最终任务无反馈。待定参数仍列明，尚不具备启动真实选择的完整配置；本轮不运行复测。
