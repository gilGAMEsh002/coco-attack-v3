# 模块接口与轮次流程

设计整理：GPT / Codex，2026-10-26。

审核清单修订：GPT / Codex，2026-10-27。

接口审阅：DeepSeek-v4.1-flash（OpenCode Go CLI）；采纳与协议整理：GPT / Codex。审阅不代表已运行验收。

状态：新方法接口设计稿，尚未实现。用于约定 候选探索、经验检验与模板选择模块的交接，不建立通用框架。字段名是本方法拟采用的协议，不代表公共服务已支持全部对象。研究边界见[架构总览](迭代方法架构.md)。

## 1. 共同约定

程序分配 run、轮次、候选、样本、指导与检验标识，校验引用是否属于实际输入。模型只填写内容和允许的引用，不制造样本、计数、费用或历史身份。解析失败保留原文和原因，不猜补缺失内容。

研究对象是完整物化模板；模型返回字段补丁。补丁相对固定初始模板应用，公共 `PatchPolicy` 限定示例 2/3/4 的 `code`、`cot`。`code` 保持资产中的字段形态，通常为与固定前缀组装的函数体，不擅自改成整段程序；`cot` 是完整字符串。派生元数据由公共服务重算。

下述对象属于新方法。文件引用用于保存与回查；传给执行模型的是解析后允许的文本，不给它可追溯到原始 victim 输出的读取通道。结构校验不能代替语义可靠性判断。

## 2. 模块交接

| 对象 | 生产者 → 消费者 | 最小内容 |
| --- | --- | --- |
| `RunSpec` | 配置 → 三模块 | 目标定义、clean code/CoT 初始模板、初始假设、四个示例及实际测试、固定任务演示、两道训练题与测试、无 trigger clean 参照、模型、公开 SAST 规则及实际扫描身份、模板来源、预算与明确决策；按角色过滤，不整体提供给生成模型 |
| `RoundInput` | 运行器 → 候选探索与经验检验模块 | 轮次、冻结经验快照、当前指导、待执行检验、候选用途与采样安排 |
| `CandidateDraft` | 执行模型 → 候选探索模块 | `patch`、`victim_learning_goal`；身份和来源由程序附加 |
| `CandidateEvidence` | 候选探索模块 → 经验检验模块/候选记录 | 生成状态与失败阶段、已形成的完整快照（可为空）、已取得的检查/响应/评价、逐题程序统计、失败与缺口 |
| `CandidateReport` | 独立归纳 → 汇总 | 观察、假设、指导修改建议、检验建议、限制与证据引用 |
| `RoundUpdate` | 汇总 → 运行器 | 指导变更、下一轮检验提案、未解决问题；校验和完整保存后发布下一轮经验，下一轮轮初再分配执行预算 |
| `SelectionResult` | 模板选择模块 → 保存/最终评价入口 | 完成状态、搜索结束与规则版本、入围及未入围理由、冻结集合与复测计划/证据、功能约束状态及理由、最终模板或未选出原因、逐题计数/真实分母/覆盖、消耗引用；仅选出模板后进入最终评价 |

未定研究参数显式列为待定，用于真实运行前补齐所涉及步骤的条件，不借用旧 runtime 默认值。配置和提示词副本随 run 保存。

`RunSpec` 中公开规则和实际扫描规则分别可追溯，记录工具版本、规则版本及内容哈希；不能只写工具名却让执行模型看到与实际评价不对应的规则。停止细则包括预算边界及采用的轮数/重试/修复限制，具体值仍待定。

角色输入对齐（GPT / Codex，2026-10-27）：候选生成和独立归纳共享当前 CWE 的目标定义；候选生成按来源仅注入一条 `source_instruction`；统一汇总保留 clean-fewshot 的程序统计及可比性，用于核对功能观察而非承担模板选择模块判定。具体变量与材料粒度见[角色提示词使用说明](../角色提示词模板/角色提示词使用说明.md)。本次不改变下述角色输出字段。

逐句复审后，候选来源标签仅保留在调用元数据与候选记录，不作为候选生成模板变量。独立归纳的辅助任务、测试、规则和 clean 材料按实际阶段准备，未注入原因显式记录，原始证据保留；独立报告只解释本检验臂，统一汇总负责跨臂比较。这些调整不新增角色或改变输出字段。

用户更新：六条初始假设直接写在候选 user.md.j2 的固定列表中，每轮原文不变。新 run 冻结后由同一份原文初始化内部假设与经验 ID；后续经验可修正或撤回其适用性，但不覆盖模板原文。guided 动态块只展示变化；原句不变而范围或把握变化时只发编号及变化，初始撤回也单列编号通知。unguided 仅读固定背景，不接收跨轮变化；归纳侧保留完整历史。

## 3. 候选身份与证据

`source` 由程序指定为 `guided`、`unguided`、`probe`；后者另有 `probe_id`、`arm_key`，成组比较不计为独立探索。来源保留到归纳、预算和选择，不自动成为质量权重。

调用元数据的 `candidate_source` 与候选记录的 `source` 使用相同取值，由程序保持一致。候选生成模板不再接收 `candidate_source` 变量，而由该元数据选择一条固定 `source_instruction`；它不替代按来源过滤实际材料。

`CandidateEvidence` 保存下列内容及其引用：

- `candidate_id`、轮次、来源、`generation_status`、`failure_stage`、调用动作；已形成的完整模板引用 `snapshot_ref`、内容身份、相对初始模板的补丁和 victim_learning_goal。
- `example_checks`：示例编号、语法/入口、固定内容未变、trigger 规则、code/CoT 一致性、无要求后续模仿的显式元指令、功能、oracle、SAST 的分项状态、原因及证据；方法准入决定与理由另列。语义检查承担方式仍待定，不假称公共代码检查服务覆盖全部项目。
- `training_status`：是否采样及未执行原因；计划任务与重复编号、请求尝试、实际响应。
- `sample_evidence`：样本身份、原始响应、提取后代码及身份、oracle 原始状态、指定 SAST 状态、功能结果和各层证据。
- `task_summary`：程序计算的逐题计数、分母、计划数、终态数、覆盖与缺口；实际消耗和重试账目引用。

候选身份在计划动作时分配，不依赖生成成功。`generation_status` 区分未执行、失败、已物化；失败时 `failure_stage` 记录调用、解析、字段校验或物化等实际阶段，未失败时为 null。没有可用快照时 `snapshot_ref`、内容身份及未取得的补丁/学习目标为 null；不以初始模板代替失败候选。未取得的检查和样本数组为空，`training_status` 等保留未执行原因，不将空数组解读为通过、未命中或零成本。

拒答、截断、提取失败及工具故障保留，不能写成普通未命中。`present`、`possibly_present` 分列，H 按协议包括两者。SAST 未完成没有 ¬D。统计只连接同一份代码，不能拼接不同输出的 H、D、F。

## 4. 角色输出约定

外置模板与本节共同维护输出字段；数组可为空，空不代表失败或否定证据。所有 JSON 保持可解析，不将未定项填成模型猜测的数值。

### 候选生成

```json
{
  "patch": [],
  "victim_learning_goal": "期望 victim 从本次修改中学到的实现方式或求解步骤"
}
```

`patch` 各项为 `{"example": 2, "code": "完整替换字段", "cot": "完整替换字段"}`。一例至多一项，仅填写要改的字段。空补丁表示没有改动，不伪装为新候选。

候选协议 egs-candidate-v2 仅含上述两个字段，victim_learning_goal 必须为非空字符串；不再要求或接收旧 rationale/intent/expected_change/uncertainty。程序保存学习目标供归纳分析，仅将 `{"patch": [...]}` 送给现有 parse_sparse_patch 和 apply_patch，不改变公共补丁策略，也不把学习目标当作实际效果。

### 单候选归纳

`CandidateReport` 必含 `candidate_id`、以下四个数组和字符串数组 `limitations`：

| 数组 | 每项字段 |
| --- | --- |
| `observations` | `local_key`、`statement`、`scope`、`evidence_refs` |
| `hypotheses` | `local_key`、`statement`、`scope`、`support_refs`、`counter_refs`、`uncertainty` |
| `guidance_suggestions` | `action`（propose/revise/withdraw/retain）、`guidance_id`（新增为 null）、`statement`、`scope`、`support_refs`、`counter_refs`、`uncertainty` |
| `probe_suggestions` | `question`、`hypothesis_refs`、`candidate_refs`、`fixed_conditions`、`varied_conditions`、`supports_if`、`refutes_if`、`inconclusive_if` |

`local_key` 是本报告内标识，程序在汇总输入中加候选命名空间，避免不同报告的 `h1` 混同。`scope` 为对象，含 `task_ids` 数组和字符串数组 `conditions`、`limits`；不以“所有任务”扩张观测范围。

`probe_suggestions` 是独立归纳对本候选提出的文字比较建议，允许为空；不直接安排采样或决定检验优先级。统一汇总再结合全部报告，将适合细化的问题写成 `next_probes`。

### 统一汇总

`RoundUpdate` 必含 `guidance_updates`、`next_probes`、字符串数组 `unresolved` 和字符串 `summary`：

- `guidance_updates` 每项字段与上述指导建议一致，`action` 使用 add/revise/withdraw/retain；新增 ID 为 null，由程序赋值，既有 ID 必须来自输入。指导是有条件的尝试建议。
- `next_probes` 每项含 `question`、`hypothesis_refs`、`candidate_refs`、`fixed_conditions`、`varied_conditions`、`fixed_fields`、`varied_fields`、`arms`、`supports_if`、`refutes_if`、`inconclusive_if`、`priority_reason`。`arms` 各项为局部 `arm_key`、`change_request`。文字条件说明研究比较，字段约束供程序核对。
- `unresolved` 保留冲突、缺口和不可执行比较；`summary` 简述更新，不输出完整 victim 代码。没有值得检验的判断时 `next_probes` 可为空。

`fixed_conditions`、`varied_conditions`、`supports_if`、`refutes_if`、`inconclusive_if` 均为字符串数组；引用字段为 ID 数组；`question`、`priority_reason`、`change_request` 为字符串。指导筛选与检验采纳的语义规则仍待定，不能把结构校验当作科学认证。

`priority_reason` 保留现有字段名，语义为“这个问题为什么值得检验”的说明，不是执行排序、优先级分数或预算安排。实际检验选择由运行器按事前确定的规则处理，不从该字段名推导默认策略。

`fixed_fields` 各项例如 `{"example": 2, "field": "code", "candidate_ref": "initial_template"}`，表示各臂都必须使用该快照对应字段的值；`candidate_ref` 填输入候选 ID，或以字符串 `initial_template` 引用初始模板。`varied_fields` 各项为 `{"example": 2, "field": "cot"}`，表示本组允许变化的字段。只允许例 2/3/4 的 code/cot；两组字段不得重叠或重复。未列入两组的字段保留初始模板。引用必须能在输入候选快照中解析，不能引用 victim 输出。无法写清比较字段时保留为待细化问题，不批准执行。单候选 `probe_suggestions` 是文字建议，不直接当成可执行计划。

更新按既有快照应用；未提到的旧条目不被推断为撤回。撤回需明确操作，同一指导 ID 不接受冲突操作。指导状态与完整证据记录分开，更新校验完成后整体保存；执行摘要只来自本轮确认保留的当前指导，不能从完整报告自动补回已撤回或待检验内容。

withdraw 操作仍填写完整字段以保持输出形态，记录被撤回陈述、范围及撤回依据；没有反例就说明证据不足，不虚构反证。空更新不默认撤回所有指导。

## 5. 冻结输入与受控比较

所有单候选归纳读取同一轮初经验快照。候选共享模板中固定的六条初始背景；guided 另读有效经验的变化及初始撤回通知，unguided 不读任何跨轮动态，probe 另读选定比较计划、字段和必要假设。固定背景不等于当前有效指导，动态撤回不改写原文，也不将撤回内容重发为有效建议。三者不读 victim 原始输出；unguided 不通过历史计数、例证或共享聊天历史间接接收累积反馈。

检验可以引用本方法过去生成的候选字段作为固定条件。程序先解析为明确值，再从初始模板为每个比较臂应用完整补丁，保证约定字段一致；不会把上一轮冠军自动设为父模板。引用 victim 输出作为候选代码种子不符合信息边界。

经验检验模块在采样前写明支持、反驳和无法判断的条件。提案不等于已安排或已执行检验；保存经验更新不以预算充足为条件。下一轮轮初由运行器按预定选择规则和预算形成执行计划，再由候选探索模块执行。比较臂无法准入，记无法执行，不计反证。不能将下一轮计划回写本轮生成输入或看完结果后换判据。

## 6. 一轮与终局流程

1. 轮初读取已发布经验和检验提案，按预定规则分配本轮预算，选择可执行检验，再固定 `RoundInput`：经验版本、用途和采样安排、执行计划、可用预算。首轮只有六条初始假设，检验列表可为空；未安排的提案保留未执行状态。
2. 候选探索模块按用途调用、物化和检查；普通候选独立生成，检验臂按共同条件分别构造。失败也进入候选清单。
3. 合格候选在预算内采样、评价；经验检验模块对已就绪候选独立归纳，不读同轮其他报告。
4. 计划候选均有结果或未执行原因，所需报告齐备后统一汇总。程序校验引用和统计，完整保存 `RoundUpdate` 与新经验快照后发布下一轮指导及检验提案；此时不要求已分配下一轮采样预算。
5. 继续搜索仍从初始模板出发；搜索结束后模板选择模块冻结入围模板并复测，按已定规则选择，最终评价另存。

完成次序与 worker 数不改变经验更新时点。已撤回指导和旧版本留在记录中，不继续作为当前指导。未完成归纳或汇总时不静默跳过并开启下一轮。

`SelectionResult.status` 区分 `selected`（规则允许据现有证据选定模板）、`no_feasible`（判定已结束，候选明确均不满足可行要求）、`undetermined`（预定步骤已结束，但约束或比较仍未知，证据不足以决定）和 `incomplete`（预定复测或判定尚未完成）。非 selected 的最终模板为空，并保留原因；未知不能写成已证实全部不可行，未完成也不冒充已完成的未选出结果。详细语义见[模板选择模块模块设计](复测驱动的模板选择/模板选择模块设计.md)。

## 7. 预算、进度与恢复

参照、探索、检验、复测都属于同一方法运行总预算，阶段成本分别报告；最终评价预算按统一协议单列。入围复测的预留是总预算内部的阶段额度，不是额外预算，搜索/检验并发不能把这部分当作可用搜索额度。额度和是否允许事前调整分配仍待定。派发时还要从对应阶段可用额度预留在途请求，两种预留分别记录，不能混为新增消耗。

成功响应、终态失败、API 尝试/重试、缓存引用、未知 token/费用分开记账。外部请求未落盘可能已经执行，不能保证调用恰好一次，也不能把成功响应数称为全部消耗。

状态摘要显示轮次和步骤、候选用途、计划/终态/失败采样数、覆盖、在途额度、预算、最近错误；原始产物为准。暂停停止派发，已有结果尽可能落盘；恢复使用 run 配置、提示词和经验副本：有响应补评价，有评价补归纳，有报告补汇总。汇总未完整保存前不发布下一轮；结果未知的请求按明确重试策略处理并保留未知尝试。

研究提示词或条件改变用新 run。恢复不读外部新模板，不因归纳中断重复 victim 采样。模板选择模块按 status 保存选出、明确不可行、证据不足或未完成，不借最终测试改选或放宽约束。模板选择模块结果若用于修改模板或规则，应另开开发 run 并披露已使用的反馈，不回流到已结束的本次搜索。

## 9. 一轮交接的假想走查

以下只说明接口关系，不是实验记录，不预设候选数或成功率。

1. 某轮冻结本轮入口经验。一个 guided 候选读取当前指导，一个 unguided 候选不读累积材料；它们都从初始模板物化，实际同类可有更多候选，数量待定。
