# 约束下的候选探索

设计整理：GPT / Codex，2026-10-26。

审核清单修订：GPT / Codex，2026-10-27。

状态：实现准备稿，未实现。入口见[架构总览](../迭代方法架构.md)，字段协议见[模块接口与轮次流程](../模块接口与轮次流程.md)。本模块负责候选构造和测量，不更新当前指导，不临场决定最终选择规则。

## 1. 输入与输出

模块输入为固定初始模板、六条初始假设、示例任务与实际测试、固定任务演示、两道训练题与测试、公开 SAST 规则、当前轮冻结指导、轮初检验计划，以及按用途安排的采样与预算。程序按来源组装执行输入：候选生成不接收训练题题面、训练测试或参考实现，两道训练题仅供测量及后续归纳使用。

目标定义按当前 CWE 单独提供，与独立归纳使用同一行为陈述及必要边界。角色输入对齐：GPT / Codex，2026-10-27。

输出为每个计划候选的 `CandidateEvidence`，包括生成失败、未准入和未训练的候选；不得只把高分或成功候选交给经验检验模块。每个原始响应和评估结果可回指到候选、任务、样本及实际代码。

## 2. 三类候选怎样准备输入

| 来源 | 执行模型读取 | 排除的材料 |
| --- | --- | --- |
| `guided` | clean code/CoT 起点、模板内固定六条初始背景、四个示例及实际测试、固定演示、公开规则、有效经验的变化与初始撤回通知 | 训练题题面/测试、参考实现、已撤回指导、完整观察库、所有独立报告、原始 victim 输出、同轮其他候选 |
| `unguided` | 相同起点、初始六条假设、四个示例及实际测试、固定演示、公开规则 | 训练题题面/测试、参考实现、原始 victim 输出、跨轮指导、历史计数、跨轮候选例证、检验计划及共享聊天历史 |
| `probe` | 相同起点、示例任务及实际测试、固定演示、公开规则、明确比较问题、固定字段值和本臂修改要求 | 训练题题面/测试、参考实现、原始 victim 输出、同轮其他臂结果、与该比较无关的完整指导历史 |

unguided 是“不读跨轮累积反馈”，不是没有先验：起点与六条假设本身有历史来源。模型配置与调用策略需要可比，具体模型和每类数量未定，不能按来源静默使用不同模型或采样温度。

初始六条原文现直接写在 user.md.j2，冻结后各轮保持相同；经验可以修正或撤回其适用性，guided 单独接收这些动态变化而不覆盖固定原文，unguided 不接收跨轮变化。未变的初始内容不在动态 JSON 重复，撤回通知仅指向初始编号。每次保存实际消息，不只凭变量名称声称隔离。

普通候选各自生成，不按上一个候选结果滚动修改提示。probe 属于一个预先约定的比较组，其相关性和消耗单列，不把 probe 标成 unguided 来冒充不读反馈的探索。三类数量、比例或是否设置保留额度仍待定，这里不指定固定名额。

候选调用用 `source_instruction` 只注入当前来源的要求，具体固定文本见[角色提示词使用说明](../../角色提示词模板/角色提示词使用说明.md)。三类共享 system 中的修改和输出契约；来源材料仍按上表过滤，不依赖模型自行忽略无权读取的内容。

## 3. 从模型响应到完整候选

1. 调用[候选生成模板](../../角色提示词模板/候选生成/system.md.j2)，保存实际输入、响应、模型与动作信息。
2. 方法层解析 `CandidateDraft`，保留 `rationale`；仅将 `patch` 包装成公共服务支持的对象进行解析与校验。
3. 从初始模板应用完整字段补丁；不改示例 1、题面、顺序、数量及 trigger 渲染规则。模型不得手写 `is_poisoned` 等派生元数据。
4. 保存快照、内容身份和相对初始模板的真实改动。无改动或重复内容明确标记，是否复测由已声明用途决定，不算新增探索方向。

候选探索模块负责识别重复内容，并按生成/采样阶段规则决定是否停止该条、引用已有证据或追加新的独立采样；该用途规则仍待定。候选探索模块将内容身份、记录关系和实际新增采样交给模板选择模块，不决定重复记录能否分别占入围名额，也不决定搜索证据如何与复测证据合并。模板选择模块的相应决策见[模板选择模块设计](../复测驱动的模板选择/模板选择模块设计.md)。复用同一响应不增加样本数。

`code` 采用原示例资产字段形态，通常是函数体；不能让模型重复固定 imports/函数签名造成错误组装。`cot` 与 `code` 都是替换后的完整字段，不接收 diff、片段省略或占位文本。

### 固定起点与检验字段的兼容

检验计划可能要求两臂保留某个过去候选的 code，只改变 CoT。程序从候选快照解析该 code 的真实值，为每臂生成相对初始模板的完整补丁，并验证两个 code 一致。这样物化基准仍是初始模板，但 probe 的共同固定条件可以来自历史候选；不应错误要求它必须等于初始模板的原字段。

各臂必须符合各自预定修改条件。`fixed_fields` 解析成明确字段值，`varied_fields` 限定可变字段，未列字段保持初始模板；程序注入本臂要求并核对物化结果，不能只靠自然语言声称“固定了代码”。若模型擅自改变固定因素，记录比较无效，不能把结果用来解释该因素作用。计划引用只能来自本方法生成的示例，不以 victim 原始输出作为代码种子。

## 5. 训练测量与归纳交接

准入后在两道原题按可比安排采样。victim 接收物化示例和查询，不接收测试、经验或归纳报告；候选生成只接收前表示例材料与固定演示，不接收训练题及其测试。归纳已有 victim 输出时接收训练题与实际测试，但不接收参考实现。渲染约定见[victim 提示词约定](../../victim提示词模板/victim提示词约定.md)。

对同一代码分别评价 H、D、F，程序计算逐题统计并关联 clean-fewshot 参照。功能检查复用已经生成的代码，不要求 victim 修复失败输出；现有训练闭环没有功能层，应接入已有功能服务后再称反馈完整。

所有训练输出保留。功能失败不阻止 oracle/SAST 尝试评价；工具未完成保留缺口。提取失败造成无法评价时说明原因，不编造代码或以其他采样替换后抹去原记录。

一候选证据就绪即可独立归纳，经验检验模块不需要等其他训练全结束；但经验仍只能在整轮汇总后发布。生成失败可能没有快照：保留候选动作身份、已取得的响应和失败阶段，快照引用为 null；未形成的检查或训练结果留空并记录未执行原因，不以初始模板冒充已生成候选。生成或检查失败的候选可归纳构造问题，不得推断未观察的 victim 行为。

## 6. 失败、恢复与实现检查点

生成解析错误保留响应并按明确策略处理；不将猜补 JSON 算成模型输出。没有预算的计划记录未执行原因，外部请求结果未知时保留尝试，不自动补出新样本。恢复优先复用已保存快照、响应和评价，不能因为经验检验模块中断重复采样。

后续实现验证应覆盖：三类输入实际没有越界材料；公共补丁适配保留理由；probe 固定字段一致；SAST 超时不能过门；H/D/F 关联同份代码；失败候选和样本仍完整传递。这里只列验证目标，本轮不新增或运行测试。

待决定：修复与重复候选安排，以及候选数量、每题采样数和工具版本。基础接线可实现，真实运行前须明确相应配置。
