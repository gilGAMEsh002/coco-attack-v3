## 1. 输入、输出与经验内容

输入为目标定义、本轮冻结经验、各候选完整证据、公开任务与规则、可比 clean-fewshot 参照和已执行检验的计划。所有独立归纳使用同一入口经验，但只看本候选，不看同轮其他报告。

输出分两步：每候选 `CandidateReport`，以及统一汇总的 `RoundUpdate`。后者包含指导变更和下一轮检验提案；经过方法校验并完整保存后发布新经验快照，发布不以下一轮预算是否充足为前置条件。下一轮轮初再由运行器分配预算、选择执行提案并冻结 `RoundInput`；未获安排的提案保留为未执行，不在归纳调用中直接生成或采样候选。

| 内容 | 需要回答的问题 | 对执行模型的影响 |
| --- | --- | --- |
| 观察 | 在哪道题、哪个样本或示例，实际发生什么？ | 原始记录保留，不默认整库传入 |
| 待检验假设 | 可能怎样解释，还有哪些替代解释？ | 可以转为特定 probe 问题，不直接推广给所有候选 |
| 当前指导 | 目前在哪些条件下值得尝试什么？ | 过滤后供 guided 使用，可以修订或撤回 |

六条初始经验是初始假设，既有历史依据不等于新设置验证。指导不用“已证明”“必然有效”等措辞，不要求复制成功样本。记录持续保存，当前指导不必单调增加。

程序在初始经验为六条初始假设建立可追踪 ID，仍标明初始假设性质。修订或撤回后，guided 的初始条目视图随之更新，不通过固定前缀重新注入旧指导。unguided 的起始六条保持不变，也不读取修改状态；其用途正是不依赖累积反馈。

## 2. 单候选独立归纳

调用[独立归纳模板](../../角色提示词模板/独立归纳/system.md.j2)，实际注入本候选已取得的快照与改动、生成理由、示例检查、原始 victim 输出、程序统计及各层证据。生成失败可能没有快照或理由，按 `failure_stage` 与空引用解释可见范围，不据初始模板猜造生成结果。训练测试和 clean 参照在训练输出分析时提供；无训练输出时不默认注入无关正文。最终评估任务和结果不可见。

同时注入与候选生成一致的 `target_definition`，供解释目标模式和实现改写；它不替代 oracle 的实际评价。辅助规则和测试按候选所在阶段、相关任务及规则 ID 组装，保留解释功能失败所需的断言、fixture 和 mock；任务上下文通过字段白名单，不注入 canonical_solution 参考实现或 raw_test 原始测试副本，实际测试保留在 test。省略内容及原因显式记录，具体粒度见[使用说明](../../角色提示词模板/角色提示词使用说明.md)。输入组装使用已有状态与固定规则，不增加材料筛选模型，也不按结果好坏裁剪样本证据。

分析按以下顺序展开：

1. 区分生成/构造失败、未准入、已采样、评估缺口，限定本候选能支持的判断。
2. 说明 victim 保留、改写或替换了什么实现，以及这些解释所对应的证据；不以模型解释覆盖 oracle 或 SAST 状态。
3. 逐题观察 H、D、F 及联合情况，保留 present/possibly_present 与未知明细，不重算或改写程序给出的分母。
4. 描述功能失败与任务要求的联系，参考 clean-fewshot 的逐题事实；相近通过率不能证明原因相同，clean 很低时不用比例相除。
5. 提出对既有指导的保留、修订、撤回或新增建议，记录支持与反例；多项同时改动先解释整份候选，不自动归给某句话。

报告必填数组 `probe_suggestions` 用于提出本候选引出的比较问题、固定/变化条件及支持、反驳、无法判断的观察条件；没有合适问题时为空。它是候选层建议，不决定检验优先级、不占用预算，也不直接成为候选探索模块执行计划；统一汇总再核对并细化为 `next_probes`。

对本轮已执行 probe，独立归纳只读取本臂预定条件及相关假设，说明条件是否满足和实际观察；不注入同轮其他臂结果，不在独立报告中判定整组比较支持或反驳假设。统一汇总收到各臂报告后再形成跨臂结论。

无训练输出时只分析示例构造，不将“未采样”写成 victim 不采用。缺失证据可以产生问题，不能产生肯定效果。报告中的 `local_key` 由程序加候选命名空间后再供汇总引用。

## 3. 统一过滤与指导更新

全部候选有明确结果且所需报告就绪后，调用[统一汇总模板](../../角色提示词模板/统一汇总/system.md.j2)。输入共同入口经验、全部独立报告、程序统计、clean-fewshot 的逐题统计及可比性说明、已执行检验的计划与完成状态、证据索引；需要回查证据由程序显式提供，不假设模型能从路径自行读取。候选失败和冲突不能因“没有启发”被静默遗漏。

clean 输入用于核对跨报告的功能观察和解释范围，不重算功能退化阈值或输出候选可行性决定。参照缺失或不可比时保留原因；默认不重复注入 clean 原始响应，必要原文由显式摘录提供。最终选择仍由模板选择模块负责。

汇总先比较任务条件，再整合相近建议。两题支持可扩大已观察范围，但仍不能称为普遍结论；多个报告引用同一输出，不增加支持样本。来源 guided/unguided/probe 保留用于分析，不当成质量标签。

过滤关心：建议与下一步修改是否相关、支持来自什么、是否有反例、是否依赖某道题或某个实现、是否过于具体而只是在复述样本。可以保留有探索价值但证据有限的方向，只要明确其假设地位；不能把“允许试一试”等同“已经验证可靠”。具体筛选、压缩和条目数量规则待定，不引入虚构置信分数。

更新动作使用 add/revise/withdraw/retain。既有条目保持可追踪 ID，新条目由程序赋 ID；撤回只退出当前指导，旧版本和证据保留。`unresolved` 保留冲突、任务差异、评价缺口和解释局限。

程序核对结构、引用与计数，不自行声称能认证语义；结构不合法或引用不存在时保留原输出，按显式调用重试或人工处理策略恢复。不得因解析失败自动接受部分建议。

## 4. 检验计划怎样形成与执行

检验选择准则仍待定。供讨论的考虑因素包括：判断是否会反复影响后续候选、已有证据是否矛盾、是否难以区分 code/CoT 作用；这些例子不是已确认的优先顺序、自动评分或预算分配规则。汇总仅提出提案，运行器在下一轮按预定规则选择执行；预算不足时记录未安排，不为配额虚构问题。

计划在采样前写清：问题和关联假设、可引用候选、哪些字段固定、哪些因素变化、各臂要求、支持/反驳/无法判断的条件，以及检验价值说明 `priority_reason`。该字段解释为什么值得检验，不输出执行排序或预算安排。固定字段用 `fixed_fields` 指明候选快照和字段，允许变化的字段用 `varied_fields` 列明；文字比较条件不能代替程序约束。支持条件应对应可观察差异，不写成“模型认为更好”；数值阈值未约定时，不让归纳模型现场发明。

例如比较解释组织时，可要求各臂采用同一已保存候选的 code，分别替换约定的 CoT。候选探索模块从初始模板物化每臂，校验固定条件；经验检验模块不直接把候选设为下一轮父模板。计划只包含本方法的候选示例，不向执行模型复制 victim 代码。

在下一轮执行后，各臂独立归纳，统一汇总再结合整组结果审视假设。若某臂未准入、测量缺口太大或比较因素未保持，记无法判断或无法执行，不记反证。不能看到结果后改换判据，把一切现象解释成支持。

## 5. 执行输入过滤与例证

guided 只接收选定的当前指导（含仍有效且选入本次输入的初始条目）及必要限定，不接收整个观察/假设库或全部报告。初始条目与新增指导可分变量注入，但共同遵守筛选、修订和撤回规则。probe 只接收比较相关的计划、假设和固定字段。unguided 不接收原始 victim 输出、跨轮指导、计数、例证、检验计划或共享对话历史；它仍可读固定初始假设。

完整证据保存在归纳侧；执行输入可回指证据编号，但不提供原始 victim 文本或可读取其路径。定向检验解决一个特定问题，不应让该假设成为所有普通候选的通用要求。

是否用本方法生成过的示例片段补充文字指导尚待确认。若启用，需包括条件、支持与反例，保留候选出处，不能取自 victim 输出；不读累积经验的来源依然不接收。

## 6. 轮末发布与恢复

独立归纳可并行，共同本轮入口经验不变；统一汇总之后保存完整 `RoundUpdate` 与下一轮经验，才可用于下一轮。轮内产生的建议不能提前影响仍在生成的候选。全轮失败也需保留原因；是否继续和是否消耗轮数由停止规则声明，不从失败自动得出新指导。

独立归纳中断时复用已有评价，汇总中断时复用独立报告，不重跑 victim。已有完整发布结果就复用，不为 resume 再创造一版新经验。若预算不支持下一轮检验，记录未执行，不能当作已通过。

后续实现验证关注：同轮报告隔离、初始/当前材料版本、指导过滤、证据引用、撤回保留历史、计划下一轮生效、无法执行不计反证。具体指导筛选准则、检验选择准则与预算、例证表示仍待决定；本轮只完成接口和流程准备。
