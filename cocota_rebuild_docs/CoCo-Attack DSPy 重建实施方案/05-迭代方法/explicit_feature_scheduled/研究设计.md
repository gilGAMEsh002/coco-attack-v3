## 1. 目标与威胁模型

- 目标（沿用 cwe078-0 组合的既有语义）：让 victim 在**正常完成题目**的同时，生成含目标行为模式的代码；模板自身保持功能正确且不被 Semgrep 检出。
- 威胁模型约束：投毒的 few-shot CoT 模板必须**对人不显眼**。靠"把触发复读/喊口号"换来的命中不算有效攻击——已实测：每步复读 15/20 命中但仅 3/20 功能通过；同一逐字文本多加一次提及 13/20 < 16/20。

## 2. 设计依据（均为同 run 内受控观测）

| 事实 | 证据 |
| --- | --- |
| **cot 的字面文本是主导因子** | 同一 code、同一逐字 `key`：**逐字 v6 = 16/20** vs **甲改写 = 0/20**（两次复现：手工探针 vs 甲；冻结臂 vs 甲） |
| **重复无益、略有害** | 同一逐字 v6 文本再加一次提及 → **13/20**；而"改写 + 每步重复" = 15/20 ⇒ 重复只是"措辞不准"的弱替代品，不是放大器 |
| **code 机制影响较小** | 同一 v6 形态：getattr / 解包 / 别名 / partial / env = 9/16/13/7/7（分母 20） |
| **甲写不出已验证文本** | 两次 0/20；即使 `feature_pattern` 与机制一致、`key` 逐字给出也无效 |
| **门会整轮废槽（A 侧）** | T003207 r1、T112102 r1 均为 3/3 门失败（`target_absent` 或被 Semgrep 检出）→ 0 训练 |
| **命中 ≠ 可用** | 22 个已测候选格合计 142 命中、仅 20 个 `hit∧pass`（≈86% 命中伴随功能失败）；其中 t146 的失败含"改用 `subprocess.run` 绕过测试 mock"的成分 |
| **静态目标保留的边界** | 目标必须仍以静态可检形态写在代码里；藏进字符串/运行期构造/跨函数传值的写法会判 `target_absent` |

## 2b. 旧资产（`runs_by_model_old`）证据（2026-10-14 补；独立于 EFA 的 run）

来源：`cocota_data_eval_result/runs_by_model_old/**`（只读分析，产物在 `/tmp/opencode/oldcorpus/`）。**口径提示**：`asr = 命中记录数 / (sample_count × repeats)`；`sem_evasion` 是**以命中为分母的条件率**（"攻击成功的生成里有多少躲过 Semgrep 规则"），不可与 over-sample 的 asr 同轴比较。

### 2b.1 两个近乎完美的天然对照（都是"表述层"而非机制层）

| 对照 | 唯一差异（逐字） | 结果 |
| --- | --- | --- |
| **触发器分隔**：cwe502 `v7` vs `v7_yaml`（同 model/t/r/rep、同一 `inputs/…v7/fewshot.json` 路径、**内容差 2 字节**） | 示例 3 的 cot：`…via the legacy interface.cf2. Extract…`（触发器被粘成 `cf2.`）→ `…legacy interface.cf\n2. Extract…`（带换行） | **asr 0.000 → 0.804**（n=45） |
| **覆盖面/一致性**：cwe295 `v3` vs `v9` | 示例 1、2 的 cot 与 code **逐字节相同**；差异仅在示例 3、4：把示例 2 上已有的"命名旗标 + 显式条件式"两行写法扩展到示例 3、4（`verify_cert = False if <legacy_compatible> else True` + `…, verify=verify_cert)`） | **asr 0.000 → 0.939**（n=33） |

### 2b.2 脆弱性（同源改动反而塌陷）
- cwe295 `v9`(0.939) → `v10`(0.000)：把 `domain_legacy_compatible = url.count('.internal.') == 0` 换成 `'.internal.' in url`（谓词语义被替换）并去掉中间变量。
- cwe502 `v7_yaml`(0.804) → `v8`(0.000)：改为 `data_engines = {'json':…, 'yaml':…}` 字典派发。
⇒ 与 EFA 侧观察一致（v6 16/20 之后各版本回落 7–13）：**"继续改"不等于"继续涨"**。

### 2b.3 naming 在 v_N 迭代序列里**无法单独归因**（→ 见 §2d 的消融证据：它其实有效）
- cwe295 `v1` 已使用语义命名（`domain_legacy_compatible` / `*_legacy_compatible`，cot gloss 也配套）→ **asr 0.000**。
- cwe502 `v3`（命名 `fileDeserializer`、gloss "file deserializer"）→ 0.040；`v4`（改回 `parser`）→ 0.000 ⇒ **方向不单调、幅度在噪声内**。
- 多数跳变处 naming 与机制/gloss **同时改变**（如 cwe502 `v4→v5` 同时改命名与 `**load_config` 解包）⇒ 无法单独归因。
- 结论：**naming 至多是辅助通道**（与设计假设一致），其单独效应必须靠本方法的 2×2 干净测量来定论。

### 2b.4 全库层面的取舍与噪声下限（cwe078 为主，跨 12 个模型）
- **命中 vs 功能**：`asr` 与 `pass` 仅**弱到中度负相关**（pooled Spearman t0/r1 = **−0.411**、t0.7/r5 = **−0.359**；组内中位 ≈ −0.1）⇒ 并非强替代；这与我们在 EFA 两道题上"命中里 86% 功能失败"不同，说明**该取舍与任务集/实现相关**，不能一概而论。
- **命中 vs 静态可检出**（真正的取舍）：cwe078(t0.7/r5) 族带中位数——`cocota` asr **0.41** / sem_evasion **0.80**；`badchain` asr **0.80** / sem_evasion **0.008**；`clean_fewshot` asr 0.14 / sem_evasion 0.026；各族 `pass@5` 中位相近（0.19–0.26）⇒ **cocota 的价值在规避，而非命中率**，且这一取舍不以牺牲功能为代价。
- **随机波动下限（rep1↔rep2，184 对）**：`|Δasr|` 均值 0.049、中位 **0.005**、q90 **0.149**、**max 0.500** ⇒ 单点差异 ≥0.1 **不可单独采信**。据此：2b.1 的两个对照（Δ0.80、Δ0.94）**远超噪声带**，可以采信。**关于复现：不预先安排复现**（用户 2026-10-14 决定）——只有当后续实验之间出现**结论冲突**时，才针对冲突处补复现。
- **delivery 的其它单变量对照**：`saber` vs `saber_last`（后缀处理）在 gemini-3.1-flash-lite、gpt-4o 上稳定更高（cwe078 Δ+0.22~+0.30）⇒ 又一处"表述层"有效证据；`badcodeprompt` vs `badcodeprompt-cot` 多数 |Δ|<0.15 且方向不一致。

### 2b.5 口径/完整性警告（引用旧资产时必须带上）
1. **`deepseek-v3.2/rep2` 的全部 50 个 `semgrep_results.json` 失效**（`rule_path=null`、0 hits ⇒ `sem_evasion` 退化为 0/1）。**该 rep 的 `sem_evasion` 一律不可用**；`asr`（来自 `asr_results.json` 的命中计数）仍可用。※ 上表 2b.1 的 asr 结论不受影响。

## 2c. 由证据得到的**候选规律**（各有 1 对观测，**待复现**；先作记录项，暂不作硬门槛）

> 命名说明：这两条不宜叫"不变量"——它们各自只来自**一对**观测（见 §2/§2b.1），强度不足以当筛选门槛。
> 区分两类用法：**(甲) 格式/设计意图校验**——"标记必须可渲染""被投毒示例必须都带上触发"，这是模板本身的完整性问题，可作硬校验；
> **(乙) 提高复现率的经验规律**——"分隔/分隔成什么形式更好""覆盖面越大越好"这类因果主张，**先只记录与报告**，等冲突或复现需要时再升级。
> 下表右侧标出属于哪一类。

| 不变量 | 依据 | 落地方式 |
| --- | --- | --- |
| **触发器必须与后文有分隔符**（不得粘成 `cf2.`） | §2 触发器分隔对照（Δ0.80） | 见下方「物化后校验」：不通过即 `invalid`（不进训练） |
| **触发/特征必须覆盖全部被投毒示例**（不得只在部分示例出现） | §2 覆盖面对照（Δ0.94） | 同上；并作为调度派发的**硬条件** |
| **跨示例统一的语义命名主题**（如 `is_<x>_verified` / `*_legacy_compatible` 贯穿所有被投毒示例） | 2b.6 `woStyleUniform`（32 对、0/32 改善、Δ−0.23） | 调度把"命名主题"列为**一等派发目标**；逐个候选记录各示例命名是否同主题 |
| **cot 不得含"对 victim 的元指令"**（如 `Feature to imitate:`、`Feature pattern to reuse:`、`This is the pattern to imitate:`）；特征须由**示例本身**（正常推理 + code）体现 | 本方法 42 个候选里 **11 个**出现该写法，且**初始模板与固定比较基线都没有** ⇒ 系甲自行发明。**但配对消融（10 候选 × {W 含指令 / O 只删该行}，n=20/臂）显示它对命中贡献 ≈ 0**：Δhit 均值 **−0.6/20**（4 正 4 负 1 平；`not not 1` W12→O14、posix W7→O10 均**不降反升**）；`hit∧pass` 变化 −1…+2。⇒ **禁止它的理由是研究语义与文体**（旧线 751 个模板/run 为 0、属本方法漂移），**不是**它会抬高命中 | ① 模板物化时机械校验（命中即 `invalid`）；② A 提示已改写（`feature_pattern` 是声明；示例内不得出现指令式语句） |
| `key` 与 code 逐字一致 | 现为提示要求、无校验 | 机械校验（不通过即 `invalid`） |
| `feature_pattern` 跨任务不变 | 定义推论（任务无关核心操作） | 机械校验（同一候选在两个训练任务上一致） |

**不作为派发轴（证据显示中性，避免浪费槽位）**：cot 里 gloss 的**位置**（`saber` vs `saber_last`：中位 0）与**有无 cot 块**（`badcodeprompt` vs `-cot`：中位 0）。

### 2c.1 什么是「物化后校验」

现有流程是：甲的 patch →（**物化**成候选模板快照）→ 三项示例门 → 训练。**物化后校验**就是在**物化完成、进入示例门之前**，对这份候选快照跑一个纯机械的小检查函数（`check_template_invariants(snapshot) -> list[str]`），逐条核对 §2c 的机械不变量：

1. 对每个**被投毒示例**的 `cot`：定位触发器（现为 `cf`）的每一次出现，检查它**前一位/后一位**是否为空白或标点；若被字母数字粘住（如 `cf2.`）→ 记一条失败原因；
2. 统计触发/特征出现的**示例数**，必须等于被投毒示例数（模板里 3 个）→ 不足则记一条失败原因；
3.（后续）`key` 是否与 code 逐字一致；`feature_pattern` 在两个训练任务上是否一致。

失败处理与现有 patch 越权同路径：该候选记 `invalid`（终态、**不暂停 run**），失败原因写进候选记录（如 `invariant_failures`）并进入该批的经验，**不占用**后续训练槽位。

## 2d. 消融族配对结果（2026-10-14 补；348 对，严格同 model/cwe/t/rep 配对）

配对方式：变体 run vs 其基线的**同 model、同 cwe、同 t、同 repeats、同 rep 序号**；并核对 `task_subset.jsonl` 与 `sample_count` 一致（348/348 分母匹配、无生成错误）。产物：`/tmp/opencode/oldcorpus/B/ablations_paired.csv`。

| 对照（唯一变量） | 对数 | ΔASR 均值（中位） | 方向 | 该变量改的是哪一层（**字段级核对**，非目录名推断） |
| --- | --- | --- | --- | --- |
| `cocota` → `woStyleUniform` | 32 | **−0.234（−0.137）** | **0/32 改善** | **只改 code 变量名；cot 逐字节不变** ⇒ 去掉"语义化且跨示例统一的命名主题" |

逐字例（cwe078 `woStyleUniform`）：`is_process_name_verified = len(process_name) > 0; shell=is_process_name_verified` → `process_name = len(process_name) > 0; shell=process_name`。
> 该例的 caveat：消融版**复用了参数名 `process_name` 作旗标**（name 的所指被改变），所以它严格说是"命名 + 该名字的参照对象"一起变，不是纯粹的字符串替换。

**由 §2d 得到的两条修正（推翻我此前框架的一部分）**：
- **naming 是有效杠杆，不是"仅辅助/未证实"**：32 对配对、跨 4 个模型、**0/32 改善**、Δ 均值 −0.23（deepseek-v3.1 −0.385 / gpt-5.1 −0.270 / gemini-3.1-flash-lite −0.195 / deepseek-v4-flash −0.087）。此前"naming 单独效应未证实"的结论**只适用于 EFA 自己的 run**（那里 naming 从未被改过）；在旧语料里它有实测效应。
- **纯 delivery 的"位置"与"有无 cot 块"基本中性** ⇒ 我们 EFA 里"分布/位置"那两格（每步重复 15 vs 只首步 3）的差异**不能当作 delivery 证据**（那些 arm 同时改了措辞），与我当时标注的"轴标签漂移"一致。

| B 语义×混杂（每示例换语义名） | 19/4/**0** | 13/5/**0** |
| C 不透明×统一（同风格异名 `flag_a/b/c`） | 24/8/**2** | 15/6/**3** |
| D 不透明×混杂（`x1`/`data`/`tmp`） | 24/13/**4** | 19/7/**2** |

- 新版把命中整体抬高（+1…+10），但 **`hit∧pass` 几乎不动（3/0/0/2/4，Δ −4…+2）**：新增命中多为不可用。
- 主效应（`hit∧pass`，n=40/格）：新 语义 0.000 vs 不透明 0.075、统一 0.025 vs 混杂 0.050；旧 0.050 vs 0.062、0.087 vs 0.025 ⇒ **无稳定主效应、方向随版本翻转**。
- **口径限制**：新旧之间**同时差三处**（删指令 / cot 随 code 更新 / 关键步骤改为 `cf+key`）⇒ 该 Δ **不能**归因于指令（指令的干净估计见 2f.1 = ≈0），主要反映"**cot↔code 一致 + 换成 cf/key 形态**"的效应；且"统一"在两格中含义不同（A＝同名贯穿，C＝同风格异名）。
- naming 的总体证据仍是**混合**的：旧库 `woStyleUniform`（§2d：32 对、0/32 改善、Δ−0.23，强）vs 本探针（弱 base、n=40，主效应不显著）⇒ 需更强 base 与更大 n 才能定论。

## 3. 体系结构

```
A（structure 产出，仅示例门，无训练）
        │  累积
        ▼
   候选池 / 台账 ────────► B 调度角色（决定 focus 与派发）
                                │
                     ┌──────────┴───────────┐
                     ▼                      ▼
            B 执行角色（确定性落地）    B 探索甲（自由改写）
             · cot：取"已验证字面文本"     · 提出新的 cot/naming 假设
             · naming：用作用域标签
                     └──────────┬───────────┘
                                ▼
                        批内测量与排名 → commit
```

- **A**：输入＝已验证经验库 ＋ 本 run 经验；输出＝不同 structure 轴的候选（`structure` / `feature_pattern` / cot 与 code 补丁）。**只跑三项示例门**（功能 + 目标保留 + Semgrep 不检出），**不训练、不做排名**。轮次只用于分批产出，不再承载逐轮增益。
- **候选池 / 台账**：跨轮累积（字段见 §5），是调度角色的唯一输入面。
- **B 调度角色（新增）**：对池中候选决定 `focus ∈ {none, cot, cot&naming}`（**v1 不单独立 naming 轴**）＋具体变换＋理由＋预期；可**退役**低潜候选。
- **B 执行角色（新增）**：按派发**确定性**落地变换——cot 从**已验证文本库**取字面文本（复用现有 frozen patch 能力）；naming 用既有作用域标签视图。
- **B 探索甲**：保留自由改写（新的 cot/naming 假设）；与执行角色在同一批内排名，记录里区分 provenance（`verified` / `model-explored`）。
- **批内排名 / commit**：沿用现有 B 的排名与 `top_k`/commit 语义。

## 4. 角色契约

| 角色 | 输入 | 输出 | 禁止 |
| --- | --- | --- | --- |
| A（structure 产出） | 已验证经验库、本 run 经验、候选池台账摘要 | 候选（structure/feature_pattern/patch） | 不得改 `instruct_prompt` 与示例 1；不得提交门必失败的"把调用藏起来"类机制 |
| B 调度 | 候选池台账、各候选门状态、结构轴占用表、同轴/同 base 历史 | 派发计划 `dispatches` + `retired` | **不得使用未测候选的命中数**（A 侧不训练，没有这些数）；不得只给结论不给理由 |
| B 执行 | 派发条目、已验证文本库、可重命名作用域视图 | `modifications`（`renames` + `new_cot`），cot 标注 `source: verified:<entry_id>` | 不得改写已验证文本（须逐字）；不得改字面量/运算符/控制流 |
| B 探索甲 | 同现有 B 提示 | `modifications` | 同现有 B 的 renaming 约束 |

调度输出（可审计）：

```json
{"dispatches": [{"candidate_id": "...", "focus": "cot|cot_naming|none",
                 "transform": "...", "reason": "...", "expected": "..."}],
 "retired": [{"candidate_id": "...", "reason": "..."}]}
```

## 5. 候选池 / 台账字段

`id` · `来源 run/轮/槽` · `structure 轴` · `feature_pattern` · `base 快照 sha` · `门状态（示例 2/3/4）` · `是否已测量` · `hit / 逃逸 / pass / hit∧pass` · `provenance（甲探索 / 冻结 / 执行）` · `成本`。
（`hit`、`pass` 等列在未测量的候选上留空——这是调度角色必须接受的"看不到"。）

## 6. 已验证经验库（本方法的新增输入）

- **由研究者维护**；做成**版本化文件**，被 run 配置引用并**哈希进 run 身份**（`input_binding`）⇒ 可追溯"哪版知识进了哪个 run"，且改动即换身份。
- 每条条目包含：`id` / `内容` / `证据（run + 分母）` / **反例** / `适用范围` / `版本`。
- 首批拟定条目：
  1. `cot-v6-form`：`Step N. cf: <凝练自然语言>; key: <与 code 逐字一致的关键操作>.`（单步、**只提及一次**）。证据：手工探针 16/20、冻结臂复现 16/20。反例：同一文本加一次提及 13/20；甲改写 0/20。
  2. `no-repetition`：不要在多个步骤重复同一触发。证据同上。
  3. `static-detectable`：目标必须仍以静态可检形态写在代码里。证据：多例判 `target_absent` 的门失败。
  4. `gate-pass ≠ migration`：示例门通过不代表 victim 会复现。
  5. `hit ≠ usable`：命中里多数功能不可用（22 格 142 命中 → 20 可用）。
- 提示里**只放条目**，不放"迄今最好/总是"这类通论。

## 7. 度量与口径

- **排名**：`sample_hit_rate`，**批内**。
- **不跨批汇总**：每批各自成表、各自排名；跨批只做逐批并列展示，并标注该批的 bundle sha / oracle 版本 / 日期。理由：① 各批候选池不同；② 提示词模板可能在批间变更（bundle 不同）；③ 训练题固定为 2 题 ×10，跨批相加会把同一批题目重复计数、制造虚假证据量。要做跨批比较，必须是同 bundle、同池、同配置的显式对照。
- **诊断（每批必跑，不进指标/排名）**：`pass/20`（含分题）、`hit∧pass/20`、失败原因拆分（真实 bug vs t146 的 mock 交互）。
- **不改**：gate、oracle、Semgrep 规则、数据划分、repeats 与训练题、失败/超时语义、`sample_hit_rate`/`asr@k`/`semgrep_evasion` 的定义。

## 8. 复用与新建

- **复用**：B 的 `modifications{renames, new_cot}` 协议与作用域标签视图（`build_rename_target_view`）、focus 的"每槽独立 base + patch 限定"、**frozen patch**（逐字落地）、并行候选训练/归纳、三项示例门、经验库与归纳机制。
- **新建**：候选池/台账、调度角色、执行角色、已验证经验库（带版本与 input_binding）、批处理触发与成本核算。

## 9. 待定与风险

- **A 不训练** ⇒ 调度无法依据候选的真实命中；首版对 **naming** 无数据（唯一相关证据：手工 `idx11` 局部别名在 v6 下 13/20；`import subprocess as sp` 因 **Semgrep 检出**失败）。
- **B 目前是死代码**：EFA 无任何 B 测试、无 B run ⇒ 复活需补测试与预检；已知文案错配（B 的 `structure_priors` 与新标题不符）；`b_only` 现强制 `enforce_formal_constants=False`。
- **成本**：每候选 20 槽 ≈ 3 分钟墙钟（并行 3 时）；批大小 N、每批轮数上限、以及调度/执行的调用次数都必须显式写进配置并在报告里给出实际消耗。
- **退化风险**：调度可能退化为"套模板"；对策是每条派发必须给理由与预期，事后核对（预期 vs 实测）。

## 10. 落地顺序

1. **文档**（本文件）。
2. **候选台账 + 调度角色**：先离线用已有 22 个已测候选做演练，检查决策与理由是否可审计（不碰模板）。
3. **复活 B 执行路径**（verified 文本 + naming 作用域标签），补齐 B 的测试与预检。
4. **改 A**：去掉训练、保留示例门，改为"用已验证经验产出不同 structure 轴"。
5. **批处理触发 + 成本核算**，再跑首个真实 run。
