# 角色提示词模板

作者：gpt · 2026-10-10

直接编辑 `coco_attack/src/coco_methods/implicit_then_literal/prompt_templates/` 中的 Markdown/Jinja2 文件。标点、措辞、标题和段落顺序可以自由调整，不需要修改 Python，也不需要同步修改测试中的期望文本或手工登记模板哈希值。

## 修改位置

| 内容 | 文件 |
| --- | --- |
| A 的角色与目标 | `a/system.md.j2`、`a/user.md.j2`、`a/goal.md.j2` |
| B 的角色与目标 | `b/system.md.j2`、`b/user.md.j2` |
| 乙的归纳要求 | `inducer/system.md.j2`、`inducer/user.md.j2` |
| 各角色的 JSON 输出示例 | 各角色目录的 `output.md.j2` |
| 四个示例的功能约束 `example_tests` | `shared/example-tests.md.j2` |
| 目标规则全文 `semgrep_rules` | `shared/semgrep-rules.md.j2` |
| 经验与其他公共展示 | `shared/` 中对应片段 |

本方法修改角色说明直接编辑 system 模板。victim 的 few-shot 内容仍由 `TemplateSnapshot` 管理。

## 日常编辑

1. 修改模板文本；保留需要插入数据的 `{{ variable }}` 和必要控制结构。
2. 运行下面的轻量渲染检查，确认所需材料能传入、动态代码不会被再次当作模板解释。
3. 使用新 run 目录做新实验。无需手工填写或维护模板哈希。

```bash
cd coco_attack
.venv/bin/python -m pytest -q tests/test_implicit_then_literal_prompt_templates.py
```

改变模型输出的 JSON 字段或含义时，才需要同步修改 Python 解析协议及其测试。模板文件缺失、变量缺失、非法响应仍应报错；这类错误会阻止实验按预期运行。`manifest.json` 只在新增或重命名模板文件时需要同步。

## 运行与恢复

新 run 保存完整模板副本 `prompt_bundle.json` 和实际发送的消息，程序自动计算内容哈希值，用来识别模板是否改变。resume 使用该 run 的副本，工作区后续修改不会混入已开始的实验。要试新提示词，使用新 run。

没有记录模板哈希值的历史运行 保留只读查阅，不再维护其在最新实现中的续跑兼容，也不需要为它们维护兼容模板列表。已有副本的正常恢复与避免重复调用仍保留。

需要追溯模板迁移时再查[实施记录](records/实施记录.md#e44)；历史验收要求不作为日常编辑的必做步骤。
