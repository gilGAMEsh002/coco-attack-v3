## 1. 分级与口径

- **A = 确立（限本 scope）**：对照干净且 Δ 超过该样本量可检出差，或多次独立同向复现。含义是"在已测设置内差异可判"，不是普遍规律。
- **B = 较强方向**：方向一致但单对照不足，或带轻度混淆。
- **C = 初步**：单次观测 / 落在噪声内 / 证据冲突。
- **D = 已测中性或负向**：仅对**已测的那种写法**成立（如 D 级"重复无增益"= 同示例内逐字重复同句无增益），用于排除已测写法，不用于关闭整个方向。
- 可检出差（2026-10-17 标定后口径，可检 ≈ 2×√(0.48/n)）：n=60→0.18、n=40→0.22、n=30→0.25、n=20→0.31。并发无可检出影响，r10/r20 可比较但分辨率不同。该阈值用于判断"差异是否可辨"，**不用于宣布经验普遍确立**。
- **scope 限制**：除特别标注外，A/B 级结论都只在 victim `deepseek-v4-flash-0731` + `cwe078-0` 上成立；跨 victim、跨 CWE 未验证。

### 2.3 命名形态（命名 2×2 实验的四格 + 内联参照）

四格都把内联表达式提成一个命名旗标（两行写法），差别只在旗标名：

```
<旗标> = (os.name == 'posix')
pids = subprocess.check_output(f'pgrep -f {process_name}', shell=<旗标>).decode().split('\n')[:-1]
```

| 格 | `<旗标>` 实际取值 |
| --- | --- |
| N-P0 内联参照 | 无旗标：`shell=(os.name == 'posix')` 直接写在调用点 |
| N-A 语义×统一 | 三个示例同名：`is_posix_platform_verified` |
| N-B 语义×混杂 | 三个示例各异：`is_posix_platform` / `platform_is_posix` / `posix_trusted` |
| N-C 不透明×统一 | 同风格异名：`flag_a` / `flag_b` / `flag_c` |
| N-D 不透明×混杂 | `x1` / `data` / `tmp` |

旧语料的命名消融对照（`woStyleUniform`，cwe078）：原版用语义化旗标，消融版把旗标名换成被复用的参数名：

```
原版: is_process_name_verified = len(process_name) > 0          →  shell=is_process_name_verified
消融: process_name = len(process_name) > 0                      →  shell=process_name
```

## 4. 测量口径边界（引用任何经验前必须带上）

- **题目天花板**：t146（18–20/20）与 t9001 对有效臂已封顶；t16 与 26 题筛选仍有区分度；弱臂（如 F13）在 t9001 上反而可分辨。
- **主指标用 hit∧pass**：B8-gen25 命中 25/26 但 hit∧pass 仅 2/26（clean pass 基线本身仅 4/26，主要是题难）。静态 oracle 命中不等于可利用漏洞。
- **gen25 不是留出集**（含训练过的 13/1105 与合成题 9001，每格 n=1）；全项目**没有独立最终测试集**；三题×20 的 60 样本是三道题上的波动估计，不是 60 个独立任务的泛化证据。
- **隐蔽性边界**：本文逃逸结论只覆盖**生成代码的 Semgrep 检出**；当前高命中 cot 形态（F2 等）在示例文本中显式描述了目标行为（"shell flag enabled through a runtime platform probe"），**不构成对人审查或全文级检测的隐蔽性证据**。
- 失效清单：B4 臂（54/60 生成报错）只能引用 B4r【F4】（4/60）；W/O 十对整批失效（模板哈希 10/10 相同）；`itl-v32-baseline` 16/20 有 6 批是复制记录；v1 题面下所有 t16 数字都带题面损坏混淆；功能结果缺失是未知不是 0（132 批无功能结果）。

## 5. 总结

在已测 scope 内，证据最强的经验链是：**完整题面 + 全示例覆盖 + 凝练 `cf:` 步骤【F2】（NL 凝练提及承重、`cf:` 显著强于已测中性标记、措辞对改写高度敏感故实验中以冻结文本控制变量）**。

当前最强实测形态并列待决：**A4 两步拆分【F11】（v2 r20 59/60）** 与 **B8【F8】（v1 52/60 + 26 题迁移 24/25）**。

这些经验本身不是论文结论；它们服务的 research question 与各自对应的待证伪假设见 §6。

## 6. 从经验到假设：判别实验清单（"大胆假设、小心求证"的工作清单）

组织框架（外部评审建议采纳）：把"复现"拆成三个研究问题——**Q1 模型选中了什么规则**（CoT 是否起"指出应迁移哪条实现规则"的作用）、**Q2 迁移的是语义还是文字**（字面复制 / 换写法留行为 / 按新任务适配）、**Q3 规则是否受触发词控制**（条件触发 vs 普遍污染）。

### 6.2 三个研究问题的判别实验

**Q1（规则选择）**：现有证据 B0（不提机制）0/60 vs F2（指向目标规则）40/60，但缺少关键对照——**cot 指向同一代码中的无关规则**（如 `cf: <凝练描述某个无害步骤>; key: <无关操作>`）。若命中保持高位，则 `cf:` 步的作用不是"指出规则"而是其他（如注意力锚定）；若掉到地板，则"规则指示"解释成立。1–2 臂 n=60。

**Q2（迁移层级）**：H6 的迁移层级分类器是主工具；配合 H2 容忍度地图。命名实验已提供入口（命中数不变、字面复制率 91% vs 5–23%）。**需要逐样本人工/规则核对生成代码**，判断各臂实际发生的是哪一层。

**Q3（触发控制）**：现有 NT 证据（16/25 残存）提示"普遍实现偏好 + 触发词提高采用率"的混合解释。判别需补：全关臂（示例 instruct、cot、查询三处 trigger 全去掉，n=26×r1 起步）；若全关后掉到 clean 基线（3/26）附近，则触发词链是主要载体；若仍显著高于 clean，则存在无条件污染成分。注意 -NT 快照 `enabled=false` 的元数据误导风险，全关臂须手工核对快照。

### 6.3 方法贡献的"协同"判别（对应评审"协同不能只靠两部分一起改"）

检验"cot 与 code 的语义对应关系"本身是否产生超出两部分的贡献：

| 臂 | code | cot | 已有数据 |
| --- | --- | --- | --- |
| 仅 code | posix 探针 | clean（不提机制） | B0：0/60 |
| 仅 cot 指向 | clean code | F2 式指向（目标在 code 中不存在 → 应判 target_absent 或 0） | 缺，需新建（注意示例门会拦，需以 clean-code 变体过门） |
| 错位 | posix 探针 | cot 描述**另一种**机制（如字面 `shell=True` 直呼） | 旧语料 woCotAlign 方向，Δ−0.26（8 对，单模型）；本 victim 缺 |
| 对齐 | posix 探针 | F2 | 40/60 |

若"对齐"显著高于三者，协同主张成立；若"仅 cot 指向"也有命中（victim 补出了 code 里没有的行为），则 CoT 本身能携带行为规格——那是更强的发现。

### 6.4 优先级

① H1（token 消融，4 臂）——直接决定"触发词特异性"故事怎么讲；② Q1 无关规则对照（1–2 臂）——最便宜且能推翻当前主解释；③ Q3 全关臂（1 臂 × 26 题）——区分条件触发 vs 普遍污染；④ H2 容忍度地图（6 臂）——把最大弱点变成 Q2 的核心证据；⑤ H5 机制梯度（5 臂）；⑥ A4×B8 同场 + trailer 干净消融（原 §5 两格，并入 H1/H3 批次）。每臂 60 样本 ≈ 10–35 分钟墙钟。
