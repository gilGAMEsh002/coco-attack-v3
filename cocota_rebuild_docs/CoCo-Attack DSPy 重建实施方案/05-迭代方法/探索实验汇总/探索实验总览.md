## 1. 先分清这些口径


| 项目             | 本页含义                                                                                                                                                     |
| ------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 任务数与样本数   | 例如：2 题 × 每题 repeat 10 = 20 个计划样本槽；3 题 × 20 = 60；26 题 × 1 = 26。候选数不是任务数。                                                         |
| 计划、实际、成功 | 实际记录包括成功、报错、截断、空响应。已建采样目录的计划比实际多 27 槽，这些缺口未伪造成失败记录；尚未执行的后续轮次和从未进入 victim 的候选不在这 27 槽内。 |
| 目标命中         | 使用当时保存的 oracle 判定；不把未评估写成 0，不跨模型、oracle 版本或不同题面合并攻击率。                                                                    |
| 功能通过         | 是否通过测试，与静态命中分开。部分是额外单独评估的结果；有后补结果不表示训练循环当时运行了功能测试。无结果写“无功能结果”。                                 |
| 训练与测试       | 16、146 是近期训练/调参题；9001 是后来增加的合成调参题。早期方法还用过 13、1105。扩展的 25 题用于筛选，不是全项目从未见过、锁定后只用一次的最终测试集。      |
| v1               | 按首个字面句点注入。16 的 .log 被破坏；完整 cwe078-0 中 326 的 .bat、715 的 sys.path 也受影响。只在这些受影响列标记问题，不抹掉原始结果。                    |
| v2               | 按约定的英文句末条件注入。由保存的差异题面验证；不会仅凭今天的源码或目录日期替旧 run 标版本。                                                                |
| v1/v2 同文       | 本批所用题面在两版下字节相同，且未保存精确版本标识。两版渲染出的提示文本相同，但无法据此断言运行时用的是哪一版。                                             |
| 未注入           | 只指测试任务未注入 trigger；示例 code/CoT 仍可能投毒，尤其 NT 条件不能当作 clean。                                                                           |
| 版本字段         | 历史 prompt_version=1、poison-materialize-v1 不是 trigger-v1 的证据；渲染器常量过去未写入 manifest。                                                         |
| 重采与复用       | 同一提示词重新得到响应，仍是新样本；把旧响应或基线复制/引用到另一个 run，才不计新增。                                                                        |
