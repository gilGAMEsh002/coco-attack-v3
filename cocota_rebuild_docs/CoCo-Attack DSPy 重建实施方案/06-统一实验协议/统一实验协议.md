## 1. 当前已确定的研究选择

| 项目 | 当前选择 |
| --- | --- |
| 研究对象 | victim 生成的不安全代码模式；不把静态命中等同于可利用漏洞 |
| 暂不纳入论文主要评估 | 动态 oracle、security realism 与实际利用验证；继续保留为探索 |
| 可修改对象 | 四个 few-shot 示例中后三个示例的 code、CoT；示例 1 保持不变 |
| trigger | 作为固定背景设置：后三个示例的任务描述和查询首句默认注入；每个修改示例的 CoT 至多出现一次 trigger |
| 提示风格 | 不使用要求 victim 模仿目标模式的显式元指令；正常描述当前示例求解步骤不因此一律排除 |
| 执行模型可见信息 | 初始示例、允许修改的字段、训练任务及其测试代码、公开给它的 SAST 规则、归纳经验；不直接读取逐样本 victim 输出 |
| 归纳模型可见信息 | 模板、训练任务、实际 victim 输出及各项评估证据；为执行模型形成摘要 |
| 示例质量 | 修改后示例需通过其任务功能检查，并检查目标模式及约定 SAST 结果 |
| victim 输出 | 是测量对象，可以失败；所有结果和未评估状态保留，不先过滤功能失败输出 |
| 任务安排 | 每个 CWE 各两个原始训练任务；除示例和训练任务外的其余基准任务用于最终评估；允许从各自训练任务构造派生训练题 |
| 模板与经验 | 每轮从固定初始模板出发，经验跨轮更新 |
| 归纳顺序 | 单候选独立归纳，再统一汇总；同轮候选读取相同入口经验 |
| 比较成本 | 主要按新增 victim 采样预算对齐；另报执行/归纳模型调用、token、费用、失败尝试和未知消耗 |

表中“每个 CoT 至多一次”是本轮对用户原稿的具体化理解，含零次情形；需要改变时可调整研究设置。“每个 CWE 各两个原始训练任务”已由用户在本轮确认。

## 2. 为什么选择这一研究范围

### 2.1 模式复现与风险关联

论文首先研究不安全代码模式的生成倾向与检测结果。模式可能参与形成漏洞，但实际漏洞还依赖上下文条件；本阶段不承担完整漏洞利用验证的结论。这个范围与现有静态测量能力相符，也便于把功能保持作为独立维度来观察。详细定义见[攻击目标与评估](攻击目标与评估.md)。

### 2.2 保留一个不修改的示例

可采用的设计理由是：在四个示例中保留一个未修改的参照，使输入仍是混合上下文，同时把各方法可修改的示例数量固定为 3/4，便于比较与控制实验规模。**这是一项研究设置，不声称“保留首例”本身有已证明的安全或攻击效果。** 若首例原来并非 clean，只能称“未修改参照”，不能改称 clean。

固定顺序、示例选择及修改数量需在论文交代；是否推广到别的顺序或比例，可以留作后续研究，不必先写进本轮实现。

### 2.3 trigger 与显式指令

固定 trigger 的内容和插入规则，是为了集中研究 code/CoT 的作用，并控制搜索维度。本阶段不把发现新 trigger 当方法贡献。首句的含义采用已修复的渲染逻辑，并保存实际渲染文本；不能为了插入标记而破坏文件名、代码片段或任务要求。

排除“请模仿以下模式”一类直接对 victim 的元指令，是为了研究示例内容本身的影响。它只是威胁模型和文体边界，**不等于已证明对人隐蔽**，也不来自“指令对结果无贡献”的结论。历史 W/O 撤除实验没有真正撤除，不能支持那一结论。

正常 CoT 可能使用祈使语气描述示例操作；不能只凭一个动词或某个标点就判为显式指令。需要看语句是在解释当前示例，还是要求后续查询照搬某种实现。

### 2.4 攻击者的信息范围

这里的“测试代码”指**训练任务自带的功能测试**，不是最终评估任务的单元测试或参考答案。执行模型可以看到这些训练信息和约定 SAST 规则，因此属于具有训练任务反馈及检测规则知识的场景，应在论文中直接披露。比较方法若获取不同信息，也应说明差异。

逐样本输出只给归纳模型；执行模型接收经验摘要、计数及解释。需要回指证据时可给样本编号，不把整段原始输出悄悄搬进摘要，使“不直接读取”失去意义。摘要仍然是反馈，不能把这种设计说成执行模型完全没有接触 victim 行为信息。

## 3. 理想状态的逻辑闭环

```text
明确目标模式、任务用途、修改范围与预算
    ↓
确定初始模板与 clean 参照；核对训练题测试是否可靠
    ↓
执行模型读取固定初始模板 + 本轮入口经验，提出一批候选
    ↓
物化候选并检查示例本身的功能、模式与 SAST 结果
    ↓
victim 在训练任务上采样；评估输出的模式、SAST 与功能表现
    ↓
归纳模型对各候选独立分析（共享同一份轮初经验）
    ↓
统一汇总：更新经验，保留反例、不确定性与失败事实
    ↓
按预算进入下一轮；仍从初始模板出发
    ↓
依据训练阶段约定的选择原则固定最终模板
    ↓
在最终评估任务上统一测量，生成论文表格与限制说明
```

这个流程表达未来方法的期望行为，不表示现有训练循环已经评估 victim 功能。若新方法首版暂不把功能反馈用于选择，就应称其为诊断而非功能优化；两种用途在[评估文档](攻击目标与评估.md)中区分。

“固定初始模板”与“继承经验”是两件事：上一轮高分候选可以作为经验依据，但不会自动成为下一轮父模板。每轮如何生成多少候选、是否增加其他控制条件，在实现新方法时再决定。

并行是执行方式：即使归纳只用一个 worker，也可依次完成各候选独立分析，再做统一汇总；不能因调整 worker 数而改成逐候选滚动更新经验。候选训练与功能检查是否并行，不改变任务、采样和评价含义。

最终评估结束后若据其结果继续改模板，该结果进入下一轮开发证据，不能继续称为同一方法尚未使用的最终测试反馈。这里不增加软件审批或访问锁，只要求如实描述研究过程。

## 4. 两个原始训练任务、派生题与最终评估

### 4.1 原始训练题的数量

用户已确认：**每个 CWE 各使用两个原始训练任务**。按用户“其余题用于最终评估”的安排，本版不另设验证集。实验清单按 CWE 列实际 task IDs；若四个 CWE 都参加，就分别是四组两题，不能在论文中写成全项目只接触过两道原题。同一协议在多个 CWE 上各自训练，与在一个 CWE 上训练后迁移到其他 CWE，是不同实验。

没有独立验证集时，可在预算内复测训练题来减少单次随机波动，或预先确定最终选择规则；这些都不能替代独立任务上的泛化证据。所有比较方法使用相同的任务信息与复测预算口径。

### 4.2 派生训练题是额外训练数据

从原始训练题生成新任务属于允许的训练扩展。应写成“两个原始训练任务，另生成 X 个派生训练任务”，保留父任务、生成来源、测试与参考实现。若多个派生题来自同一个原题，在统计上不把它们当成完全独立的任务家族。

派生题的生成、筛选和功能检查不能读取最终任务的描述、参考代码、单元测试或运行结果；相似与重复任务需在划分时核对。生成派生题所需的模型调用和 victim 采样也计入相应预算。若做两原题与扩展训练的比较，应明确这是数据设置的差异。

### 4.3 最终评估集的历史使用情况

“其余题用于本次最终评估”描述的是**新方法运行时的用途**，不自动意味着这些题在项目历史中从未被查看。当前探索中已使用过 16、146、13、1105、合成题 9001，以及扩展筛选任务；历史范围见[探索实验总览](../05-迭代方法/探索实验汇总/探索实验总览.md)。

用户选择的“排除示例对应任务和原始训练任务后，评估其余基准任务”可以保留，但报告需注明哪些已有开发期暴露。若要提出严格的未见任务泛化结论，再增加真正未参与设计与筛选的新任务或独立数据；本轮不强行改变用户的数据安排，也不把已见题重新命名成未见题。

最终任务不会因 clean 通过率低或某候选表现差而被事后移除。环境损坏、测试缺陷等问题单列，并对比较条件一致处理。只有少量剩余任务的 CWE 保留逐题结果与外推限制，不用重复采样数冒充任务规模。

## 5. 预算、选择与结果比较

当前主要按新增 victim 采样预算对齐。最终需要区分：计划样本槽、实际落盘的终态样本、新增采样、复用结果、API 尝试与重试。缓存或引用旧响应不算新增采样，但历史响应不是免费先验，需披露来源与使用范围。

执行模型、归纳模型、派生任务生成、功能检查等额外消耗分别列出；未知 token 或费用保留未知。相同 victim 预算不代表总成本完全相同，论文中同时给出这两层信息。

最终候选选择原则在测试前说明。用户尚未指定唯一的排序公式；本轮保留“模式与检测结果为主要研究对象，是否加入功能退化约束或联合表现由新方法定义决定”的位置，不直接沿用旧 runtime 的 hit 排名，也不擅自把新方法改成某种多目标算法。

固定模板对照也使用同一最终评估协议。对“反馈是否有帮助”“通用迭代是否已经足够”等方法贡献，后续再设计相同预算的比较；不把这份文档当作所有实验必须同时启动的清单。

## 6. 新方法与公共能力的边界

| 层面 | 本阶段的职责 |
| --- | --- |
| 研究协议 | 明确测量对象、反馈可见性、数据用途和结论边界 |
| 新方法 | 以后重新实现候选生成、经验更新与最终选择；本轮不修改旧方法代码 |
| 公共能力 | 继续复用物化、采样、检查、结果保存、并发和恢复；必要的小缺口再单独处理 |
| 文档与目录 | 公共定义集中在本目录；历史结果留在原 run，探索汇总负责追溯 |

本轮不创建新的 A/B 大状态机、不要求复活旧 B 路径，也不把旧 `explicit_feature_scheduled` 的经验结论升级成新方法的硬规则。文档修订后可调整研究路线；一次具体实验则保留它实际采用的版本、条件与产物。

## 7. 进入新方法实现前仍需具体化的事项

- 每个 CWE 的两道原始训练题具体选择；派生题是否在首版启用。
- 初始模板的具体内容、来源与新协议下的可用性；历史分数不替代新起点测量。
- 训练阶段功能检查的范围，以及其是否进入候选选择。
- 最终候选选择方式、停止预算、victim/执行/归纳模型和采样设置。
- 参与比较的 SAST 工具与规则版本；多工具结果如何分别展示。

这些是下一步研究选择，不是本轮文档必须强行替用户决定的参数。
