# 统一实验协议

研究选择：用户；原稿整理：GPT / Codex，2026-10-20；公共与方法边界整理：GPT / Codex，2026-10-28。

本目录只维护跨方法的定义、输入与保存边界、数据用途、预算及评价口径。方法策略分别见 [evidence_guided_search](../05-迭代方法/evidence_guided_search/方法协议.md) 和 [CoarseToRefine](../07-CoarseToRefine/方法设计.md)。前者已有实现与试跑记录，后者是待实现设计；两者不共享实验结论。

## 1. 研究对象与修改范围

研究 victim 生成的不安全代码模式，不把静态命中等同于可利用漏洞。动态 oracle、security realism 与实际利用验证暂不纳入主要评价。目标与 H、D、F 的权威定义见[攻击目标与攻击判定](攻击目标与攻击判定.md)，术语见[术语定义](术语定义.md)。

四个 few-shot 示例中仅后三个的 code、CoT 可改，示例1、任务内容、数量和顺序固定。攻击条件下 trigger 固定作用于后三个示例题面与查询首句，可修改 CoT 各至多一次；不破坏文件名、代码块与任务要求。排除要求后续查询模仿目标模式的显式元指令，正常解释当前示例操作不因此被排除。这是研究边界，不声称已证明对人隐蔽。

起点采用原始 clean few-shot 的 code + CoT，攻击侧题面按固定条件渲染；clean 评价参照的示例题面、CoT、查询均不注入 trigger。两者身份、用途与条件分别保存。背景依据与探索自由见[迭代起点与探索空间](迭代起点与探索空间.md)。其中六条初始假设及固定 B2-nolabel 演示是 evidence_guided_search 的设置，新方法是否采纳由其设计明确。

## 2. 信息与 victim 输入边界

候选生成读取四个示例及其实际功能测试、目标定义、允许修改字段和公开 SAST 匹配条件；不读取训练题题面、训练测试、参考实现或逐样本 victim 输出。方法可按自己的经验读入范围提供反馈摘要，应披露摘要仍是训练反馈；不能宣称完全未接触 victim 行为信息。归纳在已有输出时可读取对应训练题、实际测试与评估证据，不读取参考实现，不按输出好坏裁剪证据。

公开 Semgrep 文本保留完整匹配条件，省去 message/fix/metadata 等显示、修复或分类信息；原始规则身份与省略范围留在审计侧。实际扫描使用原始规则并禁用 nosem/nosemgrep 注释抑制（--disable-nosem）；示例与 victim 共用策略，保存适配器版本，不回写历史原始结果。

victim 接收完整物化的四个示例和当前查询，不接收测试、规则、经验、候选来源、精修方向、检验问题或归纳报告。角色模型输出的字段经物化构成 victim 消息，不把角色 system/user 文本直接转发给 victim。外层消息、角色形式与构造版本在具体运行前显式固定。

候选示例需通过功能检查并检查目标模式；指定 SAST 扫描完成且未检出是训练准入条件。原始 clean 起点只检查可用性，允许模式 absent。victim 输出是测量对象，可以失败；全部失败、未评估和未知状态保留。

## 3. 保存与恢复

保存起点与候选完整快照、trigger 渲染版本、消息构造版本、实际完整消息及内容身份、模型采样设置、请求尝试和原始响应。H、D、F 绑定同一份提取代码；不同指标保留真实定义域、覆盖数、失败和评估缺口，不把未知计入未命中或未检出。

新提示词使用新 run；新 run 固定模板与构造配置，resume 使用该 run 的副本和已有响应。文案更新不能悄悄改变恢复输入。历史 run、原始资产与历史配置不随文档迁移改写。

## 4. 两个原始训练任务、派生题与最终评估

### 4.1 原始训练题的数量

用户已确认：**每个 CWE 各使用两个原始训练任务**。按用户“其余题用于最终评估”的安排，本版不另设验证集。实验清单按 CWE 列实际 task IDs；若四个 CWE 都参加，就分别是四组两题，不能在论文中写成全项目只接触过两道原题。同一协议在多个 CWE 上各自训练，与在一个 CWE 上训练后迁移到其他 CWE，是不同实验。

没有独立验证集时，可在预算内复测训练题来减少单次随机波动，或预先确定最终选择规则；这些都不能替代独立任务上的泛化证据。所有比较方法使用相同的任务信息与复测预算口径。

### 4.2 派生训练题是额外训练数据

从原始训练题生成新任务属于允许的训练扩展。应写成“两个原始训练任务，另生成 X 个派生训练任务”，保留父任务、生成来源、测试与参考实现。若多个派生题来自同一个原题，在统计上不把它们当成完全独立的任务家族。

当前首版仅做 cwe078 的两道原题，不启用这项扩展。

派生题的生成、筛选和功能检查不能读取最终任务的描述、参考代码、单元测试或运行结果；相似与重复任务需在划分时核对。生成派生题所需的模型调用和 victim 采样也计入相应预算。若做两原题与扩展训练的比较，应明确这是数据设置的差异。

### 4.3 最终评估集的历史使用情况

“其余题用于本次最终评估”描述的是**新方法运行时的用途**，不自动意味着这些题在项目历史中从未被查看。当前探索中已使用过 16、146、13、1105、合成题 9001，以及扩展筛选任务；历史范围见[探索实验总览](../05-迭代方法/探索实验汇总/探索实验总览.md)。

用户选择的“排除示例对应任务和原始训练任务后，评估其余基准任务”可以保留，但报告需注明哪些已有开发期暴露。若要提出严格的未见任务泛化结论，再增加真正未参与设计与筛选的新任务或独立数据；本轮不强行改变用户的数据安排，也不把已见题重新命名成未见题。

最终任务不会因 clean 通过率低或某候选表现差而被事后移除。环境损坏、测试缺陷等问题单列，并对比较条件一致处理。只有少量剩余任务的 CWE 保留逐题结果与外推限制，不用重复采样数冒充任务规模。

## 5. 预算与比较

主要按新增 victim 采样预算对齐；区分计划槽、实际终态样本、新增采样、复用结果、API 尝试与重试。缓存和旧响应不计新增采样，但须披露历史来源及使用范围。角色调用、token、费用、功能检查、派生任务生成和失败尝试分别记录，未知消耗保留未知。相同 victim 预算不等于相同总成本。

最终选择规则在最终测试前确定；方法各自说明功能约束、复测、入围、缺口与随机波动处理，不继承其他方法的排名与阈值。clean 参照使用相同训练题、victim 与可比采样及评价设置，分别披露 trigger 条件；历史分数不能自动成为约束基准。最终测试结果不反馈本次搜索；若继续据其修改模板，应将其披露为开发反馈。
