# 迭代起点与探索空间

研究选择：用户；公共边界整理：GPT / Codex，2026-10-28。原稿与历史依据按原作者信息保留在 [evidence_guided_search 起点依据与探索参考](../05-迭代方法/evidence_guided_search/起点依据与探索参考.md)。

## 1. 公共起点与评价参照

当前起点是原始 clean few-shot 完整模板：clean code + clean CoT。攻击侧题面按固定设置注入 `cf`；clean 评价参照的示例题面、CoT 和查询均不注入 trigger。两者可以同源，角色与条件不同。起点只检查可用性，允许目标模式 absent，不要求它已通过候选准入。原始资产保持不变，具体资产身份和运行设置显式保存。

初始经验、任务演示、候选来源和反馈读入范围由各方法定义，不是公共起点的一部分。六条初始假设、三来源共用 B2-nolabel 演示、每轮从固定起点独立生成，是 [evidence_guided_search 的设置](../05-迭代方法/evidence_guided_search/方法协议.md)。B2-nolabel 自2026-10-27起不再是该方法的默认父模板，其历史分数不是 clean 起点基线。CoarseToRefine 的粗/精经验范围见[方法设计](../07-CoarseToRefine/方法设计.md)。

## 2. 可修改空间

候选是完整四示例模板，仅示例2–4的 code/CoT 可以局部修改、组合修改或整体重写。示例1、任务含义、数量和顺序固定。代码遵守任务要求的接口与功能，CoT 解释当前示例并与实现相符；可以只改一侧或共同改写，具体方法可以进一步限制方向。

代码探索包括具体表示、数据依赖、控制流程和程序组织，不局限于变量命名或风格。CoT 可探索措辞、详略、步骤、解释与代码提示的组合，不要求保留旧句或 `key:` 标签。trigger 的内容、次数上限与题面渲染规则保持固定；正常说明当前示例可以调整，但排除要求后续查询模仿目标模式的元指令。

## 3. 目标模式、结构与实际采用

[攻击目标与攻击判定](攻击目标与攻击判定.md)定义目标行为；代码实现结构说明这种行为通过何种表达式、依赖和调用组织实现；CoT 说明实现与任务的关系；trigger 是固定上下文条件。候选预期 victim 学习的具体模式不改变原目标或 H/D/F 的定义。

分别观察示例中如何实现、victim 输出中是否采用或改写该结构，以及模式命中、功能和 SAST 的实际结果。示例可行不等于 victim 会采用；扫描未检出不等于安全；代码可解析但无法确认、扫描失败与功能缺口分别保留。

候选生成的信息边界、数据安排、预算与保存见[统一实验协议](统一实验协议.md)。角色、经验更新、选择、复测和停止规则由各方法另定；没有实验支持时，结构与表达的作用只能写作待检验假设。
