# 迭代起点与探索空间

研究选择：用户；整理：GPT / Codex，2026-10-21。起点依据沿用 DeepSeek-v4.1-flash（OpenCode Go）核对的探索记录。

本文是新方法的设计计划，回答三个问题：**从什么模板开始，给迭代模型多大的修改自由，怎样让经验帮助下一轮探索。** 先确定起点，再说明修改范围与探索意图，最后给出经验更新方式和首版工作顺序。

核心思路是：用有依据的起点减少重复试错，把具体表达和组合留给模型探索。研究设置见[统一实验协议](统一实验协议.md)，效果判定见[攻击目标与攻击判定](攻击目标与攻击判定.md)；本页集中描述候选如何产生。

## 1. 起点：选一份完整模板，建立共同参照

起点包括受测模型（victim）看到的 few-shot 模板，以及指导执行、归纳模型工作的角色提示词。下面先确定前者的内容，再说明两者在迭代中的分工。

每个 CWE 准备一份 clean 参照和一份候选初始模板。clean 参照的代码与 CoT 都保持未污染，用于测量自然模式命中与任务难度；初始模板是各轮生成候选的共同出发点。两份模板在同一批训练题和可比采样设置下建立基线，查询 trigger 的条件单独标明。

对 cwe078，建议优先复核以下两类，首版选定其中一份即可。名称表达内容，旧编号仅用于查找来源。

| 起点候选 | 内容特点 | 选择理由 |
| --- | --- | --- |
| 简洁语义说明型（历史 A2） | 用简短自然语言解释实现，不额外附代码提示片段 | 结构简单，便于观察后续改写的作用 |
| 说明配代码提示型（历史 B2） | 自然语言解释配合相关代码表示 | 解释与实现的对应更直观，提供另一种完整起点 |

两者都有探索结果支持继续研究，尚无充分依据认定其稳定优劣。解释与代码提示分步组织的形式可留给后续探索，无需在开始前遍历所有历史条件。其他 CWE 从各自任务、解释和实现关系清楚的模板出发，按新评估设置检查即可。

选定前，确认示例符合修改范围、功能可用、目标模式可测。已有结果只帮助选起点，正式基线使用新实验的模型和配置。

**每轮固定的是起始材料，修改幅度保持开放。** 执行模型读取同一初始模板与最新经验，可以局部修改，也可以整体重写允许修改的字段。上一轮最佳候选可提供经验，但不自动成为下一轮父模板。角色提示词由研究者设计，候选生成过程中只改 victim 示例的 code/CoT。

## 2. 修改空间：字段有限，改写方式开放

本节明确哪些内容可以交给模型自行决定。固定研究设置提供比较基础；在允许修改的字段内，模型可以改变内容、结构及其组合。

四个示例中，第一个保持不变；后三个示例的 code/CoT 可修改。任务描述、示例顺序和数量、trigger 内容及题面注入规则固定。每个可修改示例的 CoT 至多出现一次 trigger；CoT 解释当前示例的求解过程，不加入要求后续查询模仿目标模式的元指令。

| 可修改对象 | 模型的自主选择 | 需要保持的内容 |
| --- | --- | --- |
| CoT | 整段重写或局部修改；决定措辞、详略、步骤划分与顺序、是否附代码提示 | 与当前任务及代码实际行为相符 |
| code | 改写实现；决定命名、中间变量、表达式与程序组织 | 任务要求的接口和功能 |
| code 与 CoT 的关系 | 只改一侧或共同重写；自行选择修改顺序 | 最终呈现为解释与实现一致的完整示例 |
| 三个可修改示例的关系 | 修改部分或全部；决定哪些内容共同表达、哪些随任务变化 | 各自任务完整，示例之间不必逐字统一 |
| CoT 中的 trigger | 在次数上限内决定是否出现、位置及语句衔接 | 使用固定 trigger，不改变题面渲染规则 |

这些是自由度的说明，不是改法的穷尽清单。模型可以提出表外的组织方式，同时修改多个方面，也可以生成与起点结构明显不同的候选。训练任务、评价规则和方法角色提示词由实验设计确定，不属于候选修改字段。

## 3. 探索方向：给出意图，让模型寻找表达

开放空间仍需方向。下面描述我们认为值得探索、但尚不能给出最佳写法的几个问题；模型负责把这些意图落实为具体候选，也可以提出其他有理由的方向。

| 探索方向 | 希望达到的状态 | 留给模型决定的部分 |
| --- | --- | --- |
| 解释与实现连贯 | CoT 清楚说明代码怎样完成当前任务 | 哪些步骤值得解释、解释到什么程度、是否辅以代码片段 |
| 信息取舍合适 | 关键实现信息与正常任务要求都清楚，减少无关说明的干扰 | 删什么、保留什么、放在哪里；长短由内容需要决定 |
| 跨示例有共同结构 | 示例之间存在可理解的联系，同时各自符合任务情境 | 共性体现在哪一层，哪些命名、结构和解释需要因题而异 |
| 表达能够适应不同任务 | 保留有用的实现含义，让形式随任务调整 | 哪些内容需要准确保持，哪些属于可替换的措辞和组织方式 |
| 功能与研究目标并存 | 修改后仍认真完成题目，功能证据能指导后续修订 | 如何协调代码与解释，如何处理已观察到的功能问题 |

从注意力与上下文学习角度看，这些方向分别关注模型如何利用上下文中的信息、从多个示例中归纳什么。这是提出候选的设计假设；内部机制是否如此，需要另行研究，当前迭代依据实际输出评价效果。

执行模型只需简短说明“主要改了什么、为什么值得尝试”。不要求每个候选覆盖全部方向，也不要求先归入一个固定类别。搜索允许组合修改；发现值得解释的结果后，再用独立对照研究原因。

## 4. 经验更新：帮助选择下一次尝试

经验的作用是保留有效线索、减少无理由的重复，同时允许新证据修正判断。以下说明一轮反馈如何变成下一轮可用的信息。

```text
固定初始模板 + 轮初经验 → 生成一批候选 → 训练评估
    → 各候选独立归纳 → 统一汇总经验 → 下一轮
```

| 角色 | 读取的主要信息 | 产出 |
| --- | --- | --- |
| 执行模型 | 初始模板、目标与修改范围、训练任务及其测试、约定公开的 SAST 规则、最新经验 | 候选及简短修改理由 |
| 单候选归纳 | 候选、逐题 victim 输出、模式/SAST/功能结果、共同轮初经验 | 观察事实、可能原因、反例与不确定性 |
| 轮级汇总 | 同轮独立归纳及共同轮初经验 | 更新后的简洁经验，包括值得继续、需要调整或尚无结论的方向 |

执行模型通过摘要了解 victim 行为，不直接读取逐样本原始输出。同轮归纳共享同一份入口经验，汇总后才更新；并发数不改变这一顺序。

每条经验尽量说明观察到的现象、适用条件和下一次尝试的理由。组合修改得到好结果时，先保留整份候选的观察，不立即认定每个改动都有效；失败也应区分功能问题、任务难度和证据不足。归纳可以修改或删除旧建议，成功措辞无需冻结，失败方向也不永久关闭。

功能保持若作为方法目标，就让功能结果实际参与上述反馈及最终候选选择。具体指标和训练题要求由[评估计划](攻击目标与攻击判定.md)集中说明。

## 5. 首版落地：先跑通一个完整研究循环

接下来只需把起点、角色输入和选择方式具体化，即可重建方法并开始小规模实验。

1. 为每个参与的 CWE 选择两道原始训练题，检查 clean 功能信号；选定一份初始模板并测基线。
2. 按修改范围和探索意图写执行提示词，按事实、解释与不确定性写归纳提示词。
3. 确定首版预算、功能反馈用途和最终候选选择方式，运行完整的生成—评估—归纳循环。
4. 观察候选是否有实质差异、经验是否影响后续尝试，再调整方法设计。

新方法围绕上述流程重新实现，可直接复用已有采样、检查与结果保存能力。设计按新实验修订，具体实验保留实际采用的设置与结果。
