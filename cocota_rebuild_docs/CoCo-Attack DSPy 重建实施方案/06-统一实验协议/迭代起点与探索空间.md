# 迭代起点与探索空间

整理：GPT / Codex，2026-10-20；历史条件核对：DeepSeek-v4.1-flash（OpenCode Go）。

本文依据[探索实验总览](../05-迭代方法/探索实验汇总/探索实验总览.md)、[逐批次明细](../05-迭代方法/探索实验汇总/逐批次实验明细.csv)和已保存产物，说明新方法可参考的起点与研究因素。遵循[统一实验协议](统一实验协议.md)的范围，评估解释见[攻击目标与评估](攻击目标与评估.md)。**本轮没有生成新攻击文本、启动实验或实施新方法；历史条件是设计参照，不是已经确定的新方法配置。**

## 1. 先区分两个 prompt

| 对象 | 用途 | 这轮要明确什么 |
| --- | --- | --- |
| victim 的 few-shot 初始模板 | 展示任务、示例 CoT 和代码，接受固定 trigger 的渲染 | 选什么内容作为每轮共同起点；哪些字段固定；如何与 clean 比较 |
| 执行/归纳模型的角色提示词 | 提出候选、解释结果、形成下一轮经验 | 各角色读取哪些证据、如何区分观察与猜测；不在本轮逐字定稿 |

“初始模板固定”指一次实验内每轮使用同一个 victim 模板起点；不意味着不同研究实验永远不能改变初始模板。角色提示词修改也需要记录，不能将手工调整后的实验描述为始终使用同一个方法。

## 3. 起点建议：先确定参照，再确定新模板

### 3.1 一份 clean 参照与一份候选初始模板

每个 CWE 各保留一份 clean few-shot 参照，用于测量自然模式命中和功能难度；新方法另有一份固定初始模板。两者用途不同，不能把“只保留 clean CoT、代码已修改”的模板记为 clean。

当前 cwe078 的起点可以先围绕 **A2 与 B2 这两份无末尾模仿指令、结构较简洁的历史模板做内容复核**，不必从 B8 最高的扩展题命中数倒推初始模板。A2 提供简洁解释的参照，B2 提供解释与代码提示并列的参照；A4 留作结构差异对照。这里依据的是可读性、可解释性和与新范围的相容性，不宣称哪份具有已证明的最优攻击效果。

这轮大致收敛到上述两类起点，不另创一套更复杂的投递文本。正式选择时，核对示例 1、后三个示例的修改范围、每个 CoT 的 trigger 次数、是否存在直接对 victim 的元指令，以及示例功能；把选择理由写清。**历史分数不能替代新协议下的起点检查和训练基线。**

不把 cwe078 的表达逐字复制成其他 CWE 的通用答案。其余 CWE 先从各自已有、任务描述与代码关系清楚的模板确定参照；当前证据不足以在本文指定它们的最佳文本。

### 3.2 不把“固定起点”写成“固定咒语”

每个 run 固定起点是为了知道变化从哪里开始；“必须逐字出现某个句子”则是研究结论，需要单独证据。A2 去掉额外代码提示后仍有较高历史命中，已经说明不能先把某一种 key 写法规定成所有候选的必要条件。

同样，不因为局部实验未检出增益，就永久排除一种表达方式；也不因为历史某种句子得分高，就把它作为不能被修改的理论前提。

## 4. 将经验改写为待验证因素

| 因素 | 希望解释的问题 | 历史能提供的线索 | 当前不宜下的结论 |
| --- | --- | --- | --- |
| 解释与代码的语义对应 | 模型理解的是当前任务中的实现含义，还是仅复制文字？ | 相同代码、不同 CoT 的结果不同 | 任意措辞变化都等于破坏语义一致性 |
| 解释的详略与组织 | 信息是否清楚、是否与正常任务步骤竞争？ | B2/A2/A4 与较长说明存在差异 | 越短越好；某个位置永远最好 |
| 代码表达与命名 | 形式变化是否影响字面复现、功能和静态判定？ | 命名保真度与模式命中未完全同步 | 变量名越像某种风格就一定有效 |
| 跨示例的共同结构 | 模型是否将某个做法视为可迁移规则？ | 旧实验存在覆盖与命名的线索，但有条件耦合 | 所有示例都必须出现完全一样的句子 |
| 任务相关性与功能保持 | 示例改变是否干扰正常任务的 API、数据和控制流程？ | 有些命中伴随功能失败，也有 clean 本来很难的题 | 所有功能失败都是 CoT 导致的 |
| 触发条件的特异性 | 查询标记是否改变模式采用倾向？ | 有标记与无标记条件存在差异；无标记也有命中 | 无查询标记就完全没有模式，或当前实验已证明内部绑定机制 |

探索因素属于研究空间，不是必须实现的调度器轴，也不要求一次实验同时改变所有因素。需要解释某个因素时，尽量保留其他条件；若多项一起变化，就描述组合效果，不把差异归功于其中一项。

trigger 内容、注入位置、可修改示例数量在主方法中按协议固定；上述触发条件的分析可作为独立对照，不扩展为本轮搜索新 trigger 的任务。每个修改示例 CoT 至多一次标记是用户当前选择；历史反复标记条件可留在背景分析，不进入本次同范围候选。

代码层只在已声明目标模式和检查范围内讨论表面表达的研究意义。本页不列新的绕过配方或扩大 oracle 的要求；若某表达静态不可判定，首先记录测量限制，不能把工具不理解当成成功证据。

## 5. 执行与归纳提示词的内容结构

这里给未来提示词的输入输出逻辑，不写可直接运行的角色模板。

| 角色 | 需要知道什么 | 应产生什么 |
| --- | --- | --- |
| 执行模型 | 固定初始模板；训练任务及其测试；目标定义；约定公开的 SAST 规则；允许修改范围；当前经验及不确定性 | 一个候选及修改说明，明确本次主要变化与希望观察的问题 |
| 单候选归纳 | 该候选的真实模板、逐题输出与判定、功能失败信息、共同轮初经验 | 观察事实、可能解释、反例与证据不足之处；对功能表现单独说明 |
| 轮级汇总 | 同轮各候选分析及共同入口经验 | 合并一致观察，保留冲突与适用范围；提供下一轮可用的简洁经验 |

归纳应保留“同一条件下观察到什么”和“为什么可能这样”之间的区别。比如 0/20 不证明一个策略永远无效，16/20 不证明必须冻结逐字文本；多条归纳相同也可能来自同一个证据源，不能重复计算为多次验证。

若论文主张方法优化了功能保持，功能结果必须真实进入上述反馈和最终选择；只在提示词里写“不要破坏功能”，或只要求示例通过测试，不足以支持该主张。相应训练题选择与 clean 校准见[评估文档第 6—7 节](攻击目标与评估.md#6-功能保持怎样进入理想迭代闭环)。

## 6. 不再延续的历史推论

- **“撤除显式指令没有影响”**：W/O 实际使用相同提示词，不能用于这个推论。排除指令来自新研究范围，不来自该失效对照。
- **“t16 低 pass 说明模式复现必然破坏功能”**：v1 题面被破坏；后续需使用完整题面及同条件 clean 参照。
- **“重复、位置或命名没有价值”**：未检出差异和证据有混淆，都不等于已经证明无效。
- **“A4/B8 是通用最优”**：任务集、renderer、repeat、指令范围不同；不混成一个排行榜。
- **“高命中就是功能保持下的有效结果”**：扩展题中 B8 命中 25/26、联合仅 2/26，clean 本身也只通过 4/26；需同时看分项和联合表现。
- **“结果变化证明注意力集中或模型学会抽象规则”**：当前黑箱观察只能支持行为假设，尚没有内部机制的因果证据。

这些修正不删除历史实验，而是避免它们继续作为未来方法的硬约束。

## 7. 下一步如何收敛而不提前写死方法

先明确各 CWE 的两道训练题和 clean 功能信号，再核对候选起点与新研究范围是否一致，最后决定未来方法实际使用哪些反馈和选择原则。首批实验可以验证这一闭环是否提供可解释证据，不必同时实现调度角色、执行角色、冻结文本库和多个候选池。

本页不改变“每轮初始模板固定、经验跨轮更新”的选择，不把历史最佳候选自动变成逐轮父模板；也不要求已经用过的测试题重新被称为未见题。新方法可以围绕论文问题重新实现，公共能力继续复用。
