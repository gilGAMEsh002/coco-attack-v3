# 经验组织与更新

研究选择：用户；设计整理：GPT / Codex，2026-10-28。状态：待实现，配合[方法设计](方法设计.md)。

## 1. 两个相互独立的维度

经验按针对对象分为 cot、code、both。cot 面向解释内容与组织，code 面向实现结构，both 面向两侧对应与协同；both 不是自动允许修改两侧，实际可改字段仍由方向安排决定。

另按来源与使用阶段分两级：一级为人工审核的稳定经验；二级为迭代根据实际证据提出的经验。每条都保留对象、陈述、适用条件、依据、反例与不确定性。人工审核表示可以作为稳定指导使用，不等于统计验证、普适因果或已经证明安全/有效。初始直觉与实际观察分别标注，不能混写。

## 2. 读入范围（用户已确认）

| 调用 | 可读取经验 |
| --- | --- |
| 粗模板生成 | 合并后的全部一级稳定经验；不读取二级经验 |
| cot 精修 | cot 与 both 的一级，以及与当前问题有关的 cot/both 二级 |
| code 精修 | code 与 both 的一级，以及与当前问题有关的 code/both 二级 |
| both 精修 | both 的一级，以及与当前问题有关的 both 二级；是否额外读取 cot/code 经验待定 |

“指定方向及 both”按最保守范围解释：both 方向当前只明确读取 both；是否同时读取 cot/code 尚待确认。

合并一级是形成一致的可读指导，保留对象与适用范围，不将互相冲突的条目压成无条件命令。相关性筛选的具体责任与规则待定，不能借摘要或结构去重记录绕过粗生成的读入限制。

二级的完整证据记录与实际传给精修模型的指导视图区分保存。完整记录可含逐题统计与内部原始证据引用；指导视图只提供经验陈述、适用条件、摘要与聚合计数、不确定性及逻辑证据编号，不提供训练题/测试原文、参考实现、逐样本 victim 代码或响应、原始输出或可读取这些输出的文件路径。合法的逐题聚合计数可以进入指导视图；含 victim 反馈时须标明为训练反馈。相关性筛选待定不影响这项已明确的输入边界。

## 3. 从独立归纳到统一汇总

同轮精修读取冻结的轮初二级版本，不逐候选滚动更新。单候选或粗精配对的证据先独立归纳，在轮末统一汇总，结束本轮；本轮提案汇总后的二级版本供下一轮读取。精修带来的效果增加、退化、无明显差异与未知均进入二级经验。二级条目保留粗精模板身份、方向、实际改动、样本量、逐题 H/D/F 与联合指标、评估缺口及原始证据引用。缺少可比粗模板测量时明确“无基线”，不能称作提升或下降。

统一汇总可合并重复观察、细化适用条件、记录冲突与撤回建议，但不删除失败或反例，也不自动晋级或改写人工审核的一级。与一级冲突的二级观察须保留并供人工审核，具体采用与冲突处理规则待定。一次 code 或 cot 精修同时改变多处时，只能先归于整份改动，不能将差异分摊为各个因素的独立因果作用。

## 4. 人工审核与待定事项

二级经验供后续定向精修与人工审核参考。人工可据证据修订一级内容，但一级起始条目的创建来源、审核准则、晋级时点与降级方式尚未确定；不默认继承旧方法六条经验，也不默认从空集开始。建议 run 内固定一级版本，跨 run 人工审核后更新；这是待确认建议，不是已批准的运行规则。

若运行中允许变更一级，需保留版本、生效轮次和前后内容，避免把后见经验写成粗生成当时已知的信息。无论采用何种方案，都保留实际作者、审核来源、引用与未知状态；本次文档整理没有生成新的实验观察或完成任何经验晋级。
