# 子任务目标追溯与范围核查

核查日期：2026-09-15。范围为当前已有的阶段 01 五份、阶段 02 八份 plan，以及阶段 03/04 已列出的工作包目标。本表核查需求与目标来源，不宣称代码或执行证据已经通过复核。

## 1. 依据与使用规则

追溯方向：**任务书条款或用户决定 → 主方案公共契约 → 阶段验收标准 → 子任务目标/检查场景**。子计划只能细化有来源的目标；不能互相引用后便将实施者提出的方案升级成用户需求。

- 原始需求：[v3 任务书](../dspy重建任务书.md)，F/E/X 编号均指其中条款。
- 当前公共规则：[主方案](./CoCo-Attack%20DSPy%20重建实施方案.md#shared-contracts)；本次变更见[运行控制与开发兼容范围](./CoCo-Attack%20DSPy%20重建实施方案.md#runtime-scope)。
- 最新用户决定：[阶段 02 D04](./02-生成与评估闭环/验收记录.md#d04)。历史差异仍按各阶段原 D 记录执行。
- 实现方式：文件名、类名、JSON 字段布局、锁/队列算法、集中测试分组可按现有代码作最小调整；须满足相应公共契约，不因某个拟定实现不同就另增产品能力、配置或验收门。

## 5. 后续阶段与变更边界

- 阶段 03 的 clean 基线来自任务书阶段 3、F2/F6/F8 → 主方案 H → 阶段 03 AC；运行准备按 D04 只核对单次输出配置与消耗记录，不再补累计预算配置。
- 阶段 04 的可插拔服务、动作持久化/恢复、四类成本审计、锁定来自 X1/X3/F8/E1 → 主方案 I/F → 阶段 04 AC；“预算查询”明确为查询消耗记录，不要求共享额度分配。具体研究方法仍另行设计。
- “字段布局兼容”“模型/温度/任务口径兼容”分别指当前模块互通与统计可比较；均不构成支持旧迭代版本执行的要求。
- 原有功能缓存指纹校验、同版本中断恢复、阶段隔离、固定分母、真实输出与费用审计仍是验收目标。范围收窄不能解释为这些能力也可以省略。
