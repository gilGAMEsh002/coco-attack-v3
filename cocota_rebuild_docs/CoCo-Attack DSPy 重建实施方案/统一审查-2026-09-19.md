## 2. 发现与处理建议

### R01 / P1：基线查询尚不能兑现版本严格匹配

范围澄清：修复个别问题形成混合版本已由 D06 接受，不作为本项缺陷，也不要求为统一版本重跑基线。本项针对后续候选与基线比较时，现有接口不能识别或报告相关评测版本差异；版本不同本身不等于结果必然不可比，具体可比性应依据变更影响和已有裁定说明，不能由漏检默认得出。

位置：`coco_attack/src/coco_attack/experiments/index.py:1114`、`coco_attack/src/coco_attack/evaluation/metrics.py:325`；依据为主方案 H、阶段 03 plan03 §5.1 与 D06。

`query_index` 只接受组合、形态、split、模型、温度、repeats 和 task_set 条件，不能约束提示/评估版本、harness、镜像、classifier 或 k。现有 `check_baseline_compatibility` 也不比较 harness、镜像、classifier；它读取 `prompt_form`，而索引使用 `form`。索引只登记 `oracle_id`，未提供计划要求的 oracle 内容指纹。

只读复现：取真实索引 `cwe078-0__clean_0shot__t0r1::search::search`，分别复制并改变 `harness_version`、`image_digest`、`classifier_version`、`form`，现有兼容检查四次均返回 `(True, [])`。这不说明阶段 04 已经错误比较，但说明不能把当前查询/比较函数直接当作完整的对齐门。

建议：明确检索与可比性判定的接口，统一字段名，补齐按指标所需的版本/输入指纹检查；版本缺失应明确无法确认对齐，不能因两侧均缺值而默认兼容。保留混合版本事实，依据条目实际来源匹配。验收至少覆盖 harness/镜像/形态错配及必要指纹缺失。

### R02 / P1：成本汇总没有覆盖修订历史，不能标为跨修订累计

术语澄清：local_test 指本机 Docker 功能测试的执行次数、耗时等资源消耗记录；目前没有货币折算，漏记执行次数不表示额外产生同等数量的收费请求，也不要求新增本地费用计价。下述 CNY 数字仅对应 judge 模型调用的已有配置计价。

位置：`evaluation/reporting.py:156` 的 `collect_costs`、`experiments/summary.py:303`；修订过程见 `cocota_runs/phase03/r2/reeval_cleaner.py`、`reeval_functional.py`，验收声明见阶段 03 `阶段验收.md:62`、`:102`。

`collect_costs` 只读当前 run 的 `ledger.jsonl` 与 `generation/ledger.jsonl`。cleaner 重评脚本把两个单元的旧 ledger 备份后替换；单独功能重评则把账本留在 r2/r3/r4，汇总没有登记或合并这些来源。

定点读取修订目录的顶层 `*.ledger.jsonl`：r2 有 616 条、r3 有 225 条、r4 有 225 条 local_test `execution_recorded`，共 1,066 条，均有 accounting_id 且无 `reused_from`。当前报告仍仅有 1,962 条 local_test，未纳入这些修订账本。此处不把该小计当成全部项目执行总数，也不假定目录副本可直接相加。

进一步核对当前 24 份 run 账本、上述独立功能账本与两个单元的 r1 备份账本，得到以下去重累计下限：

| 角色 | 当前报告 | 已证实的去重累计下限 | 漏记 |
| --- | --- | --- | --- |
| local_test | 1,962 次 | 3,418 次 | 1,456 次 |
| judge | 1,962 次 / 1.0508501 CNY | 2,352 次 / 1.38805686 CNY | 390 次 / 0.33720676 CNY |

local_test 有 3,418 个不同 accounting_id 和不同且非空的 container_id，无 `reused_from`。judge 的新旧 accounting_id 无交集，全部 `model_cache_hit=false`、无 `reused_from`；两个旧单元账本分别另有 165 次 / 0.13468236 CNY、225 次 / 0.2025244 CNY。r2 cleaner fresh 账本与当前替换后的账本哈希相同，本次仅计一份。victim 原账本未被替换，本次范围内未发现新增 victim 请求。

建议：显式登记原运行及每次修订的审计来源，按真实调用/执行身份去重，区分“当前结果对应成本”和“累计实验消耗”。保留首次付费响应及修订执行事实，缓存响应不得再次收费；无法还原的窗口记未知。修正报告和验收中的累计声明。该修复可以从现有账本开展，不需要重新调用模型。

### R03 / P2：报告与验收版本表未反映最终混合版本

位置：`experiments/summary.py:335`、`:503`；阶段 03 `阶段验收.md:48`、`:49`、`:99`。

汇总的 `_versions` 原样返回 prepare 时的全局 fingerprint，Markdown 因而只展示 cleaner-v3、harness-v2、旧镜像，未标示其为初始配置，也未列出最终条目版本分布。实际 24 个 whole-set 条目为：

| 字段 | 当前索引分布 |
| --- | --- |
| cleaner | v3：22 个；v4：2 个 |
| harness / 对应镜像 | v2：16 个；v3：7 个；v5：1 个 |
| classifier | v2：1 个（cwe502 0shot t0.7r5）；其余 23 个条目缺失 |

建议：报告分别展示初始冻结来源与最终各条目的评测来源，显式标明混合版本及缺失指纹；按 E13 与最终 manifest 修订验收版本表，保留历史记录原值。不要把 D06 的“接受混合版本”解释为允许错误展示版本。
