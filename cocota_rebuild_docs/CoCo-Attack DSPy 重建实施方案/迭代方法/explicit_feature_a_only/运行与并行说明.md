# explicit_feature_a_only · 运行与并行说明

作者：GPT · 2026-10-13

同轮的候选先完成提案与示例门检查，再并行训练。门检查仍按候选依次进行，每个候选最多使用原有的 3 个检查线程；训练只执行现有 victim 采样与评估。候选分别保存产物，全部训练完成后才开始归纳。

设置 `candidate_training_workers=3`、`candidate_induction_workers=3` 可同时训练和归纳三个候选。这两个字段缺省均为 1，已有配置沿用串行方式。它们与单候选内的 `victim_max_concurrency` 是不同层级：三个候选每个各采样 20 次时，总在途 victim 请求最多 60 个，具体还受各自的自适应窗口限制。

并行归纳改变经验更新方式：所有候选读取相同的轮初经验，分别产生报告；全部报告完成后，乙额外调用一次，将候选报告与轮初经验整合为一份完整摘要。下一轮读取汇总经验，单候选摘要不会互相覆盖。汇总调用只读取候选的归纳条目、摘要、指标与证据标签，不重新评价样本或重算命中率。提案阶段仍依次生成，以保留同轮 priors 和 CoT focus 行为。

整轮在训练前失败时，候选仍可并行归纳拒绝事实，再统一汇总；未训练状态、空样本和空训练指标保留。训练或归纳有未完成项时暂停，其他已完成候选的产物保留。恢复复用已有响应与报告；乙协议错误通过原有 retry 入口显式重试。

每轮额外保存 `rounds/<轮次>/A/round_experience.json`，A commit 引用其汇总版本和单候选版本。若汇总调用失败，可用 `explicit-feature-a-only-retry --run-root <run> --round <轮次> --stage A --candidate-id round-summary` 重试。

并行归纳采用共同父经验，与串行归纳的链式输入不同。新试验使用新 run；已有 run 按保存的配置与模板恢复，不覆盖其原有调用输入。

配置示例在 `coco_attack/configs/explicit_feature_a_only/`：

- `parallel.mock.example.json`：离线并行流程。
- `parallel.cot.2rounds.example.json`：保留当前两轮 CoT focus 方案，启用候选并行。

启动前可执行 `explicit-feature-a-only-preflight --config <配置> --project-root <项目根目录>`；正式启动使用 `explicit-feature-a-only-run --config <配置> --project-root <项目根目录>`。mock 启动另加 `--doubles-module coco_methods.explicit_feature_a_only.mock_services`。配置中 run_id 和 run_root 用于新试验；当前材料未启动真实实验。
