## 1. 新运行准备

1. 从本方法配置样例复制到新的方法产物目录，显式填写 A 初始模板、固定比较模板、数据、规则目录、执行配置及模型/协议。`mock.example.json` 与 `real.draft.json` 是模板，不是已验证的当前 run 配置。
2. 运行只读预检。真实环境检查另用 `check-execution` 及 Semgrep 检查，结果保存在本方法产物目录。`offline_preflight_passed` 不代表模型或 Docker 已连通。
3. 在实际运行授权范围内先到固定基线检查点，再到首轮检查点。新 run 不自动复用其他 run 基线；若研究协议明确允许复用，必须记录身份、来源及比较条件。

```bash
coco_attack/.venv/bin/python -m coco_attack implicit-then-literal-preflight --config <config.json> --report <preflight.json>
coco_attack/.venv/bin/python -m coco_attack check-execution --config <execution.json> --audit-dir <audit目录> --output-dir <全新环境报告目录>
coco_attack/.venv/bin/python -m coco_attack implicit-then-literal-run --config <config.json> --stop-after baseline_complete --report <report.json>
```

`check-execution` 生成的 `execution_profile.json` 是报告包装；实际执行配置使用其中的 `profile` 对象（另存文件），不把包装本身直接当执行配置。

训练集基线为两题各 10 次，共 20 个槽位；25 道测试题另属测试评估，不在探索反馈链中。

A-only 试验使用 `mode="a_only"`、`b_slots_per_seed=0`，轮数与每轮 A 名额由配置指定。每轮完成训练和归纳后直接进入下一轮；从基线检查点恢复时不指定 `--stop-after`，可连续运行配置中的全部轮次。 如仅需调整甲/乙请求超时，使用新 run 固定新配置；可显式设置 `baseline_training_path` 引用已完成且 victim 配置一致的基线，通过预检后不重复采样。

## 2. 恢复与停止点

提示词编辑采用[轻量流程](提示词模板.md)：新 run 读取当前模板，resume 使用已保存副本；无模板身份的历史 run 只读保留，不为修改标点维护兼容名单。（作者：gpt，2026-10-10）

```bash
# 只读查看，不推进运行
coco_attack/.venv/bin/python -m coco_attack implicit-then-literal-status --run-root <run>

# 从基线检查点继续到首轮结束；仅对尚未完成首轮的 run 使用
coco_attack/.venv/bin/python -m coco_attack implicit-then-literal-resume --run-root <run> --stop-after round_1_complete --report <report.json>
```

已达到 `round_1_complete` 的 run 再次 resume 会继续后续轮次，不能把相同 `--stop-after` 当成永远有效的安全锁。只在用户指定的范围内执行；已授权范围内无需逐步重复请求确认。恢复使用原配置及身份，不改模型/协议/采样数来消除冲突。

首轮结束须核对 `phase=stopped`、`stop_reason=checkpoint:round_1_complete`、`round_index=2`、本轮最后一个阶段的 commit 已写（A/B 模式为 B，A-only 为 A），且 `rounds/2/A/plan.json` 不存在。受控停止通常退出 3；暂停退出 4，失败/阻塞退出 1，用法错误退出 2，全部完成退出 0；最终解释须结合状态和日志。

## 3. 异常与重试

- 普通恢复复用已持久化响应、样本和经验，不等于自动重新生成协议失败的内容。终态生成错误可能仍计入采样分母，必须同时报告生成成功数。
- 乙内容重试只用于当前实际暂停的归纳 `protocol_error`，精确指定 round/stage/candidate。它可能继续驱动状态机，执行前检查当前 CLI 的停止控制；不能假设只重做一个请求。
- `unknown`/orphan 按现有协议暂停，先核对原动作和账本；不能删除事实或修改配置强行恢复。
- 模型/工具不可用、不完整证据或容量不足如实停止，禁止用 mock 填充真实 run。费用未知保持未知。
- 单写者由 `RunLock` 保护；监控用只读入口，避免短前台超时杀掉正在等待模型的写者。

## 6. 同一个 run 调整 victim 并发

作者：gpt（2026-10-12）。并发是执行调度参数，可在同一个 run 调整，不需要新建 run 或重新生成提案。原 `config.json` 保留为启动记录；当前设置与变更时间收在 `run/runtime_settings.json`。提示词、模型、温度、任务、采样次数和评估协议仍沿用原实验配置。

在仓库根目录执行，例如将现有 run 的自适应范围改为 16–32：

```bash
TASK_RUN="cocota_runs/phase04/methods/implicit_then_literal/runs/itl-bonly-adaptive4to16-1round-5seeds-5variants-v40731-20261011T180645/run"
coco_attack/.venv/bin/python -m coco_attack implicit-then-literal-concurrency \
  --run-root "$TASK_RUN" --mode adaptive --min 16 --max 32
```

这条命令只保存设置，不启动或重跑实验。已加载新版运行器在下一个候选开始时读取；暂停后 resume 也读取。当前批次的在途请求继续完成，已完成样本复用。恢复未完成候选时，原 loop/generation 配置和样本身份保留，剩余请求使用本批次的 `generation/concurrency_override.json`，不因并发变化拒绝恢复。修改部署前已启动的旧运行器需先在完整候选边界停止，再使用同一 run 的 resume 加载新版代码。

`--mode fixed` 时 `--min 1`，`--max` 是固定并发数；adaptive 从 `--min` 开始，非缓存响应加一、可重试传输故障减半，上限 `--max`。并发上限没有 16 的硬限制，但每候选只有 20 个样本，实际在途不会超过本批剩余样本数。示例功能检查仍最多三个容器。

用 `implicit-then-literal-status --run-root "$TASK_RUN"` 查看设置；每个训练目录的 `generation/concurrency_state.json` / `generation_summary.json` 保存该批次实际采用的并发，`concurrency_events.jsonl` 保存自适应变化。设置值和当前在途数是不同信息。

如果因其他原因选择新 run 接续，源 run 可以是上一份接续 run；完整训练前缀直接复用，保留最原始样本与提案来源，不需要退回最初 run。日常调并发使用上面的同 run 命令即可。
