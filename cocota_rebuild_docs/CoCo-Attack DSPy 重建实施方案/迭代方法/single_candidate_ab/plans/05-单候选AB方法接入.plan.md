依据：[方法设计](../迭代方法设计.md) §5–§8、[方法实施安排](实施安排.plan.md)、D02/D03。基础设施任务 01–04 提供模板、检查、训练评估、角色调用与动作恢复，本项将它们组合成当前方法。具体开工状态以[按任务阅读指引](../../../../../AGENTS.md)为准。

## 0. 先完成三处小型接线修复

[E17](../../../04-迭代平台公共能力/records/01-公共能力实施.md#e17) 的 Lunar 专项复核确认任务 04 主要恢复接口可复用，下列内容作为本项第一步修复，然后直接继续方法接入，不另起一份收尾计划。

1. `HistoryUnit.one_line()` 不再将内部 action_id 写进压缩消息。审计身份保留在 HistoryStore/压缩记录中；模型可见侧用普通角色/序号标签和方法白名单事实。增加强制压缩的检查：实际 messages 无内部动作标识，未压缩程序内容不改写。
2. 补 `commit.json` 已落盘、`ACTION_COMMITTED` 事件尚未写入的恢复窗口。已有 commit 分支须补齐缺失事件且重复恢复不重复追加，不能重做补丁、历史或 provider 调用。增加该边界的故障注入测试，保留原 E16 演示证据。
3. 演示及新方法入口的 `output_reserve_tokens` 至少为实际 `max_tokens`；统一默认配置或执行前拒绝不足值，保留启发式计量标记。现有 demo 默认 2048/8192 不应直接用于后续方法。检查无需真实模型。

本项可按需修改上述公共模块，但不重做任务 04。若测试通过，即继续以下方法接线；这三项不改变 A/B 研究规则。

## 1. 目标与范围

在独立方法模块中落地“初始功能检查 → A 改 code 并过三项门 → 训练反馈 → 一次 B 改 cot → 下一大迭代”，始终只有一个当前候选、一条共享历史。先以可注入的确定性 mock 验证一轮，再验证五个大迭代及中断恢复。

本次交付可调用方法入口、显式配置、CLI/示例及方法轨迹。公共服务不新增 A/B 阶段枚举，不内置门或 B 计数。真实模型调用、25 题测试、锁定/选优和自动续批不在本项验证范围。采用小型显式状态文件即可，不构建通用工作流引擎。

## 3. 最小方法状态

保存协议/配置身份、当前模板引用、大迭代序号、当前操作、A 尝试序号、累计待检示例、逐例证据引用、B 当前动作身份与是否已消费、未完成评估动作、共享历史位置和暂停原因。字段名由实现决定。

每个 mutator 请求、示例检查和训练评估在执行前登记逻辑动作与输入内容身份。方法状态不取代公共动作日志；状态只引用已提交结果。恢复从已保存动作继续，不能因为重新进入函数就分配新的 B 身份或重新生成请求消息。指针更新与历史追加需要可重放且只执行一次。

单候选表示合法补丁直接更新当前工作模板，门失败后仍在该工作模板上继续。历史版本仅审计，不引入选父、分数回滚或候选池。非法补丁不应用，不能部分更新。

## 4. 初始检查与 A 的推进

初始 c0 先对示例 2–4 做功能检查（语法/入口有效且 strict pass），不要求尚未变异的初始代码静态命中，也不自动增加 c0 的训练评估。失败/基础设施不可用记录并暂停，沿用方法设计的 strict 语义。

每次 A 的合法补丁应用后，将实际改过的 code 示例加入本大迭代的待检集合；后续只改另一个示例不能遗忘此前失败的示例。检查针对当前代码字节，旧代码的通过结果不能替新代码背书。未变依赖的已完成动作证据可供恢复使用，不扩成跨动作评估缓存。

每个待检示例必须同时满足：语法与入口有效、功能 strict pass、静态 verdict=target_present、Semgrep available=true 且 completed=true 且 detected=false。字段缺失、unknown/error/incomplete/unavailable 均不能通过；不以 `not detected` 把 null 当 false。

A 未过门：保存逐例失败事实，追加共享历史，留在 A；不得执行训练或 B，也不得回退到旧代码绕过门。空补丁不能清空待检集合、消除失败或靠 `all([])` 推进；无有效改写证据时保持 A 并明确反馈。基础设施故障可暂停，不把它算成方法通过。

A 过门：保存门所检查的精确代码身份，再对当前候选执行一次两题训练闭环，回灌 ASR/evasion/失败与原始代码事实，然后才请求 B。训练指标只作反馈，不另加 evasion>0 或 pass@k 门。训练执行中断时恢复该评估，不重调 A 或越过未完成反馈。

## 5. 一次性 B 与批末

每个大迭代只分配一个 B 决策动作；B 可在一个补丁中改示例 2–4 的全部 cot，code 和示例 1 冻结。已保存响应的恢复只解析/提交，不重新请求第二份决策。

非法格式/范围的 B：模板保持进入 B 时内容，记录失败与机会已使用，结束本大迭代，不追加 cot 修复调用。有效实际修改应用后执行训练评估并反馈；合法但无实际变化明确记 no-op，不伪造新版本、训练观测或提升。B 评估失败只恢复评估/暂停，不重新取得 B 机会。

孤立请求尝试对应 task-04 的 unknown_paused 时保存原动作并暂停，不能换一个 action_id 绕过不确定窗口。允许传输层既有重试，但不能借重试重做已有持久化决策。

大迭代完成后进入下一轮 A；五轮指五个完整大迭代，不能把 A 的失败尝试数当轮数。批末保存当前模板、逐轮门/训练指标、状态、历史与消耗引用，停下供审阅，不自动续批/锁定/跑测试。暂停允许通过单步运行或明确操作停止，不引入总预算体系或固定 A 尝试次数的研究规则。

## 6. 共享历史与恢复接线

任务 04 的补丁提交历史不能替代之后才产生的检查/训练反馈。方法须将后续事实作为有稳定身份的历史事件或下一次请求的一部分持久化，使 A 失败、A 训练反馈、B 非法反馈和 B 训练反馈均能到达下一决策。不要向已经提交的不可变历史单元中悄悄追加字段；小型适配即可，无需重做历史服务。

输入投影遵守白名单；内部 action_id、hash 和路径保持旁路，压缩摘要也不能重新引入内部身份。程序自身代码/测试标识符不改写。每次实际 messages 与计量方式落盘，恢复沿用已保存版本。

恢复检查至少覆盖：A 响应后未提交、补丁已提交但方法指针未更新、门结果已保存但状态未推进、训练中断、B 响应持久化但 B 状态未更新、B 非法结果已保存、反馈追加后批次指针未推进。已有底层能力直接复用；方法只补跨服务状态衔接，不重复写 provider/扫描器/账本。

## 7. 验证与交付

先用脚本化 mutator 与可注入检查/评估结果验证控制流，报告明确标为 mock 门。无需制造真实过门代码来验证状态机，也不能以 mock 门声称方法有效。至少一次通过真实模板与消息装配、角色调用/补丁服务和任务 03 mock 训练入口完成接线；外部检查仍可用明确标注的替身。
