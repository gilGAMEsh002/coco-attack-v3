## 历史串行配置的启动命令（保留参考）

在 `/home/sshuser/projects/dspy` 下操作。根目录 `.env` 中应已有 `DMX_API_KEY`（由程序读取，不在终端打印）。准备命令本身不启动实验。

先检查实际执行环境（这一步会访问 Docker 并运行既有受信任环境检查，本次未执行）：

```bash
coco_attack/.venv/bin/python -m coco_attack check-execution \
  --config coco_attack/configs/execution.local.json \
  --audit-dir cocota_runs/phase03/baseline-DeepSeek-V3.2/inputs \
  --output-dir cocota_runs/phase04/method-ab-flash-v32-startup-20260923
```

输出目录必须是新目录，若已使用就换新目录。该检查通过后，现有配置可按以下入口启动（会执行真实检查和真实模型请求）：

```bash
coco_attack/.venv/bin/python -m coco_attack run-method-ab \
  --config cocota_runs/phase04/method-ab-flash-v32-preflight-20260923/method_config.json \
  --allow-real-checks --allow-real-training
```

方法状态和产物写入 `cocota_runs/phase04/method-ab-flash-v32-r1/`，其中 `run/state.json` 记录阶段/轮次；同目录 actions/history/method_events 为审计，training/ 为训练结果。相同配置再次调用可恢复已有动作；若状态为 paused，确认暂停原因后使用：

```bash
coco_attack/.venv/bin/python -m coco_attack run-method-ab \
  --config cocota_runs/phase04/method-ab-flash-v32-preflight-20260923/method_config.json \
  --allow-real-checks --allow-real-training --resume-paused
```

unknown 调用窗口不会自动重试；不要为跳过暂停直接增加 `--allow-unknown-retry`。配置修改使用新运行目录，不能修改已有 run 的并发/模型后继续冒充同版本恢复。
